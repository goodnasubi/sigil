# 0042: P2-4 WebAssembly 出力

- **状態**: 提案（typesafe-ai の正式判定は実施済み。末尾の「正式判定の記録」を参照。別系統のレビュー前）
- **日付**: 2026-11-17（JST）
- **対象**: [Issue #565](https://github.com/goodnasubi/sigil/issues/565)、レーン E

## 背景

[ADR 0038](0038-p2-scope.md) の四番目の段 P2-4 を、[ADR 0039](0039-p2-1-javascript-output.md)（JS 出力）・[ADR 0040](0040-p2-2-ui-model.md)（UI の記述モデル）・[ADR 0041](0041-p2-3-fullstack.md)（フルスタック）の上に具体化する。P2-4 は、P2-1 と同じ核を WebAssembly（以下 Wasm）でもブラウザ実行し、P2-2 の UI と P2-3 の通信に接続する。JS ホスト層は共有する。人間が仕様だけをレビューできるよう（[ADR 0001](0001-vision-and-scope.md)）、検査・契約・所有権の意味を出力先で変えない。基準は言語の仕様と共通 lowering、比較相手は [ADR 0017](0017-run-on-sir-evaluator.md) の SIR 評価器と、P2-1 の JS 出力とする。

起草の基準は `main` の `aeffcb0`。0042 は main のファイル・索引・オープン PR・リモートブランチで未使用であることを確認した。本 PR は本 ADR の新規作成と索引追加だけを変更する。以下の API・CLI・診断は実装に向けた決定であり、現行の処理系や `sigil spec` に追加された機能を記述するものではない。

## 選択肢と決定

| 判断 | 採用する案 | 他案を採用しない理由 |
|---|---|---|
| 出力器 | 検査・単相化・検証を通った共通 SIR から、Wasm のバイナリを直接生成する小さい出力器。外部のツールチェーンを使わない | LLVM／Emscripten／binaryen を経由すると、検査後の意味を外部ツールの最適化に委ね、信頼基盤と依存が増える。SIR 評価器自体を Wasm にコンパイルする案は「核をコンパイルする」（ADR 0038 決定 2）に当たらず、遅い |
| メモリと破棄 | 線形メモリに値を置き、SIR の `Drop`／`Move`／`cleanup` を明示的なコードにして自前の割り当て器で解放する | Wasm GC 提案（エンジンの GC が値を回収）は、破棄の時点を観測できる言語の意味（ADR 0039 決定 3）と合わない。JS の GC に所有値の解放を任せない（ADR 0038 決定 2） |
| ホスト境界 | 生成物ごとに閉じた import 一覧と整数ハンドル。DOM ノードや JS オブジェクトを Wasm へ渡さない | `externref` で DOM ノードを渡すと、ノードの寿命を JS の GC に委ねる。WASI や Emscripten の接着コードは、Sigil の効果に無い能力を持ち込む |
| 配信 | `.wasm` と `.mjs` の組。`.mjs` は `.wasm` の SHA-256 を持ち、読み込み時に検証する | base64 埋め込みの一ファイルは、サイズが約 1.33 倍になり、内容の検査（秘密の走査）が難しくなる。ハッシュ無しの別ファイルは、キャッシュで版の違う組が使われる危険がある |
| スタック | 各関数の入口で論理スタックと呼び出しの深さを検査し、枯渇を `StackExhausted` として cleanup へ入る | エンジンのスタック溢れに任せると、cleanup が走らず、停止の種類も失われる。SIR を明示的なフレームで解釈する案は Wasm の利点を失う |

正式判定の確率は意味の正しさの証明ではない。採用理由は、既存の検査保証を保ち、共通の適合例で実装の完了を判断できることにある。**本 ADR の正式判定は未実施**で、後の節に理由と扱いを書く。

## 決定 1: 範囲と対応集合

Wasm の初版の対応集合は、**P2-1・P2-2・P2-3 の JS 出力と同じ**とする。すなわち [ADR 0039 決定 1](0039-p2-1-javascript-output.md) の構文・型・標準操作の許可一覧、[ADR 0040 決定 1](0040-p2-2-ui-model.md) の UI の追加分、[ADR 0041 決定 5](0041-p2-3-fullstack.md) のクライアント側（`std.web.client`）の許可一覧を、そのまま含める。**Wasm にだけある機能は加えない**。どちらかの出力に機能を足すときは、もう一方に同時に足すか、足さない理由と期間を ADR に残す。P2 の完了時には、両出力の対応集合が一致していなければならない（ADR 0038 の P2 全体の完了条件 1）。

`targets browser` を含む利用者モジュールと、その入口から必要な `browser`／`bare` の共通コードを対象とする。通常の構文・名前解決・型・所有権・借用・効果完全一致・契約式の検査を先に行い、出力器のために規則を緩めない。Wasm の導入で、効果・所有権・借用の検査を弱めない。

初版の許可効果は JS 出力と同じで、`none`・`console`（P2-1）、`dom`（P2-2）、`net.client`・`task.suspend` 等のクライアント側の効果（P2-3 の許可一覧に従う）である。`fs.*`・`env`・`net.server`・DB 等のサーバー専用効果、ブラウザで許さない待受・ファイル・環境変数の操作は、ホスト経由でも開放しない。

## 決定 2: Wasm の機能水準と生成物の形

### 機能水準

3 つの主要エンジン（Chromium／Firefox／WebKit）の現行版で共通に有効な機能だけを使う。具体的には、Wasm 2.0 のコア（可変グローバル、符号拡張、多値、バルクメモリ操作、飽和変換）に限る。次は使わない。

- Wasm GC、例外処理、末尾呼び出し、SIMD、スレッド・共有メモリ（`SharedArrayBuffer` の要求、クロスオリジン隔離の要求を持ち込まない）、64 ビットメモリ、`externref`／`funcref` による外部オブジェクトの保持。

最低対応版は実装時の試験記録に明記する（ADR 0039 決定 4 と同じ）。選んだ機能は、エンジンの `WebAssembly.validate` で検証できなければならない。

### 生成物

`sigil build --emit wasm` は 2 つのファイルを一組で生成する。

- `<名前>.wasm`: 検査済みの Sigil コードを訳したモジュール。
- `<名前>.mjs`: 読み込み・値の変換・ホスト層をまとめた ES module。`<名前>.wasm` の SHA-256 を定数として持つ。

`.mjs` は同じディレクトリの `.wasm` を `new URL('./名前.wasm', import.meta.url)` で取得し、バイト列の SHA-256 が定数と一致しない場合は**コンパイルせずに** `failure.kind=host`（原因は不整合）で失敗する。これにより、キャッシュ等で版の違う組が使われることを防ぐ。Node.js・npm・Emscripten の接着コード・動的 import・`eval`／`Function` は要求しない。

Wasm のコンパイルは非同期になるため、生成物の入口は P2-1 の同期の `invoke` とは別に、`export async function load(host)` とする。`load` は `{ invoke(args), … }` を持つオブジェクトを返し、その後の `invoke` の引数・戻り値・失敗の形は ADR 0039 決定 4 と同じ値表現を用いる（Int=bigint、Float=number、Bool=boolean、Unit=null、String=string、Bytes=Uint8Array、List／組=array、構造体=`{fields:[...]}`、列挙型=`{tag,fields}`）。UI 用の `mount(rootElement, host)`（ADR 0040 決定 6）も、`load` の後に同じ形で呼べる。JS 出力と Wasm 出力で、境界の値と失敗の形は同一でなければならない。

インスタンスとメモリは `.mjs` の内部に閉じ込め、利用者のコードに公開しない。公開する export は上記の `load` と UI 用の入口だけとする。

## 決定 3: 値・文字列の ABI とメモリ

### 数値

- `Int` は Wasm の `i64`。境界でだけ BigInt に変換する（Wasm の `i64` と JS の BigInt の対応を使う）。Number を経由して丸めない。
- `Float` は `f64`。丸め・負のゼロ・正負の無限大を IEEE 754 binary64 のとおり維持する。NaN の符号・ペイロードは Wasm の仕様で保証されないため、ADR 0039 の比較規則（NaN は NaN 同士として一致）に従い、`Float.to_bits`／`from_bits` は初版に含めない。`to_int` は有限性と切り捨て後の i64 範囲を**明示的に検査**してから変換する。
- 算術は**エンジンの trap に頼らない**。桁あふれ、ゼロ除算、最小値と `-1` の除算／剰余、シフト数の範囲は、明示的な検査から Sigil の停止（`Overflow`／`DivisionByZero` 等）の経路へ入る。Wasm の `unreachable`・範囲外アクセス・整数除算の trap が実行中に起きたら、Sigil の停止に読み替えず、`failure.kind=internal` とする。

### 文字列・集成値

`String` は線形メモリ上の妥当な UTF-8 のバイト列（内部表現）とする。ADR 0039 の意味を保つ。

- `len` は Unicode スカラー値の数、比較はスカラー列の辞書順。UTF-8 のバイト列の辞書順はスカラー値の順序と一致するので、Wasm ではバイト比較でよい。JS 出力は UTF-16 の既定比較と区別して実装する必要があるため、**補助平面の文字と U+E000〜U+FFFF の比較**を共通の適合例に含める。
- 境界では、JS の string（孤立サロゲートなし）との変換を `TextEncoder` と `TextDecoder`（fatal）で行い、不正な値を置換せず拒否する。正規化はしない。
- `Bytes` は線形メモリ上の領域で、境界では複製する。共有 `ArrayBuffer` や、ホストへの可変な別名を渡さない。

`List`・組・利用者型は型記述子に基づく配置、列挙型は腕番号と中身、借用は領域と射影を持つ参照で表す。**内部の配置は公開 ABI にしない**。ホストは境界の値表現だけを見て、線形メモリのポインタを保持・解釈しない。

### メモリの上限

線形メモリは宣言で最大ページ数を持つ。既定の最大は 1 GiB（16384 ページ）、論理スタックの領域は 64 MiB とする。この数値は実装時に 3 エンジン（モバイルを含む）で実測し、**引き下げることはあっても、引き上げる場合は ADR を改訂する**。`memory.grow` が失敗したら、新しい停止の種別を作らず、既存のリソース枯渇の停止に対応づけて cleanup へ入る（種別名の対応は実装前の契約確認で確定する）。割り当て器は、解放漏れを検出できる計数を持つ（決定 7）。

## 決定 4: 所有値の破棄と異常停止

[ADR 0015](0015-m5-native-output.md) 決定 5 の SIR `Drop`／`Move`／`cleanup` を、ADR 0039 決定 3 と同じ順序で明示的な Wasm のコードとして実行する。内側のスコープから外側へ、生存する局所値を宣言の逆順に破棄し、値自身の後に欄・要素を宣言順にたどる。部分移動、`match`、消費するメソッド、`move` クロージャを含め、移動済みの値・欄は二重に破棄しない。破棄は利用者のコードを呼ばない。深い集成値の破棄には明示的な作業スタックを使う。

- 解放の時点は、自前の割り当て器への返却で決まる。JS の `FinalizationRegistry`／`WeakRef` や、エンジンの GC に、Sigil の破棄や外部資源の解放を委ねない。
- 正常復帰、`?`、契約・篩型・標準前提の違反、算術停止は、すべて SIR の解放経路を通る。停止の種類・関数・ソース位置・契約中の `during` を保持し、最初の停止をホスト側の例外で上書きしない。
- `--trace-drops` を付けた生成物は、`host.traceDrop(text)` を import し、既存の `drop: 型名` と同じ記録を同じ順で渡す（ADR 0039 決定 4 と同じ検証用の窓口。新しい Sigil の効果にしない）。

### スタックの枯渇

Wasm の呼び出しスタックの深さの上限はエンジンごとに違い、溢れると trap で cleanup が走らない。そのため、各関数の入口で「論理スタックの残り」と「呼び出しの深さ」の両方を検査し、上限に達する前に `StackExhausted` として cleanup へ入る。

- 呼び出しの深さの上限は、3 エンジンで**エンジン自身のスタック溢れが先に起きない値**を、実装時の実測で決める。実測の方法と値を試験記録に残す。
- 上限に達する再帰の深さは、SIR 評価器・JS 出力・ネイティブと一致を要求しない（ADR 0039 決定 3 と同じ）。ただし、**エンジンのスタック溢れ（RangeError や trap）が起きたら、成功や `StackExhausted` に読み替えず `internal` として区別する**。
- ブラウザのタブ強制終了やホストのメモリ枯渇では cleanup を保証しないが、通常の言語上の停止と成功に読み替えない。

## 決定 5: ホスト境界と JS ホスト層の共有

Wasm が呼べるのは、生成物ごとに決まる**閉じた import 一覧**だけとする。import は 1 つの名前空間（`sigil_host`）に置き、一覧は入口からの依存閉包で決める。使わない能力の import は生成しない。`env`・WASI・Emscripten の接着関数は要求しない。

- 一覧に含まれうるもの: `log`（`console` 用、文字列は線形メモリ上の領域として渡す）、`trace_drop`（`--trace-drops` 時のみ）、P2-2 の DOM アダプター操作（`createElement` 等）、P2-3 の通信の発行。いずれも**同期で、戻り値で Sigil の資源や借用を渡さない**。
- DOM ノード・イベント・JS の関数・Promise は、`.mjs` 内の**ハンドル表**で管理し、Wasm には整数のハンドル（表の添字と世代番号）だけを渡す。ハンドルの解放は Sigil の破棄に合わせて明示的に行い、JS の GC に任せない。古い世代のハンドルの使用は host failure とする。
- ホスト層（DOM アダプター、`UiMount` の登録と解除、`client.fetch` の発行と完了通知）は、JS 出力と**同じ実装を共有する**。P2-3 の完了通知（`to_event`）は、JS 側の完了を `.mjs` が受け、Wasm の入口（イベントの配送）を同期的に呼ぶ。Wasm の実行中の再入、ホストの例外、Promise を返す実装は、ADR 0039／0040 と同じく host failure として cleanup を行う。
- ホストの実装は信頼する呼び出し元の責任であり、任意のホスト JS を Sigil の効果検査で隔離するものではない。

Wasm を選んだときに、未対応の処理を黙って JS の実装へ切り替えない。**小さい明示的なホスト呼び出し**（一覧に載る import）と、**出力器の代替実行**（Wasm でコンパイルできない処理を JS で実行すること）を区別し、後者は行わない。

## 決定 6: CLI・生成前診断・フルスタックとの接続

```text
sigil build --emit wasm [--ui] [--root <根>] [--trace-drops] <ファイル> <関数> -o <出力.mjs>
```

`-o` に指定した `.mjs` の隣に、同じ語幹の `.wasm` を生成する。`--emit js`／`--emit native`、既定の native、`--root` の解決は従来のまま。`--ui` の意味は ADR 0040 決定 6 と同じ。Wasm に `--fs-double` や利用者の `--trust-base` を許さない。未知の出力器・重複／矛盾した指定・不正な入口は終了コード 1、成功は 0。`sigil run` は SIR 評価器のままとし、ブラウザの自動起動はしない。

P2-3 のフルスタックのビルド（`sigil build --target fullstack`、ADR 0041 決定 6）では、クライアントの出力を明示的に選べるようにする。既定は JS のままとし、Wasm を選んだ場合に未対応があれば、**JS へ切り替えずビルドを失敗させる**。この CLI の追加は P2-4 の実装 Issue で行い、本 ADR では ADR 0041 を改訂しない。

通常の検査と SIR 検証の後、ファイルを書き出す前に、Wasm 対応集合を依存閉包で全走査する（ADR 0039 決定 5 と同じ）。未対応の構文・型・操作・効果、サーバー専用効果は、出力先 wasm、位置、依存元の関数を含めて診断する。失敗時は部分的な `.wasm`／`.mjs` を残さず、既存の出力ファイルも上書きしない。生成後には、次を機械的に検査し、違反があれば成果物を削除してエラーにする。

- 生成した `.wasm` が import する名前が、入口の依存閉包から決まる一覧の部分集合であること。
- `.wasm` が `memory`・`table` を export していないこと（export は `.mjs` の内部で使う入口だけ）。
- 確定的であること（同じ入力から、同じバイト列の `.wasm` ができる）。
- ADR 0041 決定 6 の生成後走査（サーバー専用モジュール名・環境変数名・秘密のパターン）を、**`.wasm` のデータ領域にも適用する**。文字列リテラルは `.wasm` のデータ領域に入るため、`.mjs` だけを走査しても不十分である。

## 決定 7: 適合の確かめ方と完了条件

同じ入力ソース・入口・引数を共通検査／lowering で処理し、SIR 評価器・JS 出力・Wasm 出力で実行して比較する。Wasm と JS は実ブラウザ（Chromium／Firefox／WebKit）の ES module として動かす。Node.js の成功だけでブラウザ対応としない。

| 比較対象 | 確認内容 |
|---|---|
| 値・契約・停止・破棄・外部作用 | P2-1 の共通の適合例（ADR 0039 決定 6 の比較表）をそのまま流用し、3 つの実行で一致を確認する。破棄は `--trace-drops` の列を完全一致で比較する |
| 境界値 | i64 最小／最大・2^53 前後・ゼロ除算・全シフト幅、Float の NaN／無限大／負のゼロと変換境界、補助平面の文字・結合文字・U+E000〜U+FFFF との比較・CRLF・不正 UTF-8／孤立サロゲート、空／入れ子のコレクション |
| 解放の完全性 | 各適合例の終了時と `dispose` の後に、割り当て器の「生きているブロック数」が 0 であること。ネイティブの計数（`SIGIL_RT_LIVE`）と同じ趣旨の検査で、`FinalizationRegistry` に頼らないことを確かめる |
| 停止 | スタックの枯渇、`memory.grow` の失敗の注入、契約違反・算術停止が、停止の種類・関数・位置・`during` を保ち、cleanup を経ること。エンジンの trap が `internal` として区別されること |
| 生成物 | `WebAssembly.validate` の成功、import／export の一覧、ハッシュ不一致の検出（`.wasm` を差し替えて `load` が失敗すること）、同一入力で同一バイト列 |
| 拒否 | すべての未対応区分とサーバー専用効果を負例で確認し、生成前エラーでは成果物が変更されないこと。Wasm 選択時に JS へ黙って切り替わらないこと |
| 小アプリ | P2-2 のカウンター・入力検証・一覧更新と、P2-3 の型付き要求応答の小アプリを、**同じソースから JS と Wasm の両方で生成**し、実ブラウザで同じ操作をして同じ表示・通信・拒否になること |
| 比較の限界 | lowering を共有するため、その誤りを両側で見逃しうる。既存の意味を固定する期待値・期待破棄列と SIR 検証も維持し、出力同士の一致だけで仕様の正しさとしない |

性能（実行時間・生成物の大きさ・起動時間）は、JS 出力との比較を試験記録に**残す**が、初版の合否の条件にしない。

P2-4 の実装の完了は、許可一覧の各機能に正常例と必要な失敗例があり、3 エンジンの試験記録で上記の比較が通り、Node.js なしで小アプリを JS と Wasm の両方で操作できることとする。本 Issue の完了条件は起草 PR の作成までであり、これらの実装・テストは本 PR に混ぜない。

## 影響と実装前に確定すること

Wasm の出力器、割り当て器と型記述子を含む小さいランタイム、`.mjs` のローダーと共有ホスト層、適合試験の拡張が必要になる。新しい外部依存や信頼基盤の包括承認ではない。契約変更（SIR への追加が必要な場合）→ADR→実装→サンプル・テストの順と、別 PR の規則に従う。P2-1／P2-2／P2-3 の実装が前提で、特に共通の適合例と DOM アダプター（ADR 0039／0040）に依存する。実装 Issue はこの ADR のマージ後に起こす。

次は、実装前に別の決定または実測が要る。

1. **静的配信の CSP（ADR 0041 との接続）**: ADR 0041 決定 4 の `Content-Security-Policy: default-src 'self'; script-src 'self'; …` では、ブラウザの `WebAssembly.compile`／`instantiate` が拒否される（Wasm のコンパイルには `'wasm-unsafe-eval'` が要る）。Wasm を使うページにだけ `script-src 'self' 'wasm-unsafe-eval'` を許す必要があるが、`'unsafe-eval'` は許さない。`.wasm` の MIME タイプ（`application/wasm`）の追加も要る。ADR 0041 の改訂は本 ADR の範囲外とし、**P2-4 の実装 Issue より前に、ADR 0041 の静的配信の規則を改訂する別 Issue を起こす**ことを提案する。
2. **論理スタックと呼び出しの深さの数値**（決定 4）、**メモリ上限の数値**（決定 3）の 3 エンジンでの実測。
3. **`memory.grow` 失敗の停止種別の対応**。現在の停止の種別（`RequiresViolated`・`EnsuresViolated`・`StdRequiresViolated`・`Overflow`・`DivisionByZero`・`StackExhausted`）に資源枯渇に当たるものがあるかを確認し、無ければ契約変更として扱う。
4. **`Float` の文字列化（Displayable）の実装方法**。JS のホストに頼らず Wasm 内で、既存の表示（NaN／inf／-inf／-0.0 を含む）と一致する実装にする。正解の列を SIR 評価器から作って固定する。
5. **実装の分割**（例: 出力器の核→値と破棄→UI のホスト層→通信→CLI とフルスタック接続）は、実装 Issue 側で決める。

P1 の外部公開前の残課題（#547〜#552）は本作業で修正・再起票しない。
