## 背景と前提

[ADR 0044](0044-p4-scope.md) の段 P4-3 として、Git のオブジェクト形式と互換な、ローカルのリポジトリ管理の核を定める。ネットワーク転送と管理画面は P4-4、データベースは [ADR 0045](0045-p4-1-database-core.md)（P4-1）・[ADR 0046](0046-p4-2-database-server.md)（P4-2）。ADR 0044 の「各段は単独で使える成果物を出す」に従い、本段は P4-4 が無くてもローカルの履歴管理として使える。ADR 0043 の仕様差分は、本段が提供する **スナップショットの取り出し**を、ディレクトリの代わりの入力として使える（ADR 0043 は初版でディレクトリ比較としており、改訂しない）。

起草の基準は `main` の `da6ba6a`。0047 は main の索引・ファイルとオープン PR で未使用であることを確認し、本 PR の索引行で予約する。本 PR は ADR の新規作成と索引行だけを変更し、処理系・`sigil spec` の出力・実装・バックログは変更しない。以下は将来の実装に向けた決定であり、現行の処理系の機能を記述するものではない。

前提となる既決事項:

- **版取得**（Issue #573 の決定、ADR 0045）: 実装は `sigil` の完全なコミット SHA を checkout し、同梱 `Cargo.lock` で `cargo build --locked --release` して得たコンパイラと標準ライブラリを使う。浮動 main やタグだけに依存しない。必要な fs が揃う前の SHA は、永続化を伴う実装を完成できる版として扱わない。
- **標準ライブラリの不足**（Issue #576 の結論、ADR 0045 決定 1）: ディレクトリ操作・ファイルのロック・追記・位置を指定した読み書き・同期・原子的な名前変更は、公開 `std.fs` の拡張と既存 `std.os.fs` の信頼基盤の拡張で、共通 fs 境界 ADR → fs 実装 A〜C の順に進む。圧縮は純 Sigil／`trust none` の別モジュール（契約 ADR → 実装）、SHA-1 は P4-3 が必要と決めた場合のみ。**これらの実装完了は本 ADR の起草条件ではない**。既存の全量読み書きで代替して持続性を名乗らない。
- **永続化の共通規則**（ADR 0045 決定 4）: 更新の公開点を一つにする、同期前に成功を返さない、同一 FS の rename と親ディレクトリ同期、長さ・版・検査値の検証、復旧に必要な旧データを公開完了まで保持する、冪等な復旧、障害注入と互換 fixture。Git のオブジェクトと参照に、データベースのページ形式や WAL の流用を強制しない。
- **実装の置き場所**（ADR 0044 決定 4）: 仕様は本リポジトリ、実装は所有者が作成・命名する別のリポジトリ（リポジトリ管理用）。リポジトリの作成・権限・CI・保護設定は所有者の操作で、作成までは実装に着手しない。アプリケーション側に `raw.*`／`unchecked` や信頼基盤の迂回を足さない。純 Sigil の `trust none` の核とし、公開 `std.fs` を利用する。

## 現状の確認

- 標準ライブラリの `std.fs` は、ファイル全体の `read`／`write`／`read_bytes`／`write_bytes` だけ（#576 の確認）。**ファイルの種別・実行ビット（モード）の取得と設定**は、#576 の不足の一覧に無い。Git のツリーはファイルのモード（通常 100644／実行 100755）を保存し、チェックアウトで復元するため、本段の追加の前提になる（「前提と持ち越し」の 1）。
- `std.crypto` に SHA-256 がある。SHA-1、zlib／deflate、CRC-32 は無い。
- 手元の確認環境の Git は 2.43.0。`git init --object-format=sha256` が使える（SHA-256 形式は Git 2.29 以降）。CI で比較に使う Git の版は、実装リポジトリが固定して記録する。

## 選択肢と決定

| 判断 | 採用する案 | 他案を採用しない理由 |
|---|---|---|
| オブジェクト識別子 | **SHA-256 形式のリポジトリだけ**を読み書きする。SHA-1 形式のリポジトリは `UnsupportedFormat` で明示的に拒否する | SHA-1 を含めると、衝突検出のない SHA-1（Git 本体は衝突検出付きの実装を使う）を、信頼できない入力を読む経路に置く。std.crypto に弱いハッシュを足す追加の信頼面と、#576 の SHA-1 契約 ADR・実装の前倒しが要る。SHA-256 は Sigil の暗号部品と OCI のダイジェスト（ADR 0044 決定 5 の 3）に揃う |
| オブジェクトの保存 | 緩い形式（loose）の読み書き、pack と pack index（v2）の**読み取りのみ**。書き込みは緩い形式 | pack の書き込み（`repack`／`gc`）は圧縮率と差分の探索が要り、初版の価値に比べて検証範囲が大きい。pack を読めないと、本物の Git が `gc` や `clone` で作ったリポジトリを読めない |
| 作業木と索引 | Git の索引（index v2）の最小実装を読み書きする。ただし stat 情報は信頼せず、常に内容で判定する | 索引を持たないと、本物の Git が `status`／`diff`／`commit` で本実装の状態と整合しない。stat を信頼すると、racy-git（同一時刻の変更の見落とし）の判定を再実装する必要がある |
| 差分 | 変更されたパスと変更の種類（追加・変更・削除・モード変更）は Git と完全一致。パッチの本文は、`git apply` が受理し、同じ木になる正しいパッチ | パッチのバイト一致は、Git の差分アルゴリズム（xdiff）とヒューリスティクスの完全な再現を要し、価値に対して検証範囲が過大 |
| 併合 | 単一のマージベースの三方向併合。衝突のない場合だけ併合コミットを作り、衝突があれば構造化された衝突の一覧を返して**何も変更しない** | 衝突マーカーを作業木に書き、MERGE_HEAD 等の途中状態を作ると、中断・復旧の状態数が増え、検証できる完了条件を満たしにくい。改名検出は仕様が大きい |
| 安全 | 悪意のあるリポジトリを入力として扱う。危険な木の名前・symlink・gitlink・フック・実行を伴う設定は拒否または無視する | Git の既定の振る舞い（symlink の作成、フック、フィルタドライバ）に従うと、過去の Git の脆弱性と同種の攻撃面を再現する |

正式判定は未実施である。上の採用案は、判定を経ていない起草者の案であり、判定の結果を装わない。採用理由は、ADR 0044 の完了条件（本物の Git との相互運用で検査できる）、検証できる範囲の小ささ、既存の暗号部品との整合に置く。

## 決定 1: 対象とする形式と操作の範囲

### 対象のリポジトリ

- 通常の（bare でない）リポジトリと、bare リポジトリ。`extensions.objectFormat = sha256` かつ `core.repositoryformatversion = 1` のもの。作成は `init` が行い、設定は最小（必須の拡張だけ）で書く。
- 次は**未対応**で、検出したら明示的に拒否する（黙って無視しない）: SHA-1 形式、`extensions.refStorage = reftable`、`objects/info/alternates`、`shallow`、`worktrees`（複数の作業木）、`.git` ファイル（gitdir へのリンク）、`replace` 参照、部分的複製（`promisor`）、疎なチェックアウト（sparse-checkout）、分割索引（split index）。
- 次は**読んでも解釈しない**: `commit-graph`、`multi-pack-index`、ビットマップ、`FETCH_HEAD`、reflog、`gc.log`。これらは最適化や履歴の補助情報で、無視しても正しさを損なわない。ただし本実装が書いたオブジェクトや参照を、これらが古くして矛盾させない（本実装は commit-graph を作らず、既存の commit-graph に頼らない）。

### オブジェクト形式

- 型: blob・tree・commit・tag。ヘッダ `<型> <長さ>\0` の後に内容。識別子はヘッダを含めた全体の SHA-256。読み取り時は、内容から識別子を再計算して**名前と一致することを毎回検証する**（Git のオブジェクトは自己検証できるため）。
- tree: エントリは `<モード> <名前>\0<識別子 32 バイト>`。モードは 100644・100755・40000（ディレクトリ）を扱い、120000（symlink）と 160000（gitlink）は**読んで保持するが、作業木には書かない**（決定 4）。並び順（ディレクトリは名前の末尾に `/` があるものとして比較する）、名前の重複・空・`/` や NUL を含む名前の拒否を、読み書きの両方で検査する。
- commit: `tree`・`parent`（0 以上）・`author`・`committer`・追加のヘッダ（`gpgsig`、`encoding`、`mergetag` 等は**そのまま保存して往復する**。検証や解釈はしない）・空行・メッセージ。バイト列として往復し、正規化しない。
- tag: 注釈付きタグのオブジェクトを読む。作成は軽量タグ（参照だけ）とし、注釈付きタグの作成は初版に含めない。
- 署名は検証しない。署名を含むオブジェクトを書き換えない。

### 保存形式

- **緩い形式**: `objects/<先頭 2 文字>/<残り>`。内容は zlib で圧縮する。**読み取り**には完全な inflate（固定・動的 Huffman、保存ブロック）が要る。**書き込み**は、有効な zlib であれば Git が受理するので、初版は圧縮率を問わず、非圧縮（stored）ブロックの zlib を出力してよい。圧縮器（deflate）の実装は #576 の圧縮契約 ADR の範囲で、本 ADR は圧縮率を完了条件に含めない。
- **pack**: `objects/pack/pack-*.pack` と `.idx`（v2）を読む。差分（`OFS_DELTA`、`REF_DELTA`）を解決する。`.idx` の末尾の検査値と pack の末尾の検査値は検証する。`.idx` が指す位置の再検証（オブジェクトの識別子の再計算）は、読み取り時に行う。pack の書き込み、`repack`、`gc`、`prune` は**行わない**。したがって本実装はオブジェクトを削除しない（不要なオブジェクトは蓄積する）。
- **参照**: `HEAD`（シンボリック参照または分離 HEAD）、`refs/heads/*`、`refs/tags/*`、`packed-refs`（読み取り）。書き込みは緩い参照のファイルと、`packed-refs` からの**削除**（ファイル全体の書き換え。決定 2）だけで、`packed-refs` へ参照を追加したり、`pack-refs` を行ったりはしない。`packed-refs` に同名があるときは、緩い参照が優先される（Git と同じ）。更新は緩い参照を書けば足りるが、削除は緩い参照だけを消すと `packed-refs` の値が再び有効になるため、決定 2 の手順で行う。リモート追跡参照は P4-4 で扱う。

### 操作

| 操作 | 範囲 |
|---|---|
| `init` | SHA-256 形式の空のリポジトリを作る |
| オブジェクトの読み書き | 識別子による取得、内容の書き込み（blob・tree・commit）、存在確認、型と長さの取得 |
| `add` | 明示したパスのファイルを blob にして索引に入れる。ディレクトリは再帰的に列挙する。無視規則（`.gitignore`）は**適用しない**（明示したパスだけを扱う） |
| `commit` | 索引から tree を作り、commit を作って現在のブランチを進める。作者・コミッター・時刻・タイムゾーンは**呼び出し側が引数で渡す**（環境変数・設定ファイル・時計を暗黙に読まない） |
| `log` | 履歴の列挙。順序は**位相順**（子が親より先）で、同一コミットの重複なし。比較は `git log --topo-order` と行う |
| `diff` | 木と木、木と作業木の差分。決定 3 |
| `checkout` | コミットまたはブランチへ作業木・索引・HEAD を切り替える。決定 4 |
| `merge` | 三方向併合。決定 3 |
| ブランチ・タグ | 作成・削除・一覧（軽量タグのみ作成）。`packed-refs` にある参照の削除を含む（決定 2）。ブランチの改名は初版に含めない |
| スナップショット | 指定したコミットの木を、作業木に書かずに読み取り専用で取り出す（ファイルの一覧、内容、モード）。ADR 0043 の仕様差分の入力に使える |

### 含めないもの

ネットワーク転送（`clone`／`fetch`／`push`、P4-4）、`rebase`・`cherry-pick`・`revert`・`stash`・`bisect`、サブモジュール、フック、`.gitattributes`（改行変換・フィルタ・`export-ignore`）、`.gitignore`、`git config` の一般的な読み書き、署名の検証、reflog の書き込み、ワークツリーの複数化、`gc`・`repack`・`prune`、`blame`、改名・コピーの検出。「全機能の実装済み」を意味しない。対応表に「未対応」として残す（ADR 0044 決定 2）。

## 決定 2: 永続化・原子性・復旧

ADR 0045 決定 4 の共通規則を、Git の形式に次のように適用する。

- **オブジェクトの書き込み**: 一時ファイルを同じディレクトリに**排他的に作成**して書き、内容を同期し、最終名へ同一 FS の rename で公開し、親ディレクトリを同期してから成功を返す。最終名が既にあれば（同じ識別子は同じ内容）書き込みを省略してよいが、既存の内容を検証せずに「存在」と扱わない。オブジェクトは**追記のみ**で、公開後に書き換えない。部分的な書き込みは一時名に残るだけで、読み手には見えない。
- **参照の更新**: 更新の公開点は参照ファイルの rename ただ一つ。`<参照>.lock` を排他的に作成し、新しい識別子と改行を書いて同期し、rename で置き換え、親ディレクトリを同期する。更新の前に、参照が指すオブジェクトとその到達可能な親がすべて**永続化済み**であることを保証する（オブジェクトを先、参照を後）。期待する旧値を比較して更新する（compare-and-swap）。ロックが既にあれば `Locked` で失敗し、古いロックを自動では削除しない。
- **参照の削除**: `packed-refs` にも同名の参照があるとき、緩い参照だけを消すと packed 側の値が再び有効になる。そこで、(1) その参照の `<参照>.lock` を排他的に取り、(2) `packed-refs.lock` を排他的に取り、(3) ロックの下で `packed-refs` を読み直し、期待する旧値と一致することを確認し、(4) 対象の行（と、その下の `^` で始まる peeled の行）だけを除いた全体を新しい一時内容として書き、ヘッダ（`# pack-refs with:` の特性）と他の行は変えずに、同期し、rename で置き換え、親ディレクトリを同期し、(5) その後で緩い参照を削除して親ディレクトリを同期し、(6) ロックを解放する。**packed 側を先に消す**。(4) と (5) の間で中断しても、緩い参照が残るので、参照が復活せず、削除が未完了のまま（再実行で完了できる）になる。`packed-refs` に無い参照は、緩い参照の削除だけでよい。`packed-refs` の書き換えは、読み取った内容をすべて保存する（未知のヘッダの特性は拒否する）。
- **索引の更新**: `index.lock` を同じ方法で使い、完全な索引を書いて rename する。
- **作業木の更新**: 各ファイルを一時名に書いて rename する。作業木の更新は全体としては原子的ではない。**チェックアウトが中断したときは、HEAD と索引を更新の最後に公開する**ことで、中断後の `status` が「HEAD の木と索引の差分」として観察でき、ユーザーの未保存の変更を失わない状態を保つ。中断した更新を黙って再開しない。
- **途中の失敗**: 一時ファイル（本実装が作った接頭辞のもの）は、明示的な `cleanup` 操作でだけ削除する。ロックファイルは削除しない。データを失わせる自動修復より、拒否を選ぶ。
- **同時実行**: 同じリポジトリを同時に更新するプロセスは、参照・索引のロックで排他する。読み取りはロックを取らない。本実装と本物の Git が同時に動いた場合も、ロックの規約（`*.lock` の排他的作成）が同じなので安全である。
- **命名と大文字小文字**: 参照名は Git の規則（`check-ref-format` に相当）を検査し、`..`、`@{`、制御文字、末尾の `.lock`、`/` の連続を拒否する。大文字小文字を区別しない FS での名前の衝突は、拒否する。

## 決定 3: 差分と併合

### 差分

- 木と木の差分は、パスの辞書順（tree の順序）で、追加・削除・変更（内容、モード）を列挙する。ここは Git の `diff --name-status`（改名検出なし）と**完全に一致**させる。
- 行単位のパッチは、`diff -u` 形式で出力する。**バイト一致は要求しない**。正しさの条件は、(a) 本物の `git apply` が本実装のパッチを受理して同じ木になること、(b) 本物の `git diff` が出したパッチを本実装が適用して同じ木になること。バイナリファイルは「バイナリが異なる」と報告し、本文を出さない。
- 改名・コピーの検出、単語単位の差分、色付けは対象外。

### 併合

- 入力は二つのコミットと、その**単一のマージベース**。マージベースが複数ある（交差するマージ）ときは `MultipleMergeBases` として拒否する（初版は再帰的な仮想ベースを作らない）。
- ファイルごとの三方向併合: 片側だけが変更したものはその側を採る。両側が同じ変更ならそれを採る。両側が異なる変更をしたとき、テキストなら行単位の三方向併合（変更範囲が重ならなければ併合し、重なれば衝突）。バイナリ・モード・追加／削除の組合せの衝突は、常に衝突とする。改名検出がないので、改名と編集の組合せは、Git が併合できる場合に本実装が衝突とすることがある（許す。対応表に残す）。
- **衝突のないときだけ**併合コミット（親が二つ）を作り、ブランチを進め、作業木を更新する。衝突があるときは、衝突したパスと種類の構造化された一覧を返し、**リポジトリ、索引、作業木のいずれも変更しない**。`MERGE_HEAD` 等の途中状態を作らない。衝突の解決の流れ（マーカーの書き出し、解決後の続行）は、別の ADR で決める。
- 併合の結果の木は、本物の Git の併合（改名検出を無効にした設定）と一致するか、Git が衝突とする場合に本実装も衝突とする。本実装だけが衝突とする場合（改名の例）は許す。本実装が併合して Git が衝突とする場合は、**不一致として扱い、修正する**。

## 決定 4: 作業木・チェックアウトと安全

悪意のあるリポジトリは入力として扱う。

- **パスの検査**: ツリーのエントリの名前に、`.`、`..`、空、`/`、NUL、`.git`（大文字小文字を区別せず。末尾のドットや空白、NTFS の短い名前、HFS+ の無視される Unicode 文字を含む変種を含む）を含むものを、チェックアウトと `add` の両方で拒否する。パスの全長と構成要素の数に上限を置く。絶対パス、バックスラッシュを含む名前（大文字小文字・区切りの意味が環境で変わるため）も拒否する。
- **作業木の外への書き込み禁止**: すべての書き込み先は、リポジトリの作業木の下に正規化されたパスで、途中の構成要素が通常のディレクトリであることを書き込みの直前に検査する。symlink をたどって書き込まない。
- **symlink（120000）**: 初版は作業木に作らない。チェックアウトで symlink のエントリに当たったら `UnsupportedEntry` で失敗し、**そのチェックアウト全体を実行前に拒否する**（途中まで書いた状態を作らない。事前にすべてのエントリを検査する）。`add` も symlink を対象にしない。
- **gitlink（160000、サブモジュール）**: tree に保持して往復するが、作業木には書かず、再帰もしない。チェックアウトでは空のディレクトリも作らず、`UnsupportedEntry` とする。
- **フック・設定**: フック（`.git/hooks`）は**実行しない**。設定ファイルは、`core.repositoryformatversion` と `extensions.objectFormat` など、形式の判定に必要な最小のキーだけを読み、それ以外のキー（`core.fsmonitor`、`core.sshCommand`、`core.hooksPath`、`include.path`、`filter.*`、`diff.external` など実行や読み込みを伴うもの）は**解釈しない**。`.gitattributes` と `.gitignore` も解釈しない。
- **未保存の変更の保護**: チェックアウトは、切り替えで内容が変わる（書き換え・削除・追加される）すべてのパスについて、次のいずれかがあれば、何も変更せずに失敗する。(a) 作業木のファイルが索引と異なる、(b) **索引のエントリが現在の HEAD の木と異なる**（`add` 済みで未コミットの変更。作業木と索引が一致していても、切り替えで両方から失われるため）、(c) 追跡されていないファイルが上書きされる。ただし、切り替え先の木の内容が、索引と作業木の現在の内容と同一であるパスは、変更されないので対象にしない。判定は、HEAD・索引・作業木・切り替え先の四つを、パスごとに事前にすべて比較してから行う。強制する指定は初版に含めない。
- **実行ビット**: モード 100755 のファイルは実行ビットを付けて書く。それ以外のモード（setuid、ownership）は設定しない。ファイルの所有者・時刻は復元しない。
- **改行・エンコーディング**: ファイルの内容はバイト列のまま、変換しない。ファイル名は、名前のバイト列を UTF-8 として扱えない場合を `InvalidPath` とする。

## 決定 5: 上限

読み取りは、割り当ての前に宣言された長さを検査し、加算・乗算・offset の溢れを拒否する。上限超過は専用のエラーで失敗し、暗黙の切り捨てや、上限を避ける自動縮退をしない。値は初版の提案で、個別の実装 PR で実測し、**引き下げることはあっても、引き上げる場合は ADR を改訂する**。

| 項目 | 初版の上限 |
|---|---|
| 1 オブジェクトの展開後の大きさ（ヘッダの宣言と実際の展開量が一致しなければ拒否） | 64 MiB |
| 展開後と圧縮前の大きさの比（入力が小さく出力が巨大になる圧縮爆弾の拒否） | 展開を始める前に宣言の長さで検査し、宣言を超える出力を打ち切る |
| tree のエントリ数／1 つの tree の符号化サイズ | 100000／16 MiB |
| パス全長／構成要素の長さ／階層の深さ | 4096 byte／255 byte／128 |
| commit の親の数／ヘッダの数・合計サイズ／メッセージの大きさ | 16／1024・64 KiB／1 MiB |
| 差分（delta）の連鎖の深さ／差分の復元後の大きさ | 64／64 MiB |
| 1 つの pack のオブジェクト数／pack のファイルの大きさ | 2^24／4 GiB（位置指定で読み、全体をメモリに載せない） |
| 履歴の走査で保持する識別子の数 | 2^24（超過は `LimitExceeded`） |
| 索引のエントリ数／1 つの `add` が扱うファイル数 | 100000／100000 |
| 参照の数／参照名の長さ／`packed-refs` の大きさ | 100000／1024 byte／64 MiB |
| 核の作業メモリ | 256 MiB |

SHA-256 の計算が遅いこと（Issue #539 の実測で、4096 回の PBKDF2、すなわち約 8192 ブロックの圧縮が、評価器で約 2.7 秒、ネイティブで約 1.4 秒。1 ブロックあたり約 0.2〜0.3 ms で、64 バイトあたりに換算すると毎秒数百 KB 程度）が、読み取りごとの識別子の再計算を律速にする。性能は完了条件の合否にせず（ADR 0044 決定 1）、固定した版・装置・件数とともに記録する。ただし、**検証を省いて速くしない**（識別子の検証は常に行う）。

## 決定 6: 完了の確かめ方

ADR 0044 のとおり、本物の Git を比較相手とする。比較に使う Git の版は実装リポジトリが固定して記録する。

1. **本物の Git が作ったリポジトリを読む**: `git init --object-format=sha256` で作り、`commit`・`branch`・`tag`・`merge`・`gc`（pack 化と差分）・`pack-refs --all` を行ったリポジトリの fixture を、本実装が読む。オブジェクト（型・長さ・内容）、履歴（`git log --topo-order` の識別子の列）、`ls-tree -r`、`diff --name-status` が一致する。
2. **本実装が作ったリポジトリを本物の Git が受理する**: 本実装の `init`・`add`・`commit`・`branch`・`merge` で作ったリポジトリに対し、`git fsck --strict --full` が成功し、`git log --topo-order`、`git ls-tree -r`、`git diff --name-status`、`git cat-file` が本実装の読み取りの結果と一致する。本物の Git の `checkout` が、本実装のコミットを同じファイル（内容・モード）に展開し、`git status` が clean になる。本実装の `checkout` の後でも、本物の Git の `git status` が clean になる（索引の整合）。`add` 済みで未コミットの変更、作業木だけの変更、追跡されていないファイルの上書きを含む状態からの `checkout` が、何も変更せずに失敗する。`gc`・`pack-refs --all` した本物の Git のリポジトリで、本実装がブランチとタグを削除しても、削除した参照が復活しない。
3. **差分と併合**: 決定 3 の条件を、改名なし・あり、バイナリ、モード変更、空ファイル、末尾に改行がないファイル、CRLF を含む corpus で確かめる。`git apply` の相互受理と、併合の木の一致を比較する。
4. **悪意のある入力**: 過去の Git の脆弱性と同種のパス（`.git` の変種、`..`、symlink を使った外部への書き込み、gitlink、巨大な tree・圧縮爆弾・差分爆弾・循環する差分の連鎖）を含む fixture を与え、作業木の外に書かないこと、上限を超える割当てをしないこと、`panic` しないことを確かめる。
5. **障害注入**: オブジェクトの書き込み・参照の更新・索引の更新・チェックアウトの各ステップ（一時ファイルの作成、書き込み、同期、rename、親ディレクトリの同期、ロックの解放）の前後でプロセスを強制終了し、再実行する。short write、`ENOSPC`、`EIO`、同期の失敗も注入する。いずれの場合も、(a) `git fsck --strict` が成功する、(b) 応答済みの `commit` は参照から到達できる、(c) 参照が指すオブジェクトが欠けた状態にならない、(d) ユーザーの未保存の変更（作業木だけの変更と、`add` 済みで未コミットの変更の両方）が失われない。参照の削除（`packed-refs` にある参照を含む）の各ステップ（二つのロックの取得、`packed-refs` の書き換え、緩い参照の削除、ロックの解放）の前後でも中断し、削除した参照が復活せず、`git fsck --strict` が成功することを確かめる。ADR 0045 の完了条件 3 と同様、プロセスの強制終了だけでは OS のキャッシュが残るため、同期済み境界以降の書き込みの喪失・並べ替えを再現する永続化モデルも併用し、実 FS の試験と分けて記録する。
6. **ファジング**: 緩い形式のヘッダ、tree、commit、tag、pack と pack index、差分（delta）、inflate、索引（index v2）、設定、`packed-refs`、参照名・パスの検査。期間・seed・corpus・回帰例を残す。
7. **互換 fixture**: 初版から保存した fixture を版管理し、新しい reader が古い fixture を読めることを確認する（ADR 0045 決定 4 と同じ）。
8. **両実行経路の一致**: ネイティブと SIR 評価器で同じ操作列・エラー・上限の結果が一致する。依存する fs の信頼差分の監査結果を結び付ける。
9. **性能の記録**: 固定した版・装置・seed・件数で、オブジェクトの書き込み・読み取り・`log`・`diff`・`checkout` の時間とメモリを両経路で記録する。初版の合否にしない。

意図した誤りが検出されるかの測定（変異の注入）も行う。例: 識別子の検証の省略、参照の更新前にオブジェクトを同期しない、ロックの無視、パス検査の省略、symlink の追従を個別に埋め、上の試験が落ちることを記録する。検出されない変異を検証済みとしない。

## 脅威と対策（公開関門 G1）

| 脅威 | 対策・残る限界 |
|---|---|
| 悪意のあるリポジトリ（パス、symlink、`.git` の変種、gitlink）による作業木の外への書き込み・設定の改変 | 決定 4 の検査、書き込み直前の構成要素の検査、事前の全エントリ検査、`.git` 配下を作業木のエントリとして書かない。この表の残る限界: OS の権限の範囲の外は保証しない |
| 圧縮爆弾・差分爆弾・巨大な tree・循環する差分の連鎖によるメモリ／CPU の枯渇 | 割り当て前の長さ検査と決定 5 の上限、差分の連鎖の深さと循環の検出、`LimitExceeded`。全探索にも走査数の上限 |
| ハッシュ衝突・オブジェクトのすり替え | SHA-256 のみ。読み取りごとに識別子を再計算して名前と一致を検証。SHA-1（衝突の攻撃が実在する）を受け入れない |
| フック・フィルタ・外部コマンドの実行による任意コード実行 | フックを実行しない。実行を伴う設定のキーを解釈しない。外部プロセスを起動しない |
| 作者情報などの個人情報・秘密の混入 | 作者・時刻を呼び出し側が明示的に渡す（環境変数や設定から暗黙に取らない）。エラーとログに、ファイルの内容・認証情報・作者のメールを出さず、位置と種別だけにする。試験は使い捨てのデータだけ |
| 削除後の残留 | オブジェクトを削除しない（`gc` がない）。履歴から消しても、ファイルシステム上に残る。履歴の書き換え（強制的な参照の更新）による秘密の「削除」を安全な消去と表示しない |
| 中断による破損・参照の指すオブジェクトの欠落 | 決定 2。オブジェクトを先に永続化してから参照を更新し、ロックの規約を Git と合わせる |
| ロック競合・古いロックの残り | `Locked` で失敗し、自動削除しない。手動の復旧手順を個別 ADR または運用記録に残す |
| 保存暗号化とアクセス制御 | 初版は提供しない（ファイルの所有者・権限は OS に依存）。ADR 0044 決定 3 のとおり、暗号化の要否は公開前の所有者判断に持ち越す |

「いまは外部公開しない」を維持する（ADR 0044 決定 3）。検証は CI と手元の隔離コンテナで行い、外部のネットワークや実在の利用者のデータ・秘密を使わない。G2 に相当する確認として、上の完了の確かめ方と、定数時間（本段は新しい暗号処理を追加しない。識別子の比較は公開情報のため定数時間の対象外と記録する）・上限・秘密・信頼基盤の監査を含める。G3 に相当する別セッションの公開前レビューの報告は `docs/security/` に残し、P1 の残件（Issue #547〜#552）と合わせて所有者が公開可否を判断する。本 ADR の PR の作成・マージは公開許可ではない。

## 他の段との関係

- **P4-1／P4-2**: 永続化の規則を共有する（決定 2）。データベースのページ形式や WAL は使わない。P4-2 のサーバーが保存する値の版管理に本段の履歴を使うことは、本 ADR の範囲に含めない。
- **P4-4**: 転送とホスティングは、本段の読み書きの上に載る。転送で受け取る pack の検証（識別子の再計算、接続性の検査、上限）は P4-4 の ADR で決める。本段の pack の読み取りと検証が、その土台になる。SHA-1 形式のサーバー（一般的な公開ホスティング）とは、本段の方針（SHA-256 のみ）では相互運用できない。この制約は P4-4 の ADR で再評価する。
- **P5（コンテナ管理）**: オブジェクトの保存は、Git 固有のヘッダの付与と型付けを上位に、`識別子 → バイト列` の保存・検証・列挙を下位に分けて設計する。これにより、P5 がコンテナのイメージの層（OCI、SHA-256 のダイジェストで参照）を同じ下位に置ける余地を残す。下位は検証関数（識別子の計算方法）を差し込める形にする。細部は P5 の ADR で決める。宣言の版管理（ADR 0044 決定 5 の 4）は、スナップショットの取り出し（決定 1）と、ADR 0043 の二つの版の比較で満たす。
- **P2-5（IDE）**: スナップショットの取り出しは、ディレクトリの代わりの比較単位として使える。IDE 側の取り込みは P2-5 の実装 Issue または別の ADR で決める。

## 実装の置き場所と依存する版

ADR 0044 決定 4・ADR 0045 と同じ。実装は所有者が作成・命名する別のリポジトリに置き、`sigil` の完全なコミット SHA を固定して使う。個別 ADR として、依存する SHA は、必要な fs（ディレクトリ操作・ロック・位置指定の読み取り・同期・原子的な rename・ファイルのモード）と圧縮（inflate）が入った版であることを条件とし、**未定の将来の SHA を固定済みとして書かない**。リポジトリの作成までは実装に着手しない。所有者が作成を待たず `sigil` の中で始めると決める場合は、その旨と移す時期を記録する。

## 完了条件と後続の切り方

本 Issue の完了は **ADR と索引行だけの起草 PR 作成**。以降は、共通 fs 境界 ADR と圧縮の契約 ADR の確定、必要な契約変更→ADR→実装→サンプル・テストの順に進める。実装は次の単位に分けてレビューする（前の単位が後ろの前提）。

1. 純粋な核: オブジェクトの符号化・復号、識別子、tree／commit／tag、パスと参照名の検査、inflate（fs に依存しない）。
2. オブジェクトの保存（緩い形式）と参照、リポジトリの `init` とロック（fs A・C に依存）。
3. pack と pack index の読み取り（位置指定の読み取り、fs B に依存）。
4. 索引・`add`・`commit`・`checkout`・作業木の書き込み（ファイルのモードに依存）。
5. `log`・`diff`・`merge`・スナップショット。
6. 障害注入・ファジング・Git との比較・互換 fixture の検証記録。

P4-3 の実装完了は、決定 6 の全項目を満たすことを必要とする。

## 前提と持ち越し

本 PR では修正・再起票・実装をしない。

1. **ファイルのモードの取得と設定**（実行ビット）: #576 の不足の一覧に無い。共通 fs 境界 ADR の対象に加えるか、別の項目として扱う判断が要る。無い場合、モード 100755 を往復できない。
2. **圧縮の契約 ADR**: inflate は必須、deflate は stored ブロックで足りるが、契約（展開量・メモリの上限、Adler-32、破損・打切りの拒否）は圧縮の契約 ADR で決まる。
3. **SHA-1 形式の読み取り**: 既存の公開リポジトリ（大半が SHA-1）を読めない。必要になった場合は、衝突検出付きの SHA-1 の契約 ADR（#576 の項目 6）と、本 ADR の改訂を別に起こす。
4. **CRC-32**: pack index の `crc32` 欄を検証に使うかは、実装の PR で決める（使うなら純 Sigil で追加）。
5. **評価器・ネイティブの速度**（Issue #539）: SHA-256 の速度が、識別子の検証を伴う読み取りの律速になる。性能を完了条件に含めるかは決定 5 のとおり含めない。
6. **公開関門 G3 の未達と Issue #547〜#552**: P4 の開始条件ではない。
7. **ADR 0020 の公開関門を P4 に適用するための改訂の要否**（ADR 0044 の持ち越し 4）。

## 影響

本段で、Sigil のコミットとブランチの履歴を、Sigil で書いた小さなツールで読み書きできる足場ができる。標準ライブラリ（ファイル・圧縮）と、検査済みの純 Sigil の核を前提とし、新しい効果のカテゴリ・原始操作・アプリケーション側の信頼基盤の許可は要らない見込みである。本 ADR は新しい依存・信頼基盤・外部公開の承認ではない。

## 正式判定の記録

2026-11-16 の所有者指示に従い、Gemini Decisions は使わず typesafe-ai のみを使う。

**本 ADR の正式判定は、起草時点で未実施である。** この起草セッション（claude.ai の Code セッション）には、判定 API（`POST https://api.typesafe.ai/v1/systemone`）の認証キー `TYPESAFE_API_KEY` が設定されておらず、`api.typesafe.ai` への通信がネットワークの許可で遮断されている（AGENTS.md の「キーが無い環境」。ADR 0042〜0044 の起草時と同じ）。このため、判定の入力・応答の JSON は本 ADR に無く、確率や confidence も記載しない。

扱い:

- 上の「選択肢と決定」の採用案は、**判定を経ていない起草者の案**である。
- 判定は、キーと許可ドメインが使える環境で、評価軸（ADR 0001 の人間は仕様だけをレビューする原則、ADR 0005・0044 の P4 の位置づけ、ADR 0020 の公開関門と「いまは外部公開しない」、ADR 0045 の永続化の共通規則、本 ADR の決定 1〜6）を固定して実施する。想定する問いは次の 4 つ。
  1. **Hash**（オブジェクト識別子）: `sha256_only`（SHA-256 形式のみ。SHA-1 は明示的に拒否）／`sha1_and_sha256`（両方を扱う）／`sha1_only`（SHA-1 のみ）。
  2. **Scope**（形式と操作の範囲）: `local_core_pack_read`（緩い形式の読み書き、pack の読み取りのみ、索引 v2 の最小実装、ローカルの操作）／`loose_only`（pack を扱わない）／`full_compat`（pack の書き込み、`gc`、索引の拡張、`.gitignore`・フィルタを含む）。
  3. **Merge**（差分と併合）: `semantic_clean_or_report`（パスと種類は Git と完全一致、パッチは相互に受理、併合は衝突があれば何も変更せず報告）／`byte_identical_with_markers`（パッチのバイト一致と、衝突マーカーを作業木に書く流れを初版から含める）／`defer_merge`（併合を初版から外す）。
  4. **Safety**（悪意のあるリポジトリの扱い）: `reject_unsafe`（symlink・gitlink を書かず、フックと実行を伴う設定を無視し、危険なパスを拒否）／`git_default_behavior`（Git の既定の振る舞いに従う）。
- 判定の入力・応答の JSON は、実施後にこの節へ追記する（別 PR でよい）。判定が採用案と異なる結果になった場合は、本 ADR を改訂してから実装 Issue を起こす。
- それまで、本 ADR の状態は「提案」のままとし、承認へ進めない。
