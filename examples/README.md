# examples

構文と意味論の検討に使うサンプルを置きます。実行可能なコードはまだありません（パーサ・処理系は未実装）。

## 構文候補

同じプログラムを 3 つの構文候補で書き、比較します。

| 候補 | ファイル | 概要 |
|---|---|---|
| A: S 式 | `a-sexpr.sigil` | すべてを括弧の入れ子で表す。意図・契約・効果も `(intent ...)` などの属性 |
| B: インデント + キーワード | `b-indent.sigil` | 固定順のキーワード行（`intent` / `params` / `requires` …）と字下げでブロックを表す |
| C: 波括弧 + 契約節 | `c-brace.sigil` | 一般的な C 系のシグネチャに契約節を付け、本体を `{}` で囲む |

## サンプル

| 例 | 内容 | 確認したい点 |
|---|---|---|
| [01-average](01-average/) | 数値列の平均値（純粋関数） | 意図・事前条件・事後条件・効果なしの書き方 |
| [02-read-port](02-read-port/) | 設定ファイルからポート番号を読む | 副作用の宣言、`Result` による失敗、篩型（値の範囲を型に含める） |

## 共通の約束（全候補）

- 関数は **意図（intent）・引数・戻り値・事前条件（requires）・事後条件（ensures）・効果（effects）・本体** を持つ。
- 効果は明示する。効果がない関数も「なし」と書き、省略と区別する（候補 C の 02 は事後条件を篩型に寄せたため `ensures` を省略。省略を許すかは未決）。
- 事後条件の中では戻り値を `result` で参照する。篩型の中では対象の値を `self` で参照する。
- 失敗しうる処理は `Result` で返し、`?`（候補 A では `try`）で早期に返す。

## 比較の観点（仮評価）

以下はサンプルを書いた時点での見立てで、計測による裏付けはまだありません。決定は ADR（`docs/decisions/0002-syntax-family.md`、未作成）で行います。
[ADR 0001](../docs/decisions/0001-vision-and-scope.md) により、今後は「仕様を人間に示しやすいか」と「所有権・借用を明示しやすいか」も比較の観点に加えます。

| 観点 | A: S 式 | B: インデント | C: 波括弧 |
|---|---|---|---|
| 正規化しやすさ（同じ意味の書き方が一通りか） | 高い。構文要素が少ない | 中。キーワード順を固定すれば高くできる | 中。演算子・`return` の有無などで揺れやすい |
| AI 生成時に崩れやすい箇所 | 閉じ括弧の数 | 字下げの深さ | 区切り記号（`;` `,`） |
| 人間の読みやすさ | 低め（括弧が多い） | 高い | 高い（既存言語に近い） |
| 意図・契約の位置づけ | 本体と同格の属性 | 本体と同格のキーワード行 | シグネチャへの付属物 |
| パーサの作りやすさ | 非常に容易 | 中（字下げ処理が必要） | 中 |
