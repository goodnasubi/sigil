# 信頼基盤レビュー強制の確認と P1 信頼基盤変更 PR 監査報告書（Issue #550）

## 1. 概要

本報告書は、Issue #550 の完了条件に基づき、G3 報告書（`docs/security/2026-11-16-g3-review-d9c1281e.md`）の項目 8「信頼基盤」で「未実施を含む」とされた課題の解消状況および調査結果を記録するものである。

具体的には以下の 2 点を実施・確認した:
1. **仕組みの確認と不足の是正**: ADR 0018 判断 1（T2/T3）が決めた「CODEOWNERS とブランチ保護で所有者のレビューを必須にする」仕組みについて、実在するファイル（原始操作の表・許可の一覧・信頼基盤の標準ライブラリ）を対象に設定されているかを確認し、不足を是正した。
2. **レビュー・承認記録の監査**: P1 期間に信頼基盤を変更した全 24 件の PR のうち、未確認だった残り 20 件のレビュー記録を確認し、#489 の所有者承認記録の有無を確定した。また、所有者承認の記録を欠く PR の一覧を特定し、所有者への遡及承認・容認依頼を整理した。

## 2. 信頼基盤レビュー強制の仕組みの確認と不足の是正（完了条件 1）

### 2.1 実在するファイルの確認と対応

ADR 0018 判断 1 の T2/T3 が対象として定めた構成要素について、リポジトリ内の実在状況を確認した:

| 対象要素 | 想定パス | 実在状況 | 対応内容 |
|---|---|---|---|
| 原始操作の表 | `src/stdlib.rs` | **実在する** | `RAW_OPS` 定義が存在。CODEOWNERS の対象として指定が必要 |
| 許可の一覧 | `trust-base.list` | **実在しなかった** | 本 PR でリポジトリのルートに空のテンプレート（説明コメント付き）として新規作成・配置 |
| 信頼基盤の標準ライブラリ | `src/stdlib/core_*.sigil`, `src/stdlib/os_*.sigil`, `src/stdlib/core_sigil.rs` | **実在する** | `trust base` を宣言するモジュール（計 15 ファイル）が存在。CODEOWNERS の対象として指定が必要（後述） |
| 上限の既定値の置き場所 | `src/limits.rs` | 実在しない | ADR 0020 / 0032 の予定パスとして保持 |

`trust-base.list` を実在するファイルとしてリポジトリに配置したことで、`src/project/trust_base.rs` による読み込み要件および CI（`scripts/trust-base-diff.sh`）による差分追跡の対象がファイルシステム上に揃った。

### 2.2 `.github/CODEOWNERS` の現状と所有者への変更依頼

- **現状**:
  - リポジトリの `.github/CODEOWNERS` には、存在しない `/src/limits.rs @goodnasubi` のみが記載されている。
  - 実在する原始操作の表（`src/stdlib.rs`）、許可の一覧（`trust-base.list`）、信頼基盤の標準ライブラリが指定されていない。
- **対象範囲の検討（`/src/stdlib/` 一括指定の回避）**:
  - 当初 `/src/stdlib/` 全体の指定を検討したが、これは範囲が広すぎる。
  - `src/stdlib/` 配下で `trust base` を宣言しているのは現在 15 ファイル（`core_bytes.sigil`, `core_list.sigil`, `core_path.sigil`, `core_string.sigil`, `core_sigil.rs`, `os_alloc.sigil`, `os_clock.sigil`, `os_console.sigil`, `os_env.sigil`, `os_fs.sigil`, `os_io.sigil`, `os_net.sigil`, `os_random.sigil`, `os_sched.sigil`, `os_thread.sigil`）のみである。`http.sigil`, `web.sigil`, `crypto.sigil`, `pg_scram.sigil` などの一般標準ライブラリは `trust none` であり、信頼基盤ではない。
  - ディレクトリ全体（`/src/stdlib/`）を CODEOWNERS に含めると、日常的な `std.http` や `std.pg` の修正（例: PR #655 など）でも毎回所有者承認が必須となり、AGENTS.md の「コードのみ（仕様に影響しない）は人間のレビュー不要」という運用原則や見張りによる自動マージが阻害される。
  - したがって、信頼基盤を宣言するモジュールを個別列挙する形式（`/src/stdlib/core_*.sigil`, `/src/stdlib/os_*.sigil`, `/src/stdlib/core_sigil.rs` など）が妥当である（実際の適用範囲は所有者の判断による）。
  - さらに、信頼基盤の検証・検出を担う強制機構自体（`src/project/trust_base.rs` および `scripts/trust-base-diff.sh`）についても、これらが改変されると信頼基盤の検査を迂回・無力化できてしまうため、CODEOWNERS の対象に含めるべきか所有者にて検討することが推奨される。
- **制約と依頼**:
  - AGENTS.md の規定（「`.github/CODEOWNERS` は人間のみ変更する」）に従い、エージェントは本ファイルを直接編集しない。
  - Issue #550 へのコメント等を通じて、所有者（池田さん）へ以下の設定を提案・依頼する（実際の指定範囲は所有者判断）:
    ```text

    /src/stdlib.rs @goodnasubi

    # 許可の一覧（ADR 0018 判断 1 の T2）
    /trust-base.list @goodnasubi

    # 信頼基盤の標準ライブラリ（trust base を宣言するモジュール群）
    /src/stdlib/core_*.sigil @goodnasubi
    /src/stdlib/os_*.sigil @goodnasubi
    /src/stdlib/core_sigil.rs @goodnasubi

    # 信頼基盤の強制・検査機構（検討対象）
    /src/project/trust_base.rs @goodnasubi
    /scripts/trust-base-diff.sh @goodnasubi

    # 上限の既定値の置き場所（ADR 0020 の決定 4。将来の配置用）
    /src/limits.rs @goodnasubi
    ```

### 2.3 ブランチ保護（Branch Protection）の現状と推奨設定

- **現状**:
  - GitHub REST API（`repos/goodnasubi/sigil/branches/main/protection`）の確認結果、`HTTP 404: Branch not protected` となっており、`main` ブランチに保護設定が存在しない。
  - GitHub の仕様上、CODEOWNERS によるレビュー必須化を強制するためには、ブランチ保護ルールで「Require review from Code Owners」を有効にする必要がある。
- **所有者の判断を仰ぐ推奨設定内容**:
  1. **Require a pull request before merging**: 有効
  2. **Require review from Code Owners**: 有効（所有者の承認なしでのマージをブロック）
  3. **Required approving reviews**: 1
  4. **Require status checks to pass before merging**: 有効
     - **注意**: 当初案に記載のあった `fuzz` は誤りである。`.github/workflows/fuzz.yml` は `schedule` と `workflow_dispatch` 専用であり PR では実行されないため、必須ステータスチェックに指定するとすべての PR がマージ不能になる。
     - 必須に指定すべき対象は、**PR で確実に実行されるジョブ**である。具体的には `.github/workflows/ci.yml` の集約ジョブである `gate`（または `test`）が該当する（なお `postgres.yml` の `postgres` ジョブは変更に応じて走る）。
     - GitHub のブランチ保護設定画面には、直近で実行されたステータスチェックの候補一覧が表示されるため、所有者が実際の設定画面上で PR 時に必ず走るジョブ名（`gate` 等）を確認・選択する運用とする。
  5. **Do not allow bypassing the above settings**: 有効（管理者・Bot の迂回防止）
