# 0069: サーバーレス関数実行環境（sigil-summon-functions）

- **状態**: 提案（typesafe-ai 正式判定済み。末尾に記録）。実装の着手・完了、外部公開の承認を意味しない
- **日付**: 2026-11-28（JST）
- **対象**: [Issue #785](https://github.com/goodnasubi/sigil/issues/785)、レーン E
- **仕様基準**: sigil の `main`、`fd1cc86`
- **範囲**: ADR の起草のみ。実装リポジトリは [goodnasubi/sigil-summon-functions](https://github.com/goodnasubi/sigil-summon-functions)（[ADR 0044](0044-p4-scope.md) 決定 4 のパターン）。コンパイラ・標準ライブラリのコード変更は含めない。

## 背景

`sigil-summon-functions` は、関数（Sigil プログラム）を登録しておき、呼び出しのたびに隔離された環境で実行して結果を返す部品である。常駐サービスではなく、短い処理を必要なときだけ動かす形を提供する。モチーフは召喚（Summon）で、UI を持たないため製品名は定めない。

前提となる既決事項は次のとおり。

| 部品 | 本 ADR での使い方 |
|---|---|
| sigil-container（[ADR 0053](0053-p5-container-management.md)、イメージは [ADR 0035](0035-p1-container-image-tool.md)） | 実行基盤。コンテナ仕様、隔離プロファイル、資源上限、ネットワークの既定拒否をそのまま使う |
| sigix（[ADR 0056](0056-sigix-web-server.md)） | HTTP 呼び出しの入口。プロキシ先として Summon が HTTP を受ける |
| sigil-herald-queue（[ADR 0066](0066-herald-queue.md)） | キューイベントの入口と非同期実行の受け皿 |
| sigil-argus-observe（[ADR 0067](0067-argus-observe.md)） | 実行ログとメトリクスの送り先（決定 2・3 の契約） |
| sigil-rune-auth（[ADR 0060](0060-rune-auth.md)、検証は [ADR 0037](0037-p1-authentication.md)） | 入口ごとの認証 |
| sigil-stash-kv（[ADR 0059](0059-kv-store.md)）／sigil-db（[ADR 0045](0045-p4-1-database-core.md)） | 管理情報と、関数が使う状態の保存先 |

## 本 ADR で決めないこと

- 実装そのもの（本 ADR のマージ後の各段で進める）。
- 利用側・連携先（sigix、container、herald-queue、argus-observe、rune-auth）の内部仕様。必要な追補は名前と要請だけを出し、各リポジトリの Issue で扱う。
- 課金の仕組み（初版の範囲外。登録と呼び出しの管理の枠組みは決定 1・2 で触れる）。
- マイクロ VM バックエンド、複数ノード、関数のソースからのビルド、外部公開の承認（[ADR 0020](0020-p1-security-addendum.md) の G3 で所有者が判断する）。

## 決定 1 — 持ち方とコールドスタート

**sigil-container の上の層として作る（案 A）。** Summon は「登録・呼び出しの受付・並行数の管理・結果の整形」を持つ制御層で、隔離と資源制限は sigil-container のコンテナ仕様と隔離プロファイル（ADR 0053 決定 1・3）にそのまま任せる。独立した実行部品（案 B）は、隔離・資源制限・後始末をもう一組作ることになり、ADR 0053 の既定拒否の検証を二重に持つので採らない。バックエンドは ADR 0053 の OCI ランタイム（runc／crun）に限る。信頼できないコードの実行に必要なマイクロ VM は、container 側に後続のバックエンドが入った時点で、同じコンテナ仕様のまま差し替える。

**コールドスタート。** 呼び出しごとに新しい実行環境を作り、終了後に破棄する。使い終えた環境を次の呼び出しで再利用しない（待機環境のウォーム再利用は、関数の一時領域・メモリに前の呼び出しの入力が残り、隔離と「関数は状態を持たない」前提（決定 4）を弱めるので採らない）。起動時間は、イメージの展開済みキャッシュ（digest で参照する層）で短くする。計測した起動時間が目標に届かない場合に限り、**未使用の事前作成環境**（まだ入力を受けていないもの）を有限個だけ待機させる案を、計測を添えて別の ADR で決める。初版の目標値は置かず、起動時間を計測して記録する（決定 7 段 5）。

**登録の単位。** 関数は名前と版を持つ。版は不変で、「有効な版」を指す参照だけを切り替える（登録・有効化・切り戻しは管理者認証の管理 API で行う）。実行中の呼び出しは開始時の版で最後まで動く。登録できる関数は有限（初版は 128 件まで）とする。

## 決定 2 — 関数の登録と呼び出しの契約

**登録。** 関数は、Sigil プログラムを含む OCI イメージを **内容の SHA-256 digest で固定して**登録する（ADR 0053 決定 1。タグだけの参照は拒否）。ソースを受け取って Summon がビルドすることはしない。イメージは ADR 0035 の出力を最初の入力とし、すでに container 側のストアにある digest だけを登録できる。登録は版付きの宣言 JSON（未知の項目は拒否し、一部だけの適用はしない）で、次を持つ。

- 関数名（英小文字・数字・ハイフン）、イメージの digest、入口の宣言（HTTP・キュー・定時のうち使うもの）、入口ごとの認証設定
- 資源（実行時間・メモリ・pids・一時領域・ログ量）と、許可する外向きの通信先。**運用者の最大値を超える値は拒否する**（決定 3）
- 再試行の方針（非同期のみ、決定 6）
- 秘密は**ファイルの参照名**だけを持つ。値を宣言・状態・ログ・エラーに出さない

**呼び出しの受け渡し。** 関数には、標準入力で版付きの呼び出し封筒（UTF-8 の JSON。呼び出し ID、入口の種類、入力のメディア型、本文）を渡す。本文は同期呼び出しで 1 MiB まで（[ADR 0068](0068-aegis-waf.md) の本文上限と同じ）、非同期（キュー経由）では **512 KiB まで**とし、バイト列は Base64 で入れる。非同期の封筒は Base64 で 4/3 倍（512 KiB で 699,052 バイト）とメタデータを足しても herald-queue のジョブ本文の上限（既定 1,048,576 バイト、ADR 0066 決定 4.2）に収まる。関数は標準出力に結果封筒（状態コード、許可したヘッダー、本文）を一度だけ書いて終了する。終了コード 0 以外、結果封筒の不正・上限超過、時間切れは関数の失敗とする。ログは決定 5 の経路を使う。

**入口と認証。**

| 入口 | 受け方 | 認証 | 結果 |
|---|---|---|---|
| HTTP | sigix のプロキシ先として受ける。`POST /functions/<名前>` | 既定は必須。ADR 0037 のアクセストークンを検証し、関数ごとの audience を要求する。`none` は宣言と運用者の許可がある関数だけ（Webhook 等） | 結果封筒をそのまま HTTP 応答にする。同期の上限は決定 3 |
| キュー | herald-queue のワーカーとして `summon.<関数名>` を取得（決定 6） | 呼び出しごとの認証はない。キューの信頼境界（ADR 0066 決定 4.2、ループバックまたは隔離網）が境界になる | 結果は返さず、呼び出し記録に状態だけを残す |
| 定時 | 宣言の cron 式（UTC、最短 1 分）で内部から起動 | 内部起動で認証なし | 同上。取りこぼした時刻の補填はしない（欠落は計測する） |
| 管理 | 登録・有効化・一覧・削除・呼び出し記録の参照 | **常に必須**（管理用の audience。`none` を許さない） | 管理 API の応答 |

HTTP 呼び出しの失敗は定型で返す。未登録 404、認証 401／403、本文超過 413、並行数の超過 429（`Retry-After` を付ける）、ノードの容量・内部資源の超過 503、関数の失敗 502、実行時間の超過 504。HTTP の呼び出しは Summon が自動で再試行しない（副作用を二重にしない）。キューと定時は少なくとも 1 回の実行（ADR 0066 決定 2.1）で、関数は冪等でなければならない。この前提を登録の説明と利用者向け文書に明記する。

## 決定 3 — 隔離と資源制限

呼び出しごとに新しいコンテナを、ADR 0053 決定 3 の既定（非 root、capability すべて削除、seccomp 許可リスト、rootfs 読み取り専用、書き込めるのは宣言した一時領域だけ、秘密はファイルで渡す）で実行する。ネットワークは既定で接続なしとし、関数が宣言した宛先・ポートだけを許す（ADR 0053 決定 4）。`privileged` と host の namespace 共有は登録で拒否する。

資源の上限は必須で、運用者の最大値（Summon の起動設定）が関数の宣言の上限になる。関数は最大値を下げることだけでき、上げられない。初版の受け入れ値は次のとおりで、実測に基づいて決定 7 段 5 で見直す。

| 項目 | 既定 | 最大 |
|---|---|---|
| 実行時間（実時間） | 10 秒 | 同期 HTTP は 30 秒、非同期は 300 秒 |
| メモリ | 128 MiB | 512 MiB |
| pids | 64 | 256 |
| 一時領域 | 64 MiB | 256 MiB |
| 入力の本文 | 1 MiB（非同期は 512 KiB） | 同左 |
| 結果の本文 | 1 MiB | 1 MiB |
| ログ（1 呼び出し） | 64 KiB | 256 KiB |

並行実行は**ノード全体**と**関数ごと**の上限を持つ。超過したときの待ち行列は持たず（無制限の滞留を避ける）、同期 HTTP は関数ごとの超過を 429、ノードの超過を 503 で即座に断る。非同期は取得を止めるか NACK（決定 6）で返し、取得済みジョブを抱え込まない。初版の既定はノード 16・関数ごと 4 とし、ノードの CPU とメモリから起動時に検証して、超える設定は起動を拒否する。実行環境の数の上限が、メモリの最悪値（同時数 × メモリ上限 ＋ 一時領域上限 ＋ ログ上限）を決める。

**限界。** コンテナはカーネルを共有する（ADR 0053 決定 3）。初版は、**登録する者を認証済みの運用者に限り**、関数のコードを運用者が信頼できる範囲で使う。第三者が任意の関数を登録する多テナントの実行は、マイクロ VM バックエンドが入るまで対象外とし、利用者向け文書に明記する。

## 決定 4 — 状態の扱い

関数自体は状態を持たない。呼び出しごとに新しい環境で動き、一時領域と標準出力は破棄される。永続ボリュームは使わない（ADR 0053 決定 7 でボリュームの外部ストレージは未対応）。保存は、関数が宣言した宛先（内部網の sigil-db または sigil-stash-kv）へ、ファイルで渡した資格情報を使って行う。ノード内の共有メモリや前回の呼び出しの結果に依存する関数は、この契約を満たさない。KV は単一キーの設定と期限だけを提供する（ADR 0059）ので、競合更新が要る関数は sigil-db のトランザクションを使う。

Summon 自身の管理情報（登録と版、有効版、定時の最終起動、呼び出し記録）は sigil-db に置き、整合が要る更新は単一のトランザクションで行う。呼び出し記録は ID・関数・版・入口・結果・開始時刻・所要時間・終了理由だけで、本文・ヘッダー・秘密を持たず、保持期間は有限にする（初版は 7 日）。

## 決定 5 — 記録の送り先

[ADR 0067](0067-argus-observe.md) 決定 2・3 に従うエミッターを使い、NDJSON のログとメトリクスを Argus の収集口へ出す。要求処理は送信を待たず、有界のバッファの満杯時の欠落は集計して復旧時に報告する（ADR 0068 決定 5 と同じ）。記録の失敗は呼び出しの結果を変えない。

- **Summon のログ**: `component` は `sigil-summon-functions`。開始、終了、時間切れ、OOM、拒否、登録・有効化を `fields` に関数名・版・入口・結果・理由コード・呼び出し ID で記録する。
- **関数のログ**: 関数の標準エラー（またはこれに相当する別の出力口）の各行を、Summon が `msg` として包み、`fields.stream` に `app` を付けて出す。関数が出す JSON の `component`・`level` などを**信用して転記しない**（他部品への成りすましを避ける）。行は 4 KiB、1 呼び出しで 64 KiB（決定 3 の上限）に切り、超過分は数える。標準エラーが Sigil で使えない間の出力口は実装段 2 で確認し、標準ライブラリ側の不足は sigil リポジトリの Issue として報告する。
- **メトリクス**: `summon_invocations_total`（入口・結果）、`summon_invocation_seconds`（ヒストグラム）、`summon_cold_start_seconds`（ヒストグラム）、`summon_concurrency`（ゲージ）、`summon_rejected_total`（理由）、`summon_telemetry_dropped_total`。ラベルは有限の集合に限る。関数名は登録数の上限（128）があるため `function` ラベルに使えるが、呼び出し ID・IP・URL・ユーザー ID は使わない。
- 本文、ヘッダー値、資格情報、秘密のファイル名と値、生の IP を記録しない。`trace_id` は信頼できる入口（キューのジョブ等）から受けたものだけを付け、呼び出し元の自称値を使わない。

## 決定 6 — 非同期実行とキューの分担

Summon は**自前のキューを持たない**。非同期実行は herald-queue だけを通す。

- **投入側**: HTTP の非同期モード（宣言した関数への `POST /functions/<名前>/async`）は、呼び出し封筒（本文 512 KiB まで、決定 2）を `summon.<関数名>` へ `ENQUEUE` して `202` と呼び出し ID を返す。他の部品（raven-mail 等）が同じキューへ直接投入することも、同じ入口（キューイベント）として扱う。
- **実行側**: Summon が `summon.<関数名>` のワーカーになり、決定 3 の並行上限の範囲で `DEQUEUE` する。`lease_seconds` は関数の実行時間上限に余裕を足した値にし、ジョブごとの隔離実行が終わったら `ACK` する。ADR 0066 のリース操作に更新操作がないため、実行時間の上限は herald-queue のリース上限に収まる値に制限する（不足があれば herald-queue 側の追補として報告）。
- **失敗の分類**: 関数の失敗（終了コード・時間切れ・結果の不正）は、宣言の再試行の方針（最大回数は herald-queue の `max_retries` 以内）に従い `NACK`（バックオフ付き）し、最大回数に達したものは herald-queue の DLQ に移る。Summon 側の一時的な不能（並行上限・イメージの未展開など）は取得を控えるか `NACK` し、関数の失敗の回数に数えない扱いは herald-queue の契約で可能な範囲に限る（不可なら同じ回数に数える）。
- **境界**: 永続化・遅延・再試行・DLQ・順序は herald-queue が持ち、Summon は実行・時間制限・隔離・呼び出し記録を持つ。重い処理を非同期へ回すかの判断は呼び出し元（関数の登録者）が行い、Summon は自動で同期呼び出しを非同期へ切り替えない。非同期の結果は返さず、必要なら関数が決定 4 の保存先に書く。

## 決定 7 — 実装段の分割と完了条件

ADR のマージ後、独立リポジトリで次の順に進める。各段で使う Sigil と依存は完全なコミット SHA に固定する。段 2 は sigil-container の P5-2（ランタイム接続）に依存し、未到達なら段 1 を先行して、待ち状態を段の記録に残す。

| 段 | 成果物と完了条件 |
|---|---|
| 1. 登録と呼び出しの核 | 登録宣言の型と検証（未知項目・digest 以外の参照・資源の最大値超過・特権の拒否）、版と有効版の切り替え、呼び出し・結果封筒の符号化と上限、cron 式の解釈と次回起動の計算、並行数の受付判定の状態機械。時計を差し替えた試験、同じ入力で同じ結果、不正入力のファジングを評価器とネイティブで確認する |
| 2. 実行接続 | container の仕様生成と実行、標準入出力の契約、実時間・メモリ・pids・一時領域・ログ量の超過の強制、後始末。実ランタイムで ADR 0035 のイメージが動き、否定試験（特権昇格・書き込み禁止・ネットワークなし・OOM・時間切れ・プロセスの強制終了後の残骸）が通ることを確認する。起動時間を計測して記録する |
| 3. 入口 | HTTP（sigix のプロキシ先、ADR 0037 のトークン検証、決定 2 の状態コード）、herald-queue のワーカー（取得・`ACK`／`NACK`・DLQ への移送の確認）、定時起動、管理 API。認証・認可の否定試験、`at-least-once` の重複の許容、定時の取りこぼしの記録を確認する |
| 4. 観測 | Argus のログ・メトリクス契約への適合、関数のログの包み方と成りすまし防止、秘密・本文・生の IP の除外、バッファ満杯時に呼び出しの結果が変わらないこと、ラベルの有限性を確認する |
| 5. 配備条件と計測 | 代表的な関数と上限近傍の入力で、決定 3 の既定値とメモリ上限の最悪値、起動時間（p50・p95）、並行数ごとの所要時間を計測して記録する（機材・並行数・データ量・版・測定区間を併記）。誤検知にあたる運用手順（関数の切り戻し、停止、DLQ の再投入）と既知の制約を手順化し、[ADR 0020](0020-p1-security-addendum.md) の実装完了記録 G2 を作成する |

## 影響

関数を実行する制御層が一つ増え、配備者は登録（digest と上限）、運用者の最大値、並行上限、秘密のファイル、キュー名の対応を管理する。初版は単一ノード・コンテナ隔離で、信頼できない第三者のコードは対象外になる。実行は少なくとも 1 回で、関数は冪等でなければならない。

## 脅威と対策（G1）

| 対象 | 対策 |
|---|---|
| 入力 | 呼び出し封筒と結果封筒の上限・型の検証、登録宣言の全体検証（決定 2）。digest 固定でイメージの差し替えを防ぐ |
| 認証 | HTTP は既定で必須、管理は常に必須、キューは信頼境界で保護する（決定 2）。`none` は宣言と運用者の許可を要する |
| 秘密 | 値は宣言・状態・ログに出さず、ファイルで関数に渡す。ログの成りすましと秘密の混入を防ぐ（決定 2・5） |
| 資源 | 実行時間・メモリ・pids・一時領域・ログ・並行数・登録数・呼び出し記録を有限にし、待ち行列を持たない（決定 3・4） |
| 隔離 | ADR 0053 の既定拒否と、使い捨ての環境。カーネル共有の限界は多テナントを対象外にして明記する（決定 1・3） |

## 人間の判断が要る点

- 正式判定は実施済み（下記。5 問すべてで起草者の案が選ばれ、決定 1〜7 の改訂は不要）。判断がつかず所有者への提示が必要な問いはない。
- 本 ADR は `src/limits.rs`・CODEOWNERS・CI の変更を含まず、権限も与えない。

## 正式判定の記録

起草セッションには判定 API の認証キー `TYPESAFE_API_KEY` が無く、起草時点では判定を実施できなかった（ADR 0044・0060 と同じ）。そのため問いと評価軸を先に記録し、見張りが 2026-11-28（JST）に typesafe-ai の `jev-1.13.0` で判定した（[PR #786 のコメント](https://github.com/goodnasubi/sigil/pull/786#issuecomment-7234070425)）。**5 問すべてで起草者の案が選ばれ、いずれも接戦ではなかった。決定の改訂は不要。**

評価軸（`state` の冒頭）: ADR 0001・0005、ADR 0020 の最小権限・資源上限・段階的な公開、ADR 0044 決定 4 のリポジトリ分離、ADR 0053 の既定拒否、所有者の明示方針（小さいサービス向け、段階的に進める）。判定は typesafe-ai のみで行った。

| 問い | 採用案（確率） | 比較案 | confidence |
|---|---|---|---|
| 持ち方（決定 1） | `layer_on_container`: container の上の制御層（0.99） | `standalone_runtime`: 独立した実行部品 | 0.98 |
| 起動（決定 1） | `fresh_each`: 呼び出しごとに新規・使い捨て（1.00） | `warm_reuse`: 使い終えた環境を再利用 | 1.00 |
| 非同期（決定 6） | `queue_only`: herald-queue だけを通す（1.00） | `own_queue`: Summon 内部のキュー | 1.00 |
| 登録（決定 2） | `digest_image`: digest 固定の OCI イメージ（0.99） | `source_upload`: ソースを受け取りビルド | 0.98 |
| 対象範囲（決定 3） | `trusted_operators`: 認証済み運用者の登録に限る（0.99） | `multi_tenant`: 第三者の登録も受ける | 0.98 |

判定の入出力は、見張りが `hidden_files/` に保管している（`typesafe-adr0069-q1-holding-20261128` ほか `q2-startup`・`q3-async`・`q4-registration`・`q5-scope` の入力と出力。リポジトリには含めない。ADR 0044 と同じ運用）。
