# 0068: Web アプリケーション・ファイアウォール（sigil-aegis-waf）

- **状態**: 提案
- **日付**: 2026-11-28（JST）
- **対象**: [Issue #775](https://github.com/goodnasubi/sigil/issues/775)、レーン E

## 背景

`sigil-aegis-waf` は、HTTP リクエストの検査、既知の攻撃種別（SQL インジェクション、XSS など）の検知・遮断、レート制限、送信元 IP の評価を担当する。計画下書き §13 の論点は Issue #775 の記載に基づく。仕様は本リポジトリで管理し、実装は [goodnasubi/sigil-aegis-waf](https://github.com/goodnasubi/sigil-aegis-waf) に置く。[ADR 0044](0044-p4-scope.md) 決定 4 の分離に従う。

## 決定 1 — 持ち方と配置

WAF は Sigil 製の独立した HTTP/1.1 の中継部品とし、`shield-tls → aegis-waf → sigix` の順に配置する。メソッド、パス、ヘッダー、本文を検査するには TLS 終端後の平文が必要であり、sigix の処理や副作用が始まる前に転送の可否を確定する。TLS 終端への組み込みは終端側の HTTP 解釈と責任を増やす。sigix 内への組み込みは検査ポリシーと配信を同時に更新する必要が生じる。

平文区間は専用リスナーと信頼済み接続元に限定する。[ADR 0063](0063-shield-tls.md) 決定 3・5 の境界に従い、接続先は既定で同一ホストのループバック、別ホストの場合は隔離したネットワークに限る。WAF はその境界で接続の先頭に一度だけ PROXY v2 を受け取り、送信元と宛先および `AUTHORITY`・`SSL` を検証し、sigix への対応する接続に同じ契約で伝える。送信元の異なるクライアントで上流接続を共有しない。信頼境界を満たさない接続、ヘッダーの欠落・不正は HTTP として扱う前に閉じる。SNI を示す `AUTHORITY` と正規化した `Host` の不一致は 421 とする。ADR 0056 は PROXY v2 の受信を規定していない。連携段では ADR 0063 決定 5.2 に沿って受信可能な sigix の版を確認し、必要な追補は別の ADR で扱う。

マネージドな基本ルールは WAF のリリースと一緒に配布する版付きの宣言データとする。利用者定義ルールにも同じ形式を使う（決定 3）。配置と評価契約を独立させ、ポリシーの内容と変更を人間がレビューできるようにする。

## 決定 2 — 検査と遮断の契約

メソッド、パスとクエリ、ヘッダー、本文を検査する。HTTP の構文とフレーミングは [ADR 0032](0032-p1-http-server.md) と sigix が受け付ける HTTP/1.1 の契約に合わせ、曖昧な境界を不正として拒否する。経路選択・評価・転送が同じ解釈になるよう、要求を一度パースし、検証済みの要求から転送を組み立てる。本文検査が必要な経路は、対応するメディア型・内容符号化をポリシーで宣言し、未対応の形式は 415 とする。本文検査を要求しない経路も HTTP の構文とサイズ上限を適用し、検査範囲は経路の設定に示す。上流への送信は判定確定後に行う。

| 一致したルールの扱い | WAF の動作 |
|---|---|
| 遮断 | 定型の 403 を返し、転送を開始しない。レート制限超過は決定 4 の 429 とする |
| 記録のみ | 検知を記録し、他の必須検査とルールの評価を続ける。すべて通過した場合に転送する |
| 追加確認 | 確認が得られるまで転送しない。初版は外部連携を後続とし、固定の 403 を返して内部に専用の理由コードを記録する |

ポリシーは遮断、追加確認、記録のみの順で強い結果を採り、ルール評価は同一の版、検査入力、例外の評価時刻で同じ結果を返す。誤検知の調整には、ルール ID と固定の経路 ID を指定した、理由と失効日時付きの例外を使う。例外により遮断を記録のみに降格できる。構文・信頼境界・資源上限には作用させない。新規の基本ルール版は記録のみで確認し、配備者が内容を確認して遮断モードへ切り替えられるようにする。これにより全面停止を避けながら、影響を限定して調整できる。

## 決定 3 — ルールの表現形式

UTF-8 の版付き JSON を `std.json` で読み、評価器が型付きで扱う。ルールは一意な ID、対象（経路・検査フィールド）、決められた演算子とオペランド、作用で構成する。初版の演算子は完全一致、前方一致、リテラル部分一致、有限集合への所属、処理量を制限できるものとする。任意の Sigil コード、外部呼び出し、ループ、正規表現の実行は範囲外とする。Sigil でルールを書ける案は表現力がある一方、利用者入力としての権限・停止性・実行量の契約を広げる。

マネージドセットは配備時に版を固定し、自動取得・自動有効化を行わない。利用者のルールは専用の ID 名前空間に追加し、マネージドルールの調整には決定 2 の明示的な例外を使う。版・未知項目・型・重複 ID・参照・件数・値サイズを全体検証してからポリシーを原子的に差し替える。起動時に有効な版がなければ待ち受けを開始せず、再読み込みに失敗した場合は直前の有効版を保持する。実行前にポリシー全体と資源上限を確定できることを優先する。

## 決定 4 — レート制限と送信元 IP の評価

信頼済みの PROXY v2 の送信元だけを IP 評価に使う。クライアント由来の `Forwarded`・`X-Forwarded-*` を信頼せず、後段に渡す際は除去する。IPv4 と IPv6 は型付きの正規形に統一し、IPv4 射影 IPv6 は同じ IPv4 として数える。保護対象の経路は設定済みの有限な経路 ID に写し、未分類要求は共通の固定 ID に数える。要求の生パスをキーにしない。ヘッダーの検証と経路の確定後、本文の検査前に制限を適用する。

ノード全体と（送信元 IP、経路 ID）の両方にトークンバケットを設け、単調時計で補充する。持続レートとバースト上限を有限の設定値とし、測定した上流の処理能力と経路の費用に合わせる。どちらかの上限に達した場合は 429 とし、算出できる場合は `Retry-After` を返す。並行した要求の判定と消費はノード内で原子的に行い、空いた枠を再利用できるよう実質的に満杯へ戻ったバケットを期限付きで回収する。テーブルが満杯で新しいキーを追跡できないときは、上限中の既存キーを消さず、新規キーの要求を 503 とする。

IP 評価は運用者が配備した版付きの有限な CIDR 表（効果、理由、失効日時を持つ）を検証してメモリ上に保持する。初版の効果は遮断または記録とし、有効期限内の項目で最長一致を使い、同じ範囲の矛盾する設定を拒否する。IP 評価で他の検査を免除しない。IP 単独では利用者を特定できず、共有 IP の利用者に制限が及ぶので、経路ごとに実測を踏まえて限度を調整する。

[ADR 0059](0059-kv-store.md) 決定 3 の `sigil-stash-kv` は値と期限の原子的な設定を提供する。比較交換や原子的な加算を提供しないため、`GET` と `PUT` を組み合わせた制限では並行更新が失われる。カウンター・IP 評価のいずれにも初版の同期経路から KV にアクセスしない。ノード再起動でカウンターは初期化され、複数ノードの限度は合算される。共有制限は原子的更新・期限・障害時の扱いを決める別の契約を要する。

## 決定 5 — 記録の送り先

[sigil-argus-observe の ADR 0067](0067-argus-observe.md) 決定 2・3 に従うエミッターを使う。検知、遮断、追加確認、上限超過とポリシー更新は UTF-8 の NDJSON とし、`ts`（UTC、末尾 `Z`）、`component`（`sigil-aegis-waf`）、`level`、定型の `msg` を含める。1 行の上限は 65,536 バイトとする。`fields` に結果、理由コード、ルール ID、経路 ID、ポリシー版を記録し、信頼できる追跡 ID があれば `trace_id` を付ける。本文、URL やクエリの生値、ヘッダー値、資格情報、生の IP を記録しない。

`waf_requests_total`、`waf_detections_total`、`waf_decision_seconds` のヒストグラム、`waf_telemetry_dropped_total` を出す。メトリクスは決定 3 の `ts`、`component`、`name`、`type`、`value`、`labels` の契約に従い、正規化後の `component` ラベルを含め最大 10 個とする。結果と理由など有限集合の値だけをラベルにし、IP、URL、追跡 ID、ルール ID を使わない。

決定済みのイベントを有界バッファに渡し、別の送信処理から Argus の既存の収集口へ送る。要求処理は送信を待たない。満杯時の欠落は集計して、出力復旧時に報告する。記録の送信成否は要求の判定を変えない。

## 決定 6 — 検査の性能目標と上限

初版の受け入れ値は、リクエスト行 8 KiB、ヘッダー全体 16 KiB・100 件、受け付ける本文 1 MiB、検査処理の絶対期限 10 ms とする。上流側の上限が小さい場合は小さい方を採用する。設定のルール数・入力長・評価処理量と並行処理数・バッファ総量も有限にし、超過した設定は起動または再読み込み時に拒否する。検査期限には正規化と評価を含め、単調時計で検査の開始時・作業単位の境界・転送前に期限を確かめる。各作業単位の処理量も制限し、実行中の非協調処理を 10 ms で強制中断する保証は置かない。要求の受信と上流の待ち時間は別々の有限な期限で制限する。実測の目標は、同じ固定版・計測資料を用いた 1 KiB 以下の代表的な要求群に対し、既定ルールセットと確認対象の並行数で検査の追加時間 p95 2 ms 以下とする。計測機材、並行数、データ量、ルール版、測定区間を実装段の結果とともに記録する。

サイズ超過はリクエスト行 414、ヘッダー 431、本文 413 とし、受信期限超過は応答可能なら 408、検査期限または内部資源上限の超過は 503 とする。あいまいなフレーミングは 400 とする。いずれも未検査の要求を上流へ流さず、必要に応じて接続を閉じる。記録のみの設定でも同じ上限を強制する。大容量アップロードは明示的な適用範囲として別途判断する。

## 決定 7 — 実装段と完了条件

ADR のマージ後、独立リポジトリで以下の順に進める。各段で使う Sigil と関連依存は完全なコミット SHA に固定する。

| 段 | 成果物と完了条件 |
|---|---|
| 1. ポリシーと検査の核 | 型付き入力・結果、宣言スキーマ、版付き基本ルール、例外と差し替え。同じ入力・版での結果の一致、作用の優先順、期限切れ例外、不正設定時の有効版保持を確認する |
| 2. HTTP と配置境界 | shield-tls → WAF → sigix のループバック統合。PROXY v2 の受け渡し、送信元・SNI の継承、構文とサイズの境界、判定確定前に上流へ送信しないことを確認する。sigix 側の契約の不足は別リポジトリの対応として記録する |
| 3. レート制限・IP と観測 | 時計を差し替えた補充・失効の単体試験、並行更新と容量上限の確認、Argus の受け入れ形式・ラベル・機密値除外・バッファ満杯時の判定の独立性の確認を終える |
| 4. 配備条件と計測 | 代表的な要求と上限近傍の通常の入力で決定 6 を計測し、既定値とメモリ上限を記録する。誤検知対応、ポリシーの切り戻し、既知の制約を手順化し、[ADR 0020](0020-p1-security-addendum.md) の実装完了記録 G2 を作成する |

## 影響

平文を扱うプロセスが一つ増え、配備者は専用の信頼境界、ポリシー版、上限、誤検知例外を管理する。上限による拒否とノード単位の制限は初版の運用契約となる。攻撃種別ごとのルールの中身は実装段で決める。製品名、連携先の内部仕様、外部公開の承認は本 ADR の対象外とする。

## 脅威と対策

| 対象 | 対策 |
|---|---|
| 入力 | HTTP の境界と解釈を検証し、確定した要求だけを転送する（決定 2・6） |
| 信頼境界 | 専用リスナーから受けた PROXY v2 の情報を使い、要求由来の転送ヘッダーは除去する（決定 1・4） |
| 秘密 | 平文区間を隔離し、本文・資格情報・生の IP を観測データに含めない（決定 1・5） |
| 資源 | 要求と評価に時間・サイズ・並行数の上限を設け、状態表と観測バッファも有界にする（決定 4–6） |
