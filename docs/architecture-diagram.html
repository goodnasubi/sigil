Sigil リポジトリ構成図

プログラミング言語 Sigil と、その上で動くサーバー部品の一族、全25リポジトリの構成図です。汎用OS（製品名 Machi）の sigil-polis-os を追加しました。各部品を選ぶと、下に詳しい説明が表示されます。

凡例（状態）

  • 実装あり
  • 開発中・着手したところ
  • 計画のみ（枠線だけの部品）
  • 中心の部品（sigix）
LAYER 1

土台：言語と実行基盤

Sigil でものを作るための土台になる6リポジトリです。今回、汎用OS（製品名 Machi）の sigil-polis-os を追加しました。

LAYER 2

言語側の前提（進行中）

バックエンド部品を作る前提として、言語（sigil）側で進めている2つの追加です。

LAYER 3

バックエンド部品：リクエストの流れ

外部からのリクエストが、入口の部品を順に通って中心の sigix に届くまでの流れです。この層の9件はすべて「計画のみ」（リポジトリ作成済み・実装はこれから）です。

LAYER 4

横断する役割

特定の経路ではなく、全部品と横断的につながる役割です（点線の枠で示しています）。今回、自律運用 sigil-vigil-ops の判断を担う自前 LLM 部品 sigil-anima-llm を追加しました。

セキュリティ・信頼系（3件）

LAYER 5

アプリケーション層

インフラ層の上に乗る、部品群を使う側のアプリケーションです。動画配信に続いて、SNS が2件目として加わりました。どちらも部品群の実証（ドッグフーディング）を兼ね、動画配信は将来シジの動画の置き場にもなりえます。

今回の範囲に絞るもの 動画の受け入れ、メタデータとカタログ管理、変換パイプラインの段取り、HLS 等の適応ビットレート配信の窓口、再生の仕組みまで。
  • 後段に回す：コメント・推薦・収益化・ライブ配信
  • 名前の由来：lantern ＝ 幻灯機（マジックランタン）
今回の範囲に絞るもの 投稿、フォロー関係、タイムライン／フィード、反応、通知まで。コメントは初期範囲に含めます。
  • 後段に回す：DM・検索・トレンド・収益化
  • 名前の由来：agora ＝ 古代ギリシャの広場、post ＝ 投稿

lantern-stream のつながり：変換の実行は sigil-herald-queue → sigil-summon-functions／sigil-container、保存と配信は sigix の静的配信、メタデータは sigil-db、認証は sigil-rune-auth が担います。

agora-post のつながり：認証は sigil-rune-auth、保存は sigil-db、通知の配送は sigil-herald-queue → sigil-raven-mail、メディアは sigix の静的配信が担います。

部品の説明

sigix

計画のみ

作る順番の案

sigix→ 監視・ログの形式の約束→ KV (sigil-stash-kv)→ 認証 (sigil-rune-auth)→ TLS 終端 (sigil-shield-tls)→ キュー (sigil-herald-queue)→ 監視の実装 (sigil-argus-observe)→ DNS (sigil-atlas-dns)→ メール (sigil-raven-mail)→ オーケストレーション (sigil-orchestra)→ サーバーレス (sigil-summon-functions)→ 動画配信 (sigil-lantern-stream)→ SNS (sigil-agora-post)

数について

バックエンド部品は sigix を入れて17件（第3層に9件、第4層に8件）です。そこにアプリケーション層の sigil-lantern-stream と sigil-agora-post が2件加わり、土台の6件と合わせて、Sigil 一族は全部で25リポジトリになります（計画下書きではバックエンド系19件として数えます）。

状態は図を作成した時点のものです。バックエンド部品17件とアプリケーション層の2件（sigil-lantern-stream、sigil-agora-post）は、現在は計画・概念の段階です（いずれもリポジトリ作成済み、計画下書き §18・§19 に記録済み。sigil-anima-llm は計画下書き §20、sigil-polis-os は計画下書き §21 に記録済み）。
