# examples

構文と意味論の検討に使うサンプルを置きます。実行可能なコードはまだありません（パーサ・処理系は未実装）。

## 構文候補

同じプログラムを 3 つの構文候補で書き、比較しました。[ADR 0002](../docs/decisions/0002-syntax-family.md) で **候補 C を採用** しています。候補 A・B のファイルは比較の記録として残しています。

| 候補 | ファイル | 概要 |
|---|---|---|
| A: S 式 | `a-sexpr.sigil` | すべてを括弧の入れ子で表す。意図・契約・効果も `(intent ...)` などの属性 |
| B: インデント + キーワード | `b-indent.sigil` | 固定順のキーワード行（`intent` / `params` / `requires` …）と字下げでブロックを表す |
| **C: 波括弧 + 契約節（採用）** | `c-brace.sigil` | 一般的な C 系のシグネチャに契約節を付け、本体を `{}` で囲む |

## サンプル

| 例 | 内容 | 確認したい点 |
|---|---|---|
| [01-average](01-average/) | 数値列の平均値（純粋関数） | 意図・事前条件・事後条件・効果なしの書き方 |

## 採用した構文（候補 C）の約束

- 関数はシグネチャの後に `intent` → `requires` → `ensures` → `effects` の 4 節を、この順にすべて書く。空の節は `none` と書く。
- シグネチャと 4 節が「仕様」であり、人間がレビューするのはこの部分だけ。本体（`{ ... }`）は含まない。
- 事後条件の中では戻り値を `result` で参照する。篩型の中では対象の値を `self` で参照する。
- 失敗しうる処理は `Result` で返し、`?` で早期に返す。
- 正規形（公式の整形器が出力する形）以外はコンパイルエラーにする。

比較の詳細と根拠の限界は [ADR 0002](../docs/decisions/0002-syntax-family.md) を参照してください。

## 次に検討すること

- 所有権・借用の書き方（Rust に倣う方向）
- 総称型の括弧（`<>` か `[]` か）と、本体の値の返し方
- 篩型の検査を静的に行うか、実行時に行うか
- 処理系ができた段階での、3 候補の生成エラー率の計測
