# 0013: 停止の扱い・標準ライブラリの正式な一覧・関数の値の渡し方（M3 の前）

- **状態**: 承認（2026-10-25。所有者の委任を受けて Claude が決定。計測による再検証の条件は末尾を参照）

## 背景

M2（所有権・借用の検査）は完了した（PR #27〜#31）。次の M3 は参照用の実行（インタプリタ）・契約の実行時検査・標準ライブラリのうち効果を持たない部分で、[ADR 0006](0006-p0-scope-and-bootstrap.md) の完了条件は次のとおりである。

- 効果を持たない関数（`average`・`03-ownership` の `main` 以外・`add_tax`・`apply_all`・`with_tax`）をテスト用の入口から呼び、戻り値が期待どおりになる。
- `requires` を破る呼び出しと `ensures` を破る実装が、実行時に契約違反として停止する（決定 5）。篩型への変換で範囲外の値が範囲外として扱われる。
- 標準ライブラリは `List`・`Option`・`Result`・`String` とその関数に限る。決定 3 の条件 9（停止のときの破棄の順序）のテストが通る。

M3 に着手する前に、次の 4 点が決まっていない。

1. **停止性**: 「異常停止・無限ループを効果に数えるか」は、ADR 0006 の決定 4 で P0 の中の論点とし、[ADR 0012](0012-ownership-check-and-stdlib.md) の決定 7 で決める時期を M3 の前に改めた。[ADR 0004](0004-effects.md) も「未決として残す点」に挙げている。M3 は停止（契約違反・桁あふれ・0 での除算）を初めて実装する段階である。
2. **標準ライブラリの正式な一覧**: ADR 0012 の決定 6 は `src/stdlib.rs` の表を暫定とし、正式な一覧を M3 の前に決めるとした。あわせて決める項目として、`find`・`min_by`・`position`、`get_mut`、`unwrap` に当たる停止する取り出し、`Int` の最小値の定数、`Float` の無限大・NaN の表示、間接化の型（Rust の `Box`）を書き残している。
3. **関数の値**: M2 の PR5 で、関数の値を他の `Copyable` でない値と同じく移動として追うようにした。その結果、`run(f, 1) + run(f, 2)` が `UseAfterMove` に、`while` の本体で `f` を渡すと `MovedInLoop` になる。健全だが、`effects of(f)` を持つ高階関数のほとんどを書けない。ADR 0012 の PR5 の記録は「複製できるクロージャを `Copyable` にするかは M4 以降で決める」と仮に置いた。
4. **借用区間の部品**: `src/borrow.rs` の `regions`（出来事の列から衝突を返す関数）は検査器から呼ばれず、検査器は同じ規則を `Loans` と `check.rs` の結びつけで別に動かしている（ADR 0012 の PR4・PR5 の既知の制限）。

前提:

- 書き手は AI。人間は仕様（モジュールの宣言・型の宣言・シグネチャと 4 節）だけをレビューする（[ADR 0001](0001-vision-and-scope.md)）
- P0 の契約は実行時検査だけで、契約違反は停止とする（ADR 0006 の決定 5）
- 関数の型は引数の型としてだけ書け、関数の値は入れ物に入れられず、戻り値にもできない（[ADR 0011](0011-type-system-scope.md) の決定 10）
- 同じ意味の書き方を一つにする（[ADR 0002](0002-syntax-family.md) の規則 1）

## 評価の観点

各決定に共通で、重要な順に並べる。

1. **仕様として信頼できるか**: シグネチャと 4 節が、本体の書き方によって黙って意味を変えないこと。人間が仕様から読み取ることが実行の結果と食い違わないこと。
2. **安全性**: ADR 0003 の保証（解放後の使用・二重解放・データ競合がない）を崩さないこと（必須条件）。
3. **AI が誤りなく書けるか**: 規則が少なく、同じ意味の書き方が一つで、エラーの直し方が一つに決まること。
4. **M3 の実装量と、後から広げられるか**: P0 の完了を遅らせず、契約の静的検査（P0 の後）や並行処理（P1）で規則を変えずに済むこと。

各決定では、選択肢を挙げ、推奨する 1 つを採用し、理由と選ばなかった案の理由、M3 への影響を記す。

## 決定 1: 停止性（異常停止・無限ループ）を効果に数えるか

### 選択肢

- **A: どちらも効果に数えない。`effects` は外から観測できる作用（入出力・共有所有の型を通した書き換え・タスクの中断など、ADR 0004 のカテゴリ）だけを表し、停止しうること・止まらないことは表さない**
- **B: 異常停止を効果（例: `stop`）に数える**。桁あふれ・0 での除算・契約違反・標準の関数の `requires` 違反が起こりうる関数は `effects stop` を書く
- **C: 止まらないことを効果（例: `diverge`）に数える**。`while` か再帰を含む関数は `effects diverge` を書く（構文から保守的に推論する）
- **D: 止まることを契約として示す**。5 つ目の節（`decreases` など、減っていく量）を加え、止まることを証明する

### 決定

**A** を採用する。規則:

- 効果のカテゴリ（ADR 0004 の表、ADR 0007 で加えた `task.*`）に、停止と無限ループのカテゴリを加えない。`effects none` は「外から観測できる作用を起こさない」ことを表し、「必ず値を返す」ことは表さない。`effects none` の関数も、異常停止しうるし、止まらないこともある。
- **異常停止** は次のものとし、すべて同じ扱いにする: 契約違反（`requires`・`ensures`。標準の関数の `requires` 違反（空の一覧の `min` など）を含む）、`Int` の桁あふれ、0 での除算と剰余、`Int` の最小値を `-1` で割ること（ADR 0011 の決定 1）。プログラムからは捕まえられず、回復の対象にしない（ADR 0006 の決定 5）。
- 異常停止は、停止の前に、生きている値を破棄する（ADR 0006 の条件 9 の「契約違反による停止のときの破棄の順序」を、すべての異常停止に当てはめる）。順序は `?` による早期の戻りと同じである。
- 異常停止の報告には、種類（契約違反・桁あふれ・0 での除算）と位置（関数名と行。契約違反ならどの節か）を含める。プログラムの終了コードは異常停止の種類によらず 1 つに決め、M3 の実装で値を決めて ADR 0006 の M3 の記録に残し、M5 の実行ファイルでも同じにする。
- **契約の式の中の異常停止**（`ensures result >= price` の評価中の桁あふれなど）は、契約違反ではなく、その契約の評価中に起きた異常停止として報告する。契約の式が真か偽かを決められなかったためである。
- **契約の意味**: `ensures` は「戻るならば成り立つ」ことを表す（部分正しさ）。止まらない呼び出し・異常停止した呼び出しの `ensures` は評価しない。`requires` は入口で、`ensures` は戻る直前に評価する（ADR 0006 の決定 5 のまま）。
- 止まらないことは検査しない。M3 のインタプリタは実行の歩数に上限を設けない（言語の意味としての上限は持たない）。止まらないテストへの備えは、テストを動かす道具の時間切れで行い、言語の規則にはしない。
- 契約の式が呼ぶ関数が止まらない場合も、P0 では検査しない（契約の式の中で値を移動できない規則（ADR 0012 の決定 1 の 7）は変えない）。
- タスク（P1）の中の無限ループが他のタスクの進行を妨げることは、`task.suspend` の有無で扱い（ADR 0007）、停止性の効果は加えない。

### 理由

- 観点 1: B を採ると、ADR 0012 の決定 7 で記録したとおり、`Int` の `+`・`*` を使うほぼすべての関数（`add_tax`・`sum_range`・`deposit`）が `effects stop` になり、`effects none` の関数がほとんど残らない。仕様の読み手にとって「効果: なし」が「外の世界に触れない」を表すという、効果の検査の主な価値が薄れる。停止しうることは `requires` が示す（`requires xs.len() > 0` を破れば止まる）ので、効果として重ねて書く必要もない。
- 観点 3・4: C は構文から推論するので AI の手間は増えないが、`while` を使う関数のほとんど（`sum_range`）と、再帰するすべての関数に付き、止まることが明らかな関数と区別できない。区別には D の証明が要る。D は契約の静的検査（P0 に含めない。ADR 0006 の決定 5）そのもので、4 節の形（ADR 0002 の規則 2、ADR 0008）を変える。
- A は M1 の効果の推論と全サンプルの `effects` 節をそのまま保つ。ADR 0004 の効果の検査のエラー率の計測（ADR 0012 の決定 7 の C の理由）の前提も変わらない。

### 選ばなかった案と理由

- **B（異常停止を効果に数える）**: 整数を扱うほぼすべての関数が同じ効果を持ち、効果の区別が仕様の情報にならない。P0 には静的検査がなく、停止しないことを示して効果を外す手段もない。
- **C（止まらないことを効果に数える）**: 構文による推論では、止まる関数と止まらない関数を区別できない。`while` を書くだけで効果が付くので、AI がループを避けて書き方が偏る。
- **D（止まることの証明）**: 契約の静的検査の範囲で、P0 の外である。P0 の後に静的検査を入れるとき、効果ではなく契約として改めて検討する（末尾の再検証）。

### M3 への影響

- インタプリタは、異常停止を 1 つの仕組み（破棄をしてから停止する）で実装する。契約違反・桁あふれ・0 での除算・契約の評価中の異常停止の 4 つを、テストで区別できる報告にする。
- 効果の表・効果の推論・`sigil spec` の出力は変えない。

## 決定 2: 標準ライブラリの正式な一覧

### 選択肢

- **A: M1〜M2 の表を基準に、M3 のインタプリタが本体を持つ範囲（効果を持たない部分）を正式な一覧として本 ADR で固定する。ADR 0012 の繰り延べ項目は、表で書けない意味（参照の返却・停止・型の再帰）を一つずつ決め、要るものだけ加える。効果を持つ部分（`console`・`fs`・`Path`・`IoError`・`Shared`・`Cell`）は表に残し、正式には M4 の前の分割の ADR で決める**
- **B: 現在の表をそのまま正式な一覧とし、繰り延べ項目はすべて加えない**
- **C: 一般的な言語の標準ライブラリにならい、`List`・`String` の操作を広く加える**（`position`・`contains`・`filter`・`fold`・`split`・`concat` など）

### 決定

**A** を採用する。

#### 正式な一覧（M3 のインタプリタが本体を持つ範囲）

表の「区分」は、M1〜M2 の表から変わらないもの（既存）、本 ADR で加えるもの（追加）、シグネチャを改めるもの（変更）を示す。効果はすべて `none`（関数の値を受け取るものは `of(f)` など、引数の効果）である。

| 型・名前空間 | 関数 | 区分 | 意味（M3 の本体が従うもの） |
|---|---|---|---|
| 自由関数 | `to_float(n: Int) -> Float` | 既存 | 最も近い `Float` |
| 自由関数 | `to_int(x: Float) -> Option<Int>` | 追加 | 0 の方向に切り捨てる。NaN・無限大・`Int` の範囲外は `None`（ADR 0011 の決定 1 で形を決めていたもの） |
| `Int` | `min_value() -> Int`（`Int.min_value()` と呼ぶ） | 追加 | `Int` の最小値 −2⁶³。最大値はリテラル `9223372036854775807` で書けるので、`max_value` は置かない |
| すべての型（関数の型を除く） | `clone(self: &T) -> T` | 追加 | 値の複製（下の「`clone`」） |
| `<T> List<T>` | `new() -> List<T>` | 既存 | 空の一覧 |
| | `push(self: &mut List<T>, x: T)` | 既存 | 末尾に足す |
| | `get(self: &List<T>, i: Int) -> Option<&T>` | 既存 | 0 始まり。範囲外（負を含む）は `None` |
| | `get_mut(self: &mut List<T>, i: Int) -> Option<&mut T>` | 追加 | `get` と同じ。腕の束縛への代入（`Some(a) => { a = v; }`）で要素を書き換える |
| | `len(self: &List<T>) -> Int` | 既存 | 要素の数 |
| | `is_empty(self: &List<T>) -> Bool` | 既存 | |
| | `map<U>(self: &List<T>, f: fn(T) -> U) -> List<U>` | 既存 | 先頭から順に 1 回ずつ `f` を呼ぶ |
| | `find(self: &List<T>, pred: fn(&T) -> Bool) -> Option<&T>` | 追加 | 先頭から順に `pred` を呼び、最初に真になった要素。以降は `pred` を呼ばない |
| | `max_by<K: Comparable>(self: &List<T>, key: fn(&T) -> K) -> Option<&T>` | 既存 | 空なら `None`。最大の鍵が複数あれば最初の要素 |
| | `min_by<K: Comparable>(self: &List<T>, key: fn(&T) -> K) -> Option<&T>` | 追加 | `max_by` の最小版 |
| `<T: Numeric> List<T>` | `sum(self: &List<T>) -> T` | 既存 | 先頭から順に足す。空は `0`・`0.0`。`Int` の桁あふれは異常停止 |
| `<T: Comparable> List<T>` | `min(self: &List<T>) -> &T`（`requires self.len() > 0`） | 変更 | 最初の最小の要素（後の要素 `x` が今の候補より `x < 候補` のときだけ候補を替える） |
| | `max(self: &List<T>) -> &T`（`requires self.len() > 0`） | 変更 | `min` の最大版（`x > 候補` のときだけ替える） |
| `<T> Option<T>` | `is_some`・`is_none`・`unwrap_or`・`map`・`ok_or` | 既存 | 表のシグネチャのまま |
| `<T, E> Result<T, E>` | `is_ok`・`is_err`・`unwrap_or`・`ok`・`map`・`map_err` | 既存 | 表のシグネチャのまま |
| `String` | `len(self: &String) -> Int` | 既存 | Unicode のスカラー値の数（出力先によらず同じ） |
| | `is_empty(self: &String) -> Bool` | 既存 | |
| | `trim(self: &String) -> String` | 既存 | 前後の空白（Unicode の `White_Space` の文字）を除いた新しい文字列 |
| | `lines(self: &String) -> List<String>` | 既存 | `\n` で分け、各行の末尾の `\r` を 1 つ除く。末尾の `\n` の後の空の行は含めない |
| | `parse_int(self: &String) -> Result<Int, ParseError>` | 既存 | 省略できる先頭の `-` と、1 文字以上の ASCII の数字だけを受け付ける（`+`・空白・`_` は失敗）。`Int` の範囲外も失敗 |

標準の型は `List<T>`・`Option<T>`・`Result<T, E>`・`ParseError` とする（`Int`・`Float`・`Bool`・`String`・`Unit` は基本型）。

#### 個別の規則

- **`min`・`max` を参照を返す形に改める**: ADR 0012 の決定 2 の `impl<T: Comparable + Copyable> List<T> { fn min(...) -> T }` を、`impl<T: Comparable> List<T> { fn min(self: &List<T>) -> &T }` に改める。借用の引数は受け手だけなので ADR 0003 の規則 3 を満たす。参照の名前は値を表す（ADR 0011 の決定 4）ので、`01-average` の `ensures xs.min() <= result` はそのまま書け、`Copyable` な要素なら値として読む位置で複製される。これで `String` の一覧の最小も同じ `min` で得られる。ADR 0012 が想定した「参照を返す別のメソッド」は置かない（同じ意味の操作が 2 つになるため。ADR 0012 の決定 6 の規則 7 の「同じ名前を具体化の違いで複数置かない」と同じ考え方）。
- **`clone`**: ADR 0003 の規則 1・ADR 0011 の決定 4・ADR 0012 の決定 1 は「複製は `.clone()` で明示する」としているが、M1〜M2 の表には `clone` がなかった。本 ADR で次のとおり置く。
  - `clone(self: &T) -> T` は、関数の型を除くすべての型（基本型・標準の型・利用者の構造体と列挙型・組・型引数）に付く、検査器の組み込みのメソッドとする。関数の型は型引数にも入れ物にも置けない（ADR 0011 の決定 10）ので、型引数 `T` の値には常に `clone` を呼べ、新しい性質は要らない。
  - 意味は値の複製で、構成要素を順に複製する。`Shared<T>` の `clone` は中身を複製せず、同じ値の所有者を 1 つ増やす（参照カウント。ADR 0003 の規則 4）。効果は `none`。
  - 受け手が `Copyable` と分かっている型（`Int`・`Float`・`Bool`・`Unit`・`Copyable` な篩型と組）の `clone` はエラー（`CloneOfCopyable`）とする。暗黙の複製と同じ意味の書き方が 2 つになるためである。型引数の受け手は `Copyable` と分からないので書ける。
  - 利用者は `impl` の中に `clone` という名前のメソッドを宣言できない（`ReservedNameDefined`）。
  - `List`・`Option`・`Result`・`String` の `clone` は M3 で、`Shared`・`Cell`・`Path`・`IoError` の `clone` は M4 で本体を持つ。
- **`get_mut` を加え、添字への代入（`set`）は置かない**: `get_mut` は `get` と同じく範囲外を `None` で返し、停止しない。参照の名前への代入は参照先を書き換える（ADR 0011 の決定 4）ので、`match xs.get_mut(i) { Some(a) => { a = v; } None => {} }` で要素全体を、`a.balance = v;` でフィールドを書き換えられる。結果を使い終わるまで一覧を `&mut` で借り続ける（ADR 0012 の決定 1 の 3 の規則のまま）。`set(i, x)` を加えると要素の書き換えの書き方が 2 つになり、範囲外を停止にすると添字 `a[i]` を持たなかった理由（ADR 0009 の決定 8、ADR 0012 の決定 3 の C）と同じ問題が生じる。
- **`find`・`min_by` を加え、`position` は置かない**: `find` と `min_by` は、`max_by` と同じく受け手から借りた参照を返す。`position`（添字を返す）は、添字を使う操作が `get`・`get_mut` だけの P0 では、`find` で足りない用途がサンプルにない。要素の添字が要るときは `while` と `get` で書く。
- **停止する取り出し（`unwrap`・`expect`）は置かない**: `match`・`unwrap_or`・`?` で書ける。停止する取り出しを置くと、`Option`・`Result` から値を取り出す書き方が 2 つになり（ADR 0002 の規則 1）、本体に隠れた停止が仕様（4 節）に現れない（観点 1）。`min`・`max` の停止は、値を決められない入力を `requires` で除いた結果で、呼び出し側の `requires` で防げる。`unwrap` は `requires self.is_some()` を書いても、`match` の代わりにしかならない。
- **`Int` の最小値は `Int.min_value()`**: ADR 0011 の決定 1 の「標準ライブラリの定数」をこの名前で置く。P0 には定数の宣言（`const` は予約語のまま）がないので、引数のない関数とする。前置の `-` とリテラル `9223372036854775808` を組にして受け付ける特例は置かない（リテラルの範囲の規則に例外が生じるため）。
- **`Float` の表示**: `console.log`（M4）と M3 のテスト用の表示は、有限の値を ADR 0009 の決定 5 の小数のリテラルの正規形と同じ綴りで、無限大を `inf`・`-inf`、NaN を `NaN` と表示する。負のゼロは `-0.0` と表示する。無限大・NaN の定数は置かない（`1.0 / 0.0` で得られ、P0 のサンプルは使わない）。
- **間接化の型（`Box`）は置かず、列挙型を通る再帰を許す**: `enum Expr { Num(Int), Add(Expr, Expr) }`・`enum Chain { End, Next(Int, Option<Chain>) }` のように、型の循環が少なくとも 1 つの列挙型の値（`Option` を含む）を通るなら、型の直接の再帰を受け付ける。処理系が再帰する構成要素を間接化して持つ（インタプリタではもとより間接、M5 では処理系がヒープに置く）。循環が構造体と組だけを通る型（`struct S { s: S }`）は、値を作れないのでエラーのままとする（M1 のエラーの説明を、間接化の型を待つ旨から、列挙型を通すよう示す内容に改める）。`List<Node>` を通る再帰は、M1 から受け付けているとおりである。性質の導出（`Equatable` など）は、循環の上で成り立つと仮定して構成要素から導く。
- **`Set`・`Map` は P0 の一覧に入れない**: 操作を持たない型として表に置かれているだけで、サンプルも使わない。名前は予約名に残す（ADR 0012 の決定 5）。中身を見せない型の表（`OPAQUE_TYPES`）からは除く。

#### 効果を持つ部分（M4 の前に正式に決める）

`Path`（`is_empty`）・`IoError`・`console.log`・`fs.read`・`fs.write`・`Shared`（`new`）・`Cell`（`new`）・`Shared<Cell<T>>`（`get`・`set`）は、M1〜M2 の表のまま暫定とし、M4 の前の「標準ライブラリの分割」の ADR（ADR 0006 の決定 4）で、核と OS 依存部分への置き場所とあわせて正式に決める。`Path` の値の作り方もそこで決める。

### 理由

- 観点 1: 一覧の各関数の意味（範囲外・空・重複・空白・行の区切り）を M3 の前に決めるので、M3 のインタプリタの本体と M5 の出力が同じ意味になり、仕様の読み手が出力先によって違う結果を見ることがない。
- 観点 3: 追加は、他の書き方では書けない操作（`clone`・`get_mut`・`Int.min_value()`・`to_int`）と、すでにある `max_by` と対になる操作（`min_by`・`find`）に限った。どれも同じ意味の操作をすでに持たない。
- 観点 4: 表の形（シグネチャと効果と `requires`）は ADR 0012 の決定 6 の規則のまま広げられる。

### 選ばなかった案と理由

- **B（今の表のまま）**: ADR 0003・0011・0012 が使い方を示している `.clone()` がなく、`Copyable` でない値を参照から取り出す方法がない（エラーの説明に出る直し方が使えない）。`Copyable` でない要素の一覧の要素を書き換える方法もなく、`String` の一覧の最小も得られない。
- **C（広く加える）**: 本体と意味を決める範囲が M3 の完了条件を超えて広がり、同じ意味の書き方（`filter` と `while`、`fold` と `sum`）が増える。P0 の計測でサンプルに要ると分かったものを、その時点で ADR に記録して加える。
- **`min`・`max` を値を返す形のまま残す案**: `String` の一覧の最小のために参照を返す別のメソッドが要り、同じ意味の操作が 2 つになる。
- **`unwrap` を `requires self.is_some()` 付きで置く案**: 上の個別の規則のとおり、`match` と同じことを停止で書く 2 つ目の書き方になる。
- **`Box<T>` を置く案**: 利用者が `Box.new(...)` と、取り出しの書き方を毎回書くことになり、AI が付け忘れ・付け過ぎの誤りを出しうる。間接化は性能のための表現の選択で、仕様の読み手にとって意味の違いがない（性能は非目標。DESIGN.md の 4 章）。

### M3 への影響

- `src/stdlib.rs` の表を上のとおり改める（M3 の着手時の最初の作業。「M3 の着手時に必要な変更」）。
- インタプリタは、上の一覧の効果を持たない関数の本体を組み込みで持つ（`sum` と同じく信頼基盤の標準ライブラリ。ADR 0012 の決定 2）。

## 決定 3: 関数の値の扱い

### 選択肢

- **A: とらえた値がすべて `Copyable` なクロージャと、関数の名前を `Copyable` にする**。それ以外のクロージャは今のまま移動する
- **B: 関数の値を引数に渡すことは、移動ではなく呼び出しの間の共有の借用とする。書き方（`f: fn(Int) -> Int`、`run(f, 1)`）は変えない**
- **C: B を明示の借用にする**。引数の型を `f: &fn(Int) -> Int` と書き、呼び出しの位置で `run(&f, 1)` と書く
- **D: 今のまま**（関数の値はすべて移動する）

### 決定

**B** を採用する。規則:

- 関数の型の引数に関数の値（名前・`let` に束縛したクロージャ・関数の型の引数）を渡すことは、その呼び出しの間の共有の借用とする。渡した後も、呼び出し側で同じ値を使える（`run(f, 1) + run(f, 2)`、`while` の本体での `run(f, i)`、`let g = move |x| x + k; run(g, 1); run(g, 2);` が通る）。
- 関数の型の引数（`f: fn(Int) -> Int`）は呼び出し側から借りた値なので、関数の中では何度でも使え、別の呼び出しに渡しても、`let h = f;` で別名にしても、`move` のクロージャがとらえても移動しない。関数の値は戻り値にも入れ物にも置けない（ADR 0011 の決定 10）ので、借りた値が呼び出しより長く生きることはない。
- 関数の中で作ったクロージャ（`let` に束縛した `move` のクロージャ）の所有は、束縛した変数にある。`let h = g;` と、`move` のクロージャによるとらえは、今のとおり移動とする（同じ環境の所有者が 2 つにならないようにするため）。
- 1 つの呼び出しの中で、同じ関数の値を共有の借用と移動の両方に使うこと（`pair(g, move |x| g(x))`）は、ADR 0012 の決定 1 の 2 の重なりの規則でエラーになる（共有の借用の間の移動）。
- 関数の値の呼び出し `f(x)` は今のとおり読みとする。関数の型の `Copyable`・`Sendable`・`Shareable` は今のとおり成り立たない（`holds` が `Some(false)`）。このため、借りた関数の値がタスク（P1）をまたぐことはない。
- 仕様の表示（ADR 0003 の規則 7、ADR 0008 の決定 7）で、関数の型の引数は「f を受け取る（呼び出し後、呼び出し側では使えない）」ではなく、「f を呼ぶ（fn(Int) -> Int）」と訳す。`04-effects` の `apply_all` の期待出力が変わる。
- 移動した関数の値を使ったときのエラーの説明に、`.clone()` を勧める文を出さない（関数の型には `clone` がない。決定 2）。代わりに「関数の値は引数に渡しても移動しないので、別名を作らずに元の名前を使う」と示す。

### 理由

- 観点 2: 関数の値は、ADR 0011 の決定 10 により、引数・`let` の束縛・直接の呼び出しにしか置けない。呼ばれた側は関数の値を戻り値にも入れ物にも置けず、呼ぶ（読む）ことしかできない。呼ばれた側から見て、渡された関数の値は呼び出しの間だけ使える借用と同じで、借用として扱っても解放後の使用は起こらない。とらえた値を `&mut` で借りる非脱出のクロージャを何度呼んでも、単一の処理の中の順番の呼び出しで、`Sendable` でないので他のタスクから同時に呼ばれることもない。
- 観点 3: 書き方が変わらず、`effects of(f)` の高階関数（`apply_all`・`map` に渡す `f` を何度も使うもの）が、Rust の `&dyn Fn` と同じ感覚で書ける。PR5 の `UseAfterMove`・`MovedInLoop` の過剰な拒否がなくなる。
- 観点 4: M5 では、関数の値の引数を環境への参照として渡せばよく、閉包の環境を複製しない。

### 選ばなかった案と理由

- **A（`Copyable` なクロージャ）**: 呼ばれた側の引数 `f: fn(Int) -> Int` には、とらえた値が `Copyable` でないクロージャも渡されうるので、型だけでは `f` が `Copyable` か分からない。高階関数の中の `run(f, 1) + run(f, 2)` は、関数の型に「複製できる」ことを書く新しい表記（`fn(Int) -> Int + Copyable` など）を入れない限り通らず、問題の中心が解けない。とらえる値に `String` を 1 つ足しただけでクロージャが移動に変わることも、ADR 0011 の決定 6 で構造体を `Copyable` にしない理由と同じ問題を生む。
- **C（明示の借用 `&fn`）**: 呼び出しの位置で `&` を書く規則（ADR 0011 の決定 4）とは揃うが、`max_by(self: &List<T>, key: &fn(&T) -> K) -> Option<&T>` のように、関数の値を受け取る参照を返す関数が借用の引数を 2 つ持つことになり、ADR 0003 の規則 3（参照を返せるのは借用の引数がちょうど 1 つの関数だけ）に反する。また `fn(...)` と `&fn(...)` の 2 つの書き方のどちらかを禁じる規則が要り、`run(&|x| x + 1, 1)` のようにクロージャにも `&` が付く。
- **D（今のまま）**: 健全だが、関数の値を 2 回使う高階関数を書く手段がない（関数の型には `clone` もない）。`effects of(f)` の検査（ADR 0004 の規則 4）の価値が、高階関数をほとんど書けないことで損なわれる。

### M3 への影響

- 検査器の変更（関数の値を引数に渡す位置での移動の記録をやめ、呼び出しの間の共有の借用として重なりを調べる。関数の型の引数の移動を記録しない）と、`sigil spec` の訳の変更は、M3 の着手時に、インタプリタを加える PR と分けて行う（「M3 の着手時に必要な変更」）。
- インタプリタは関数の値を引数に渡すとき、環境を複製も移動もしない。

## 決定 4: `src/borrow.rs` の `regions` を検査器に統合するか

### 選択肢

- **A: 統合しない。条件 8 の「単独で呼べる 1 つの部品」は、検査器と `regions` が共に使う `Loans`（`touch`・`lend`・`held`・`merge`・`dead_of`）と `overlaps` であると定め直す。`regions` は、その部品を直線の出来事の列で動かす単体テスト用の駆動部として残す。`regions` の各事例と同じ事例を Sigil のソースで書いた検査器のテストを対にして置き、二つの駆動部の一致をテストで確かめる**
- **B: M3 の前に統合する**。検査器が文ごとに出来事を出し、`regions` が分岐とループを含めて衝突を計算する
- **C: M4 の前に統合する**
- **D: `regions` を削除し、条件 8 の事例を検査器のテストだけで固定する**

### 決定

**A** を採用する。規則:

- ADR 0006 の条件 8 の部品は `src/borrow.rs` の `Loans` と `overlaps` とする。貸しが使えなくなる規則（読み出しは `&mut` の貸しだけを、書き換え・`&mut` の借用・移動はすべての貸しを使えなくする。経路の重なり。合流では片方で使えなくなった貸しを使えなくなったとする）は、この部品だけが持ち、検査器（`check.rs`）は同じ部品を呼ぶ。検査器が持つのは、制御の流れ（分岐・ループ・`match`）と、どの式がどの出来事に当たるかの対応だけである。
- `regions` は、出来事の列を渡して部品の規則を確かめる、単体テスト用の駆動部として残す。
- `src/borrow.rs` の単体テストの事例（規則 2 の事例、返された参照の区間とその推移、再借用、フィールドの重なり）それぞれに、同じ事例を Sigil のソースで書いて `sigil check` にかけるテストを対にして置き、両方が同じ判定（衝突の有無と、衝突なら使えなくなった地点と使った地点）になることを確かめる。M3 の着手時に、テストだけの PR として加える。
- 統合は、ADR 0007 の条件 8 の P1-b（中断をまたいで生きる値の計算に区間の部品を使う）で、部品が制御の流れを扱う必要が生じたときに改めて検討する。その時点で、検査器の流れの解析を `src/borrow.rs` に移すかを決める。

### 理由

- 観点 2: 規則の中身（どの使い方がどの貸しを使えなくするか）はすでに `Loans` に一つだけあり、二重の実装になっているのは駆動の部分（出来事の順番の作り方）だけである。対のテストで、その駆動の部分の食い違いを事例ごとに検出できる。
- 観点 4: M3 のインタプリタ・M4 の標準ライブラリ・M5 の出力は、どれも借用の区間の情報を使わない（破棄の地点はスコープで決まる。ADR 0003 の規則 1）。統合は M3〜M5 の成果を何も前に進めず、検査器の流れの解析を作り直す大きな変更になる（ADR 0012 の PR5 の記録）。M2 の完了条件のテストを壊す危険を、M3 の直前に負う理由がない。

### 選ばなかった案と理由

- **B（M3 の前に統合）**: `regions` は直線の列しか扱わないので、統合には分岐の合流とループの不動点を部品に移す必要があり、検査器の流れの解析の作り直しになる。M3 はその結果を使わない。
- **C（M4 の前に統合）**: M4 も区間の情報を使わない。時期を決めても、統合する理由が M4 で生じない。理由が生じるのは P1-b である。
- **D（削除）**: 出来事の列で書いた事例は、Sigil のソースで書いた事例よりも規則そのものを読みやすく示し、条件 8 のテストとして M2 で固定した。削除するとその記録がなくなる。

### M3 への影響

- 対のテストを加える（検査器と `src/borrow.rs` は変えない）。`src/borrow.rs` の冒頭の注記と ADR 0006 の条件 8 の行に、部品の範囲を本決定のとおり記す。

## M3 の完了条件に加えるもの

ADR 0006 の M3 の完了条件に、次のテストを加える（エラー例はテスト用のファイルに切り出す）。

- **停止（決定 1）**: `add_tax` に桁あふれする値を渡すと桁あふれの異常停止になり、`add_tax` は `effects none` のまま検査を通る。0 での除算が異常停止になる。`ensures` の評価中の桁あふれが、契約違反でなく契約の評価中の異常停止として報告される。破棄を記録するテスト用の型で、桁あふれによる停止のときの破棄の順序が、契約違反による停止のときと同じになる（条件 9 の拡張）。異常停止の終了コードが種類によらず同じになる。
- **標準ライブラリ（決定 2）**: 一覧の効果を持たない関数を、それぞれ「意味」の列の事例で実行して期待どおりになる。特に、`min`・`max`・`min_by`・`max_by` の重複したときの最初の要素、`find` が最初に真になった要素の後で `pred` を呼ばないこと（呼んだ回数を数える関数で確かめる）、`get`・`get_mut` の負の添字と範囲外、`lines` の `\r\n` と末尾の改行、`parse_int` の `+1`・`" 1"`・範囲外、`to_int` の NaN・範囲外、`Int.min_value()`、`Float` の `inf`・`-inf`・`NaN`・`-0.0` の表示（テスト用の表示の関数で確かめる）。
  - 通る: `List<String>` の `min()`、`ensures xs.min() <= result`（`01-average`）、`match xs.get_mut(0) { Some(a) => { a = v; } None => {} }` と `a.balance = v;`、`a.clone()`（`a: &Account`）、型引数 `T` の値の `clone`、`enum Expr { Num(Int), Add(Expr, Expr) }` の宣言と、それを評価する再帰の関数。
  - エラーになる: `get_mut` の結果を使い終わる前の `push`、`1.clone()`・`n.clone()`（`n: Int`）の `CloneOfCopyable`、利用者の `impl` の `fn clone` の `ReservedNameDefined`、`struct S { s: S }`、`unwrap` の呼び出し（メソッドがない）、`Set`・`Map` を型として使う宣言。
- **関数の値（決定 3）**: 通る: `run(f, 1) + run(f, 2)`（`f` は関数の型の引数）、`while` の本体の `run(f, i)`、`let g = move |x| x + k; run(g, 1) + run(g, 2)`、関数の型の引数の別名 `let h = f; let k = f;`（M2 の `function_values_are_moved` で `UseAfterMove` を期待していたもの）。エラーになる: `let h = c; let k = c;`（`c` は `let` に束縛した `move` のクロージャ。`UseAfterMove`、説明に `.clone()` を含まない）、`pair(g, move |x| g(x))`。`04-effects` の `apply_all` の仕様の期待出力が「f を呼ぶ（fn(Int) -> Int）」になる。
- **借用区間の部品（決定 4）**: `src/borrow.rs` の単体テストの各事例と、同じ事例の Sigil のソースのテストが、同じ判定になる。

## 根拠の限界と再検証

- 各決定の観点 3「AI が誤りなく書けるか」は、一般に知られている傾向（Rust の `unwrap` の多用、`Box` の付け忘れ、高階関数での借用のエラー）に基づく定性的な判断で、この言語で計測した結果ではない。
- 候補の案出しと採点を同じ者（Claude）が行っており、偏りがありうる。
- 決定 1 は P0 に契約の静的検査がないことを前提にしている。P0 の後に静的検査を入れるときは、止まることの証明（決定 1 の D）を、効果ではなく契約（4 節の拡張か、静的検査の注釈）として検討し、`effects none` の意味は変えない。仕様の表示で「効果: なし」が「止まる」と誤読されていると分かった場合は、表示の文言を見直す。
- 決定 2 の一覧は、P0 のサンプルと ADR 0003・0011・0012 が使い方を示した操作に限った。P0 の計測で、AI が `while` と `get` で書き直す操作（添字の検索・絞り込み・畳み込み）が多いと分かった場合は、`position`・`filter`・`fold` などを ADR に記録して加える。
- 決定 3 は、関数の値が呼び出しより長く生きないこと（ADR 0011 の決定 10）に依存する。P1 の前に関数の型をフィールド・戻り値に置けるようにする（ADR 0011 の決定 10 の B）とき、または起動するクロージャ（ADR 0007）が関数の値をとらえる必要が生じたときは、借用として渡す規則を見直す（その時点では関数の値の所有と `Sendable` を決め直すことになる）。
- 決定 4 は、二つの駆動部の一致を事例のテストでしか確かめない。M3 以降に区間の検査の誤り（誤った受理・誤った拒否）が見つかった場合は、その事例を対のテストに加え、同じ種類の誤りが 2 回以上続いたら統合（決定 4 の B）を前倒しで検討する。
- M3 の完了後、次を計測する。結果が本決定と大きく食い違う場合は、この ADR を見直す。
  - 異常停止（桁あふれ・0 での除算・標準の関数の `requires` 違反）がテストで起きた回数と、`requires` で防げたはずのもの
  - `CloneOfCopyable` と、`clone` の書き忘れ（参照から値を取り出す移動のエラー）の数
  - 関数の値の借用の重なりのエラー（決定 3 の `pair(g, move |x| g(x))` の形）の数
