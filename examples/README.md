# examples

構文と意味論の検討に使うサンプルを置きます。実行可能なコードはまだありません（パーサ・処理系は未実装）。

## 構文候補

同じプログラムを 3 つの構文候補で書き、比較しました。[ADR 0002](../docs/decisions/0002-syntax-family.md) で **候補 C を採用** しています。候補 A・B のファイルは比較の記録として残しています。

| 候補 | ファイル | 概要 |
|---|---|---|
| A: S 式 | `a-sexpr.sigil` | すべてを括弧の入れ子で表す。意図・契約・効果も `(intent ...)` などの属性 |
| B: インデント + キーワード | `b-indent.sigil` | 固定順のキーワード行（`intent` / `params` / `requires` …）と字下げでブロックを表す |
| **C: 波括弧 + 契約節（採用）** | `c-brace.sigil` | 一般的な C 系のシグネチャに契約節を付け、本体を `{}` で囲む |

## 採用した構文（候補 C）の約束

- 関数はシグネチャの後に `intent` → `requires` → `ensures` → `effects` の 4 節を、この順にすべて書く。空の節は `none` と書く。
- モジュールの宣言・型の宣言・関数のシグネチャと 4 節が「仕様」であり、人間がレビューするのはこの部分だけ。関数の本体（`{ ... }`）は含まない（[ADR 0008](../docs/decisions/0008-m0-notation.md) の決定 7）。
- ファイルの先頭に `module` の宣言を書き、`targets`（出力先）→ `trust`（信頼基盤か）の 2 節をすべて書く（[ADR 0008](../docs/decisions/0008-m0-notation.md)）。
- 総称型の括弧は `<>`（型の位置だけ）。値を返す関数は `return` で返す。`if`・`while` は文で、値を選ぶ分岐は `match` で書く。脱出するクロージャには `move` を付ける。
- 事後条件の中では戻り値を `result` で、呼び出し前の値を `old(式)` で参照する。篩型（`type T = B where 条件;`）の中では対象の値を `self` で参照し、`T.check(v)` で `Option<T>` に変換する。
- `effects` 節は `of(...)` を先に、カテゴリを文字の順に並べ、下位がそろったら上位に畳む。`targets` も文字の順に並べる。
- 失敗しうる処理は `Result` で返し、`?` で早期に返す。
- コメントは `//` だけ。型・列挙型の値は大文字始まり、関数・変数は小文字の `_` 区切り。文は `;` で終える。比較は連鎖させず、`&&` と `||` を混ぜるときは括弧を付ける。式は途中で折り返さない（[ADR 0009](../docs/decisions/0009-lexical-and-grammar.md)）。
- 正規形（公式の整形器が出力する形）以外はコンパイルエラーにする。

比較の詳細と根拠の限界は [ADR 0002](../docs/decisions/0002-syntax-family.md) を参照してください。
