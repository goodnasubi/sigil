# 0039: P2-1 JavaScript 出力

- **状態**: 提案（typesafe-ai の正式判定を末尾に記録。別系統のレビュー前）
- **日付**: 2026-11-17（JST）
- **対象**: [Issue #555](https://github.com/goodnasubi/sigil/issues/555)、レーン E

## 背景

[ADR 0038](0038-p2-scope.md) の最初の段 P2-1 を、実装前に具体化する。人間が仕様だけをレビューできるよう（[ADR 0001](0001-vision-and-scope.md)）、検査・契約・所有権の意味を出力先で変えない。基準は言語の仕様と共通 lowering、比較相手は [ADR 0017](0017-run-on-sir-evaluator.md) の SIR 評価器とする。

起草時の `main` は 7ccf80e。本 PR は本 ADR と索引だけを変更する。以下の API・CLI・診断は実装に向けた決定であり、現行の処理系や `sigil spec` に追加された機能を記述するものではない。

## 選択肢と決定

| 判断 | 採用する案 | 他案を採用しない理由 |
|---|---|---|
| 出力器 | 検査・単相化・検証を通った共通 SIR から ES module を生成 | AST から再検査・独自 lowering すると契約・移動・破棄を重複実装する |
| 初版の範囲 | 下記の純粋な核と `console.log` だけを明示的に許可 | サーバー機能の全面移植や任意 JS FFI は権限境界を広げ、UI・通信まで先取りする |
| 数値と寿命 | i64 を BigInt、binary64 を Number、SIR の明示的な破棄を実行 | 整数を Number に丸める案や GC 任せの解放は値と破棄時点が一致しない |
| 製品の単位 | Node.js・npm・Wasm を要しないブラウザ向け JS 単独出力 | Wasm の暫定代替として扱うと ADR 0038 決定 2 を満たさない |

正式判定の確率は意味の正しさの証明ではない。採用理由は、既存の検査保証を保ち、一覧と共通事例で実装の完了を判断できることにある。

## 決定 1: 初版に含む核

`targets browser` を含む利用者モジュールと、その入口から必要な `browser`／`bare` 共通コードを対象とする。`bare` は純粋な共通部品として利用できるが、この出力の入口には `browser` を要求する。`targets` と出力器選択を混同しない。通常の構文・名前解決・型・所有権・借用・効果完全一致・契約式の検査を先に行い、出力器のために規則を緩めない。

### 構文と型の許可一覧

| 区分 | 初版に含むもの |
|---|---|
| 宣言 | `module`・`targets`・`use`・公開範囲、関数と既存の仕様 4 節、構造体・列挙型・組、総称型／総称関数と検査済みのトレイト／`impl` の静的解決、篩型 |
| 文 | `let`／`let mut`、既存の束縛・組分解、局所／フィールド／借用先への代入、呼び出し文、`return`、`if`／`else`、`while`、文の `match` |
| 式 | 整数・小数・文字列・真偽値・組・一覧のリテラル、構造体／列挙型の構築、フィールド、関数／メソッド呼び出し、式の `match`、`?`、`&`／`&mut`、検査で許されたクロージャと `move` 取り込み |
| 演算 | 数値の `+ - * / %` と単項 `-`、比較、短絡する `&&`／`||` と `!`、String の連結、Int の `&`／`|`／`^`／`~`／`<<`／`>>` |
| 型 | `Int`・`Float`・`Bool`・`Unit`・`String`・`Bytes`・`List<T>`・`Option<T>`・`Result<T,E>`・`ParseError`、利用者の構造体／列挙型（既存の規則で許された再帰を含む）・組・篩型・借用・関数型 |
| 契約 | `requires`・`ensures`・`result`・`old(e)`、篩型への変換と標準操作の前提。検査が静的に証明しない条件は実行時にも検査する |

型引数は具体化し、トレイト呼び出しも解決してから生成する。関数値・クロージャの格納／返却・捕捉・効果上限は、現行の検査器が許す形をそのまま守る。JS の動的な型変換・truthiness・オブジェクトの同一性で Sigil の比較を代用しない。

### 標準操作の許可一覧

これは `std.core` 全体の対応宣言ではない。次の操作だけを初版の対応集合にする。シグネチャ・境界・空の場合・失敗の型は既存 ADR と標準ライブラリの表を再利用する。

- 組み込みの明示 `.clone()`（既存の `Copyable`／関数型の禁止規則を維持）。
- `to_float`、`to_int`、`Int.min_value`、`Int.rotl`／`rotr`／`rotr32`／`ashr`。
- `String.len`／`is_empty`／`trim`／`lines`／`parse_int`／`as_bytes`。
- `List.new`／`push`／`get`／`get_mut`／`len`／`is_empty`／`map`／`find`／`max_by`／`min_by`／`sum`／`min`／`max`。高階操作の効果は `of(f)` 等を既存どおり検査する。
- `Option.is_some`／`is_none`／`take`／`unwrap_or`／`map`／`ok_or`。
- `Result.is_ok`／`is_err`／`unwrap_or`／`ok`／`map`／`map_err`。
- `Bytes.new`／`with_capacity`／`from_list`／`len`／`is_empty`／`get`／`set`／`push`／`slice`／`concat`／`extend`／`to_string_utf8`／`push_u16_be`／`push_u32_be`／`push_u64_be`／`push_u32_le`／`read_u32_be`。
- 最小の外部作用として `console.log<T: Displayable>(x: &T)`（効果 `console`）。

`Shared`／`Cell` と効果 `state`、大域の可変状態、タスク／チャネル／ロック、`Addr`／`raw.*`／利用者の `unchecked`／`trust base`、`Secret`／暗号操作、`Float.to_bits`／`from_bits`、`std.json`、`Path`／ファイル／環境変数／時計／乱数／ソケット／DB／HTTP サーバー／`std.web` は初版に含めない。埋め込み標準操作を実装する出力器内部の補助コードと、利用者が原始操作を呼べることは区別する。`Set`／`Map` 等の新しい型・操作を本 ADR で追加しない。

UI・DOM・イベント・ネットワーク要求・非同期ホスト呼び出し・npm パッケージ互換・任意 JS の文字列評価は P2-1 の外である。後続段が必要とする追加は、その段の ADR と対応テストで明示的に広げる。

## 決定 2: 値・文字列の ABI

### 数値

- `Int` は符号付き 64 ビット、範囲は `-2^63`〜`2^63-1`。JS 内部では BigInt を使い、リテラルも Number を経由しない。加減乗除・剰余と単項負号は SIR の検査算術を訳し、桁あふれ・ゼロ除算・最小値と `-1` の除算／剰余を同じ停止にする。ビット演算は 64 ビットの二の補数として正規化し、右シフトは論理右シフト、シフト数は 0〜63。回転・算術右シフトも既存の幅と前提検査を維持する。
- `Float` は IEEE 754 binary64 の Number とする。丸め・NaN 比較・正負の無限大・負のゼロを維持する。NaN のペイロードの往復を初版は保証しないため、ビット再解釈の二操作は上記の未対応とする。`to_float` は i64 から binary64 への丸め、`to_int` は有限性と切り捨て後の i64 範囲を検査して `Option<Int>` を返す。暗黙の Int／Float 混合は加えない。
- 長さ・添字も言語上は Int。配列添字などに Number を使う直前に非負・整数・実装可能範囲を検査する。大きい値を切り詰めない。比較の値は型ごとに既存の意味で定義する。

### 文字列・集成値

String の内部 ABI は、Unicode スカラー列を表す妥当な JS string（孤立サロゲートなし）とする。ホスト境界では UTF-16 の妥当性を検査し、不正値を置換せず拒否する。Unicode 正規化はしない。`len` はコード単位や UTF-8 バイト数ではなくスカラー値の数、比較はスカラー列の辞書順とし、JS の UTF-16 既定比較を直接使わない。`trim` は既存の Unicode 空白集合、`lines` は LF 分割・末尾の空行除去・行末 CR 除去を保つ。`parse_int` は ASCII 数字と先頭の `-` だけを許し、`+`・空白・桁区切り・範囲外を既存どおり失敗にする。

Bytes はコピーして所有する Uint8Array、String との変換は厳格な UTF-8 とする。不正 UTF-8 は `Result` の失敗、String の `as_bytes` は妥当な UTF-8 を返す。共有 ArrayBuffer やホストへの可変別名を許さない。

List・組・利用者型は型記述子に基づく領域、列挙型は腕番号と中身として表す。借用は領域と射影を持つ参照で表し、移動元に空の印を置く。JS オブジェクトのコピーで所有権を複製しない。内部表現は公開ホスト ABI にせず、将来の Wasm の線形メモリ表現にも固定しない。

## 決定 3: 所有値の破棄と異常停止

[ADR 0015](0015-m5-native-output.md) 決定 5 の SIR `Drop`／`Move`／`cleanup` をその順に実行する。内側のスコープから外側へ、生存する局所値を宣言の逆順に破棄し、値自身の後に欄・要素を宣言順にたどる。部分移動、`match`、消費するメソッド、`move` クロージャを含め、移動済みの値・欄は二重に破棄しない。深い集成値の破棄には明示的な作業スタックを使う。

正常復帰、`?`、契約／篩型／標準前提の違反、算術停止は SIR の解放経路を通る。停止の種類・関数・ソース位置・契約中の `during` を保持する。最初の停止をホスト側の例外で上書きしない。破棄は利用者コードを呼ばない。GC／FinalizationRegistry に Sigil の破棄や外部資源の解放を委ねない。物理メモリの回収時期と、観測できる破棄の時点は分ける。

ブラウザの JS 呼び出しスタックに深さを依存させない。SIR 呼び出しを明示的なフレームで実行する方式を採り、論理スタックの上限（初版は 192 MiB、SIR の具体化した局所領域の大きさを加算）に達する前に `StackExhausted` として cleanup に入る。ネイティブ／評価器と止まる再帰の深さそのものは比較しない。ブラウザのタブ強制終了やホストのメモリ枯渇では cleanup の実行を保証しないが、通常の言語上の停止と成功に読み替えない。

## 決定 4: 最小ホスト境界と生成物

自己完結した `.mjs` 一つを生成し、名前付き export `invoke(args, host)` を持たせる。ランタイム補助コードは同梱し、動的 import・外部配信コード・`eval`／`Function`・Node.js API・Wasm を要求しない。ES modules・BigInt・Uint8Array・厳格 UTF-8 変換を備える既存の Chromium／Firefox／WebKit で実行できることを完了条件にする。ブラウザの最低対応版は実装時の試験記録に明記する。

- `args` は入口の引数順の配列。境界の値は Int=bigint、Float=number、Bool=boolean、Unit=null、String=string、Bytes=Uint8Array、List／組=array、構造体=`{fields:[...]}`（宣言順）、列挙型=`{tag:腕番号,fields:[...]}` とする。型記述子で arity・型・Int 範囲・UTF-16・腕・循環／不正な形を検査し、配列・Bytes・集成値は取り込む際に複製する。借用／関数値を引数または戻り値に含む入口は生成前に拒否する。篩型の値は基底型の表現で渡し、入口で条件も検査する。
- 戻りは同期的に `{ok:true,value}` または `{ok:false,failure}`。`value` は上記と同じ所有値の表現のコピー。境界の型不正は入口を実行する前に `failure.kind=entry`、言語上の停止は `failure.kind=stop` とし、停止の種類・関数・位置・`during` を含める。内部不変条件の破れは `internal` として区別する。成功時の戻り値を取り出した後、Sigil 内の所有値を規則どおり破棄する。
- `host` の唯一の作用 API は同期 `log(text)`。`console.log` が必要な生成物で欠落・非関数なら実行前に拒否し、既定のグローバル console に黙って接続しない。Sigil の値を既存の Displayable 表示（Float の `NaN`／`inf`／`-inf`／`-0.0` を含む）で文字列化して一回呼ぶ。ホストは資源や借用を受け取らず、戻り値も使わない。
- `log` の例外・Promise を返す実装・同じ実行への再入はホスト境界の失敗として cleanup を行い `failure.kind=host` を返す。ホスト実装は信頼する呼び出し元の責任であり、任意のホスト JS 自体を Sigil の効果検査で隔離するものではない。生成コードは `console` 以外の能力を要求しない。
- `--trace-drops` の生成物だけは `host.traceDrop(text)` を追加で要求する。既存の `drop: 型名` と同じ記録を順番に渡す検証用の窓口とし、新しい Sigil 効果にはしない。例外・非同期・再入の扱いは `log` と同じ。通常の生成物にはこの窓口を要求しない。

HTML の `<script type="module">` から import して `invoke` を呼べる。HTML の生成、DOM 描画、サーバー配信、ソースマップ、汎用 FFI はこの段の必須成果物にしない。Wasm 導入後もこの JS 単独モードと適合試験を維持する。Wasm 選択時の未対応を JS へ黙示切り替えしない（ADR 0038 決定 2）。

## 決定 5: CLI と生成前診断

将来の CLI は次とする（既存のネイティブ出力の既定を保つ）。

```text
sigil build --emit js [--root <根>] [--trace-drops] <ファイル> <関数> -o <出力.mjs>
```

`--emit native` も明示指定として受け付け、無指定は従来の native。JS は入口を一つ選び、引数は生成時でなく `invoke` で渡す。`--root` の既定・モジュール解決は既存 build と同じ。JS に `--fs-double` や利用者の `--trust-base` を許さない。未知の出力器・重複／矛盾した指定・不正な入口は終了コード 1、成功は 0。`sigil run` は SIR 評価器のままとし、JS 実行やブラウザ自動起動の CLI を追加しない。

通常の検査と SIR 検証の後、ファイルを書き出す前に JS 対応集合を全走査する。対象は入口からの呼び出し・関数値／クロージャ・型・契約式・暗黙の標準操作・cleanup を含む依存閉包。実行時の分岐が通らなそうでも閉包内の未対応は拒否する。入口に不要なモジュール全体をバンドルせず、server 専用コードを含む利用者モジュールのブラウザへの取り込みは通常の targets 検査で拒否する。

効果 `none` の関数でも未対応の型や操作は通さない。初版の許可効果は `none` と `console` だけ。`fs.*`・`env`・`net.server`・DB 等のサーバー専用効果と、`dom`・`net.client`・`task.suspend`・`state` 等の初版未対応効果を生成前に診断する。ホスト経由の代行、ダミーの戻り値、黙示の native／Wasm 実行で補わない。

診断には出力先 js、未対応の構文／型／操作／効果、ソース位置と依存元の関数を含める。通常の検査診断と同じ表示基盤を使い、検査エラー／出力未対応／内部エラーを区別する。失敗時は部分的な `.mjs` を残さず、既存の出力ファイルも上書きしない。

## 決定 6: SIR 評価器との比較と完了条件

同じ入力ソース・入口・引数を共通検査／lowering で処理し、一方を SIR 評価器、他方を生成 JS として実行する。JS 側は実ブラウザの ES module として動かし、同じ入力のホスト記録を収集する。Node.js の成功だけでブラウザ対応としない。

| 比較対象 | 確認内容 |
|---|---|
| 値 | 型付きの構造を再帰比較。Int は十進文字列化した i64、Bytes はバイト列、String はスカラー列、列挙型は腕と中身。Float は有限値・負のゼロのビット一致、NaN は NaN 同士、無限大は符号一致。JS の JSON.stringify に BigInt や NaN の意味を任せない |
| 契約・停止 | 成否、停止の種類・関数・位置・`during` を比較。requires／ensures／old／篩型／標準前提／算術停止を正常例と対にする。ホスト境界の失敗は JS 側の別試験で確認 |
| 破棄 | `--trace-drops` と評価器の `trace_drops` の列を完全一致で比較。正常復帰・分岐・ループ・`?`・異常停止、部分移動・match・消費する受け手・move クロージャ・再帰する集成値を含む |
| 外部作用 | `console.log` に渡す文字列と回数・順序を評価器の出力記録と比較。ホスト実装の違いを値の一致で隠さない |
| 拒否 | すべての未対応区分とサーバー専用効果、契約内／高階関数経由の未対応、無効なホスト値を負例で確認。生成前エラーでは成果物が変更されないことも確認 |

境界値には i64 最小／最大・2^53 前後・ゼロ除算・全シフト幅、Float の NaN／無限大／負のゼロと変換境界、補助平面の文字・結合文字・CRLF・Unicode 空白・不正 UTF-8／孤立サロゲート、空／入れ子のコレクションを含める。論理スタックの枯渇は停止の種類と解放の順序を確認し、評価器と再帰深度の数値一致は要求しない。

比較は lowering を共有するため、その誤りを両側で見逃しうる。既存の意味を固定する期待値・期待破棄列と SIR 検証も維持し、二つの出力の一致だけで仕様の正しさとしない。

P2-1 の実装完了は、許可一覧の各機能に正常例と必要な失敗例があり、Chromium／Firefox／WebKit の試験記録で上記比較が通り、Node.js・Wasm なしで小さいブラウザ利用例を import 実行できることとする。共通の適合例は P2-4 でも流用する。本 Issue の完了条件は起草 PR の作成までであり、これらの実装・テストは本 PR に混ぜない。

## 影響

共通 lowering・SIR 検証とブラウザ用の小さいランタイムを再利用し、JS 向けの対応集合・値変換・明示的な破棄・適合試験が必要になる。AST／SIR の契約を追加変更する必要が判明した場合は、契約変更→ADR→実装→サンプル・テストの順と別 PR の規則に従う。本 ADR は新しい依存・信頼基盤の包括承認ではない。P1 の外部公開前の残課題（#547〜#552）は本作業で修正・再起票しない。

### 入力

```json

混合は加えない。\n- 長さ・添字も言語上は Int。配列添字などに Number を使う直前に非負・整数・実装可能範囲を検査する。大きい値を切り詰めない。比較の値は型ごとに既存の意味で定義する。\n\n### 文字列・集成値\n\nString の内部 ABI は、Unicode スカラー列を表す妥当な JS string（孤立サロゲートなし）とする。ホスト境界では UTF-16 `-` だけを許し、`+`・空白・桁区切り・範囲外を既存どおり失敗にする。\n\nBytes はコピーして所有する Uint8Array、String との変換は厳格な UTF-8 とする。不正 UTF-8 は `Result` の失敗、String の `as_bytes` は妥当な UTF-8 を返す。共有 ArrayBuffer
