# 0045: P4-1 データベースの核

- **状態**: 提案（typesafe-ai 正式判定済み。実装完了を意味しない）
- **日付**: 2026-11-17（JST）
- **対象**: [Issue #573](https://github.com/goodnasubi/sigil/issues/573)、レーン E

## 背景と前提

[ADR 0044](0044-p4-scope.md) の最初の段として、単一ノードで使う組み込み用の永続ストレージと関係の表・索引・主キーを定める。SQL の解析・実行と PostgreSQL 通信は P4-2、分散・複製・高可用性は対象外。P4-3 に渡す共通の永続化規則もここで決める。

起草基準は `goodnasubi/sigil` の `9c7c3bacd9cae62fd1299a0ce89ce1c6138cdf7b`。main の索引・ファイルとオープン PR で 0045 が未使用であることを確認し、本 PR の索引行で予約する。処理系・`sigil spec`・実装・バックログは変更しない。

ADR 0044 前提1は [#576 の結論（2026-11-17 09:10 JST）](https://github.com/goodnasubi/sigil/issues/576#issuecomment-6933389330) を入力とする。**不足の扱いの決定は起草に先行済み。標準ライブラリの実装完了は起草条件にしない。** 不足を既存の全量読み書きで代替して持続性を名乗らない。

### 版取得と実装の置き場所

ADR 0044 決定4に従い、版取得方法は [起草前の決定コメント](https://github.com/goodnasubi/sigil/issues/573#issuecomment-6933694595) に記録する。完全なコミット SHA を checkout し、同梱 `Cargo.lock` を使い `cargo build --locked --release` でコンパイラと標準ライブラリを取得する。コンテナイメージの準備を開始条件にせず、浮動 main／タグだけに依存しない。ビルド環境の Rust 版・ターゲット・成果物の検査値も依存記録に残す。

上記 SHA は仕様の基準であり、必要な fs が未実装なので永続 DB を完成できる版とは扱わない。fs 契約・実装の完了後、必要機能を含む完全 SHA へ依存更新 PR を出し、その版で両実行経路を検証する。未定の将来 SHA を既に固定済みとしない。

仕様は本リポジトリ、実装は所有者が作成・命名する別のデータベース用リポジトリに置く。純 Sigil の `trust none` の核とし、公開 `std.fs` を利用する。リポジトリ作成・権限・CI・保護設定は所有者の操作で、作成までは実装しない。アプリ側に `raw.*`／`unchecked` や信頼基盤の迂回を足さない。

## 選択肢と決定

| 判断 | 採用 | 他案を採らない理由 |
|---|---|---|
| 同時実行 | DB ディレクトリを一つのプロセスが排他的に所有し、読み取りも含め実行中トランザクションを一つに直列化 | MVCC・複数 writer は版回収と競合の範囲が広い。直列化で初版の serializable を検査できる |

## 決定1: 標準ライブラリの依存と後続の分割

#576 の分類は「公開 `std.fs` 拡張」と「既存 `std.os.fs` の信頼基盤拡張」の両方であり、排他的ではない。

| 不足 | 扱い・契約上の条件 | 順序 |
|---|---|---|
| ディレクトリ操作 | std.fs＋既存信頼基盤。作成・削除・種別・上限付き列挙。作成／列挙の syscall 対応、既存 unlinkat／newfstatat の再利用を検討 | 1 |
| プロセス間ロック | std.fs＋既存信頼基盤。プロセス内 mutex は代替不可。競合・所有権・ハンドル寿命・解放を共通 ADR で固定 | 1 |
| 追記 | std.fs＋既存信頼基盤。既存 openat／write＋O_APPEND を再利用可能だが unchecked の前提を追加。各 write の位置の保証でありレコード全体の原子性ではない | 2 |
| 位置指定読み書き | std.fs＋既存信頼基盤。pread／pwrite 等。offset／長さの溢れ、short I/O、EOF、EINTR を契約化 | 2 |
| ファイル・親ディレクトリ同期 | std.fs＋既存信頼基盤。fsync 等を追加。close 成功は持続性ではない | 3 |
| 原子的 rename | std.fs＋既存信頼基盤。同一 FS、EXDEV は失敗、上書き規則を明示。名前の原子性と同期による持続性を分ける | 3 |
| zlib／deflate 圧縮 | std.fs 対象外。純 Sigil／trust none の別モジュール、外部ライブラリ・raw・信頼基盤追加なし | 4、P4-3 向け |
| SHA-1 | std.fs 対象外。必要なら std.crypto に純 Sigil／trust none で追加。Git ID 用途、認証に追加しない | 4、P4-3 が必要と決めた場合のみ |

順序0は **共通 fs 境界 ADR**。公開 API、ハンドルの所有権／close／fd 再利用／並行性、排他的作成、ロック、全操作の保証と限界、エラー・上限・既存効果への割当てを先に決める。既存 os_fs の単一スレッド前提を流用しない。ロックの方式（flock／OFD 等）と、他 fd の close による解放の有無もここで固定する。`--fs-double` のパス写像・同期・rename・ロック等の扱い（未対応は明示拒否）を含める。

後続は共通 ADR → A「資源・名前・排他」→ B「ページ I/O・WAL 追記」→ C「同期・原子的置換」の三つの fs 実装 Issue に分ける。C まで揃う前に永続 DB を完成扱いにしない。新 raw 名・効果カテゴリ・アプリ側の trust 許可は追加しない。必要なら ADR を先に改訂する。syscall 番号の許可・ポインタ検証の追加も信頼境界の拡張であり、ADR 0016 と ADR 0025 補足 A-3 のレビュー、ネイティブ／SIR 評価器／差し替え下の結果・エラー・上限の一致、trust 差分監査を必要とする。

圧縮は契約 ADR → 実装を fs から分離する。展開量・入力・メモリ上限、Adler-32、破損・打切り・未対応辞書の拒否、比較・ファジング・性能記録を含める。SHA-1 も必要時のみ契約 ADR → 実装とし、既知ベクトル・Git 比較を行う。両者に直列依存はなく、P4-3 が SHA-256 形式のみを選べば SHA-1 は不要。**圧縮と SHA-1 は P4-1 の実装前提にしない。** 本 PR は後続の番号予約・起票・実装を行わない。

## 決定2: 組み込み API と関係モデル

API は開く／閉じる、begin／commit／rollback、表・索引の作成と削除、主キーによる取得・挿入・置換・削除、索引範囲走査を持つ。SQL 文字列は受け取らず、型付きの操作と結果・構造化エラーを公開する。スキーマ変更もトランザクションに含める。ハンドルは所有権を一意にし、終了・取消は未 commit の変更を破棄する。プロセス間ロックを得られなければ Busy とし、ロックを保持しない read-only open も提供しない。

値は符号付き64 bit整数、bool、UTF-8文字列、バイト列。NULL・浮動小数点・照合順序・外部キー・式索引は初版で未対応。主キーは必須、単一列で一意。二次索引は単一列で一意／非一意を宣言でき、非一意は主キーで同値を順序付ける。整数は数値順、bool は false→true、文字列・bytes は符号なしバイト辞書順。重複主キー・一意索引違反・型不一致は操作を失敗させ、表と全索引に部分変更を残さない。API エラー後はその tx を中止し、rollback のみ許す。

表・索引・カタログは8192 byte固定ページの B+tree に保存する。分割・併合・ページ割当て／解放も同一 tx で行う。ページ番号と世代を検査し、解放ページの再利用を古い WAL と混同しない。走査順は明示したキー順。PostgreSQL の物理ファイル形式との互換は求めない。

| 初版の上限 | 値 |
|---|---|
| ページ数（カタログ・索引を含む） | 2^24 |
| 表数／索引数（DB 全体） | 各1024 |
| 列数／行の符号化サイズ／キーの符号化サイズ | 64／4096 byte／1024 byte |
| tx の変更ページ数／符号化 WAL 量 | 4096／64 MiB |
| 未 checkpoint WAL 総量／核の作業メモリ | 64 MiB／256 MiB |

長さは割当て前に検査し、加算・乗算・offset の溢れを拒否する。ページのヘッダを除いた領域に収まることも検査する。上限超過は Limit エラーで tx を中止し、部分 commit しない。WAL 総量に達する前に tx 間で checkpoint し、空きを作れなければ begin を拒否する。無制限待ち・暗黙の切捨て・上限を避ける自動縮退を行わない。

## 決定3: WAL、commit、checkpoint、復旧

保証対象はローカルの同一 FS 上の通常ファイルで、OS と装置が fsync の契約を守ることを前提とする。ネットワーク FS、同期を偽る装置、悪意ある同時書換えは保証しない。ディレクトリとファイルを初めて作成する際も、必要ファイル同期と親ディレクトリ同期を終えるまで成功を返さない。

### 保存形式と commit

ファイル・ページ・WAL は magic、形式版、固定 byte order（little endian）、長さ、DB 識別子、世代、ページ番号／LSN と SHA-256 検査値を持つ。検査値は偶発破損検出であり改ざん認証ではない。v1 の符号化表と正例・破損例 fixture を実装 PR で固定し、変更時は形式版を上げる。未知の版は UnsupportedFormat とし、既存ファイルを自動初期化しない。

1. tx の更新を上限付き私有ページに保持する。未 commit ページを本体へ書かない（no-steal）。
2. tx ID、連続した LSN、変更した全ページ像と割当て情報を WAL に追記する。短い write は残りを再試行し、中断とエラーを区別する。
3. 全レコードを束ねる検査値・件数・範囲を持つ commit レコードを追記し、**WAL の同期成功後にのみ commit 成功を返す**。read-only tx は書込みを要しない。
4. commit 後の像を論理状態に公開する。本体への反映は checkpoint に遅らせてよい。ロールバックは私有ページを捨てる。

I/O・同期・応答経路の失敗では commit の成否が不明になりうる。CommitUnknown を返し、その DB ハンドルで新しい処理を禁止して閉じ、再 open／復旧後に状態を調べる。失敗応答を rollback 済みと扱わず、再試行で二重適用しないようアプリは操作 ID を同一 tx に保存できる。成功応答のあった tx は再起動後も必ず残る。応答前の強制終了は tx 全体が有るか無いかのどちらかで、部分適用は許さない。

### checkpoint と WAL 回収

tx の無い時点で、(1) 対象 commit まで WAL を同期、(2) その全ページを本体へ位置指定書込みして本体を同期、(3) DB ID・世代・確定 LSN を持つ checkpoint メタデータを一時ファイルに書いて同期、(4) 同一 FS の rename で置換して親ディレクトリ同期、(5) そこで初めて古い WAL を回収し、その名前変更／削除の親ディレクトリを同期する。途中失敗時は使用を停止して復旧する。**checkpoint 公開の同期完了前に、復旧に必要な WAL を削除・切詰めない。** checkpoint 後の torn page を修復する全ページ像を、その checkpoint が完了するまで保持する。

### 復旧

排他ロック取得後、checkpoint と WAL の DB ID・世代・順序・上限・検査値を検証する。完全な commit で閉じた tx だけを LSN 順に redo する。同じ redo を何度実行しても同じ状態になるようページ LSN と全ページ像を使う。ページの途中書込みは保持した全ページ像で修復し、復旧自体の途中中断からも同じ手順で再開する。

最後の未 commit tx の、EOF で物理的に途中になったレコードだけは未完末尾として破棄できる。長さが完結したレコードの検査値不一致、中間破損、commit 済み tx の不足、ID／世代不一致は Corrupt として拒否する。「末尾だから」で検査値不一致を黙って捨てない。無効な checkpoint、復元できないページ破損も拒否し、破損状態で通常 open を成功させない。書込み途中の破損が未完末尾と断定できない場合は、データを失わせる自動修復より拒否を選ぶ。

## 決定4: バックアップ、互換、P4-3 への共通規則

最小バックアップは停止時間を許す。新 tx を止め、checkpoint を完了し、排他ロックを保ったまま本体・カタログ・必要メタデータを新しい専用ディレクトリへコピーする。形式版・DB ID・確定 LSN・ファイル長と SHA-256 を manifest に記録し、全ファイルとディレクトリを同期してから完了印を原子的に公開・親ディレクトリ同期する。不完全なコピーに完了印を付けない。復元は別の空ディレクトリで全件検証して行い、既存 DB を上書きしない。稼働中の任意ファイルコピーをバックアップと呼ばない。

新 reader は、対応済み旧形式の保存 fixture とバックアップを読めることを必須とする。初版から fixture を版管理し、互換を壊す変更は ADR とコピーによる明示移行を必要とする。インプレース自動移行は行わず、旧版 reader が未知版を拒否することも確認する。

P4-3 が共有するのは、更新の公開点を一つにすること、同期前に成功を返さないこと、同一 FS rename と親ディレクトリ同期、長さ・版・検査値の検証、復旧が必要な旧データを公開完了まで保持すること、冪等な復旧、障害注入と互換 fixture の規則である。Git オブジェクトや参照に DB のページ形式／WAL の流用を強制しない。本 ADR でこの規則を決めた後、P4-3 の設計は並行して進められる。

## 脅威と対策（公開関門 G1）

| 脅威 | 対策・残る限界 |
|---|---|
| 破損・悪意ある保存データ、メモリ／CPU 枯渇 | 長さ・参照・循環・木の深さ・順序・版・検査値を検証し、全探索にもページ数とメモリの上限を適用。巨大宣言だけで割当てない |
| 任意パス・symlink・他プロセスによる書換え | 所有者が許可した専用ディレクトリに限定し、相対内部名・排他的作成・symlink拒否を fs 契約に要求。ロックと最小権限を維持。同じ OS 権限の悪意ある主体は保証外 |
| ログ／バックアップへの秘密流出 | 行値・キー・認証情報をログに出さず、エラーは位置・種別だけ。バックアップを元データと同じ秘密として扱い、試験は使い捨てデータのみ |
| 削除後の残留 | ページ・WAL・バックアップ・FS／装置に旧値が残る。DELETE／DROP を安全消去と表示しない。保持期間と媒体廃棄を運用記録に残す |
| 保存暗号化とアクセス制御 | 初版は保存暗号化・DB 内の利用者認証／権限を提供しない。OS の専用利用者・ディレクトリ権限に依存。暗号化の要否・範囲・鍵管理は ADR 0044 に従い公開前の所有者判断へ持ち越す |

「いまは外部公開しない」を維持する。CI と手元の隔離コンテナで検証し、外部ネットワークや実利用者の秘密を使わない。G2 は以下の完了検証と秘密・上限・信頼基盤の監査を含む。暗号処理を追加した場合は定数時間の対象と実測の要否も記録する。G3 は別セッションの公開前レビュー報告を `docs/security/` に残し、P1 の残件 #547〜#552 と合わせ所有者が公開可否を判断する。本 ADR の PR 作成・マージは公開許可ではない。

## 完了条件と後続の切り方

本 Issue の完了は **ADR と索引だけの起草 PR 作成**。以降はこの ADR と共通 fs 境界 ADR の確定、必要な契約変更→ADR→実装→サンプル・テストの順に進める。実装は、保存形式と上限の純粋な核、WAL／commit／復旧／checkpoint、関係 API と索引、バックアップ／互換、検証記録に分けてレビューする。永続化を伴う部分は fs A〜C と固定依存版、所有者作成の実装リポジトリに依存する。

P4-1 の実装完了には次の全てを必要とする。

1. ACID の性質試験。原子性（表・全索引・カタログ）、型・一意性・木の不変条件、直列実行と同じ隔離性、ack 済み commit の持続性を固定 seed と生成操作列で検査する。
2. 各 WAL／ページ／commit／checkpoint／rename／同期／回収の前後で子プロセスを強制終了し、再 open を繰り返す。未応答 tx は全有／全無、ack 済み tx は全有、rollback 済み tx は全無を確認する。
3. short I/O、EINTR、ENOSPC、EIO、同期失敗、torn write と書込み途中中断を注入する。プロセス kill だけでは OS キャッシュが残るため電源断の証明にならない。同期済み境界と未同期書込みの喪失・並べ替えを再現する永続化モデルも使い、実 FS の再起動試験と結果を分けて記録する。
4. 保存ページ・WAL・checkpoint・manifest のファジング。長さ溢れ、検査値不一致、循環、未知版、切断入力から panic・上限外アクセス・過大割当て・破損状態の受理が無いことを確かめ、期間・seed・corpus・回帰例を残す。
5. 同じ型付き操作列を、P1 のクライアント経由で CI の PostgreSQL 公式イメージへ SQL に写像し、commit 後の全行・索引走査順・制約違反の種類を比較する。NULLなし、整数範囲、UTF-8 のバイト順に合う明示順序を使い、物理形式・SQL未対応集合・PostgreSQLの詳細なエラー文は比較しない。クラッシュ保証は PostgreSQL 比較だけに依存しない。
6. 新版 reader に旧版 fixture／バックアップを与え、読み出した論理状態が一致し、未知版拒否とコピー移行の失敗時に原本が残ることを確認する。
7. ネイティブと SIR 評価器で同じ操作列・エラー・上限を確認し、依存 fs の信頼差分監査結果を結び付ける。性能は固定版・装置・seed・件数・同期方式とともに throughput／commit遅延／復旧時間／メモリを両経路で記録し、初版の合否にはしない。

既存 `docs/fault-injection/*.patch` は ADR 0018 の lower に故障を埋める記録で、保存層の I/O 差し替え器ではない。直接流用せず、「意図した誤りを試験が検出するか測る」方法を再利用する。保存層の専用注入器で WAL 同期省略、commit 部分適用、早過ぎる WAL 削除、検査値無視などを個別に埋め、上の試験が落ちることを記録する。検出されない変異を検証済みとしない。
