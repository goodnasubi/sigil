# 0053: P5 コンテナ管理

- **状態**: 提案（typesafe-ai 正式判定済み。実装の着手・完了、外部公開の承認を意味しない）
- **日付**: 2026-11-20（JST）
- **対象**: [Issue #637](https://github.com/goodnasubi/sigil/issues/637)、レーン E

## 背景と前提

[ADR 0005](0005-long-term-goals.md) の段階表は、P5 を「コンテナ管理（G6）。コンテナの実行・配置を管理する仕組み。前提は P1、P4」と定める。P1（OCI 形式のイメージ出力、[ADR 0035](0035-p1-container-image-tool.md)）と P4（[ADR 0044](0044-p4-scope.md)〜[ADR 0048](0048-p4-4-repository-transfer-and-hosting.md)）は完了した。本 ADR は P5 の範囲と形、段の分割、各段の完了条件を決める。実装・処理系・バックログは変更しない。

P4 が P5 に渡すもの（ADR 0044 決定 5）と、本 ADR の使い方は次のとおり。

| P4 が渡すもの | P5 での使い方 |
|---|---|
| 状態の保存（P4-1・P4-2） | 望ましい状態・観測した状態・割り当てを保存する |
| 変更の通知（P4-2） | 調整ループが状態の変化を受け取る |
| 内容で参照する保存（P4-3） | イメージの層を内容の SHA-256 で保存する |
| 宣言の版管理（P4-3・P4-4、ADR 0043 の差分入力） | 望ましい状態の宣言を版管理し、差分をレビューする |
| バックアップと復元（P4-1） | 管理の状態を整合した時点で取り出し、復元する |

ADR 0005 決定 2 のとおり、本 ADR は「Kubernetes や Docker の全機能の置き換え」を意味しない。対応表（決定 7）に「未対応」を残す。

### 版取得と実装の置き場所

ADR 0044 決定 4 に従う。

- 仕様（本 ADR）は `sigil` に置き、**実装は別のリポジトリ**で行う。名前の決定、リポジトリの作成、権限・CI・保護の設定は**所有者の操作**で、エージェントは作成しない。作成されるまで**実装に着手しない**。
- 依存する `sigil` の基準は `aa36874abc6bc191a96be42295d3fd3830db1b9b`（起草時の main）。実装を始める前に、必要な機能を含む完全なコミット SHA へ更新し、`Cargo.lock` を使う `cargo build --locked --release` で取得する。浮動した `main`／タグだけには依存しない。
- 実装は純 Sigil の `trust none` とし、アプリケーション側に `raw.*`／`unchecked` を足さない。言語や標準ライブラリの不足は `sigil` で Issue にし、ADR→実装の順で解決する。
- P4 の成果物（データベース、リポジトリ管理）は、各実装リポジトリの固定した版を使う。

## 選択肢と決定

判断点は typesafe-ai の正式判定で決めた（末尾の記録）。

| 判断 | 採用 | 他案を採らない理由 |
|---|---|---|
| 実行環境の抽象 | バックエンド非依存の**コンテナ仕様**を核に定義し、最初のバックエンドは OCI runtime-spec の bundle を生成して既存の OCI ランタイム（runc／crun）を起動する。nspawn とマイクロ VM は同じ仕様を満たす後続のバックエンド | OCI 専用にすると nspawn・マイクロ VM（ADR 0005 追記の実例）で仕様を作り直す。自前ランタイム（namespace・cgroup を直接操作）は信頼基盤の追加が大きく、検証の範囲が広い |
| 管理の形 | **単一ノード**。望ましい状態と観測した状態を P4 のデータベースに保存し、変更の通知で**調整ループ**が収束させる。複数ノードに拡張できる状態の形だけ定める | 最初から複数ノードにすると、スケジューラ・ネットワーク・合意が一度に要る。命令的な道具だけでは、障害後に望ましい状態へ戻せない |
| 隔離と資源の既定 | **既定は拒否**（決定 3）。資源の上限は必須 | Docker 相当の広い既定は、権限と資源の宣言が省略された状態で動く。ランタイムの既定に任せると、実行環境ごとに安全性が変わる |
| 効果カテゴリ | 初版は**新しいカテゴリを追加しない**。標準ライブラリにコンテナ操作の公開 API を作る段で ADR に記録して決める | 先にカテゴリを作っても、操作の面が決まっていない。語彙は実在の操作が決まってから決める（ADR 0004、ADR 0005 決定 3） |

## 決定 1: コンテナ仕様と実行環境の抽象

**コンテナ仕様**は、バックエンドに依存しない値で、純 Sigil（`effects none`）の型・検証・変換として実装する。

- イメージは**内容の SHA-256 の digest で固定**する。タグだけの参照は受け付けない。ADR 0035 の OCI Image Layout を最初の入力にする。
- 隔離プロファイル（決定 3）、資源の上限、ネットワーク（決定 4）、マウント、環境変数・引数・作業ディレクトリ、再起動の方針を持つ。
- 未知の項目は拒否する。省略が既定の許可にならない。検証の失敗はエラー型で返し、一部だけ適用しない。

**バックエンド**は、仕様を受け取り、実行環境の操作（作成・起動・停止・削除・状態の取得・ログ）を行う境界である。

| 種類 | 初版 | 位置づけ |
|---|---|---|
| OCI ランタイム（runc／crun） | **対象**（P5-2） | 仕様から OCI runtime-spec の bundle を決定的に生成し、既存のランタイムを `process` で起動する |
| OS の仕組みによるコンテナ（nspawn） | 後続 | 同じ仕様を満たすバックエンド。入れ子（VM の内側のコンテナ）の実例に対応する |
| マイクロ VM | 後続 | 信頼できないコードの実行など、カーネルを共有しない隔離が要る用途 |
| 自前ランタイム | 対象外 | 初版に入れない。必要になれば別 ADR で信頼基盤の追加を決める |

バックエンドの差は、仕様が表せる範囲の違いとして対応表に残す。仕様にない機能を、バックエンド固有の項目として黙って足さない。

## 決定 2: 管理の形（単一ノードの調整ループ）

- **望ましい状態**（宣言）と**観測した状態**を分けて保存する。宣言は P4-3・P4-4 のリポジトリで版管理し、差分を見られる。
- **調整ループ**は、望ましい状態と観測した状態の差を埋める。操作は**冪等**で、再実行や途中の強制終了から再開できる。観測は実行環境から取り直し、保存した状態を鵜呑みにしない。
- 状態の変化は P4-2 の変更の通知で受け取る。通知を取りこぼしても、周期的な再調整で収束する。
- 配置の単位は「ノード」「ワークロード（望ましい状態の宣言）」「インスタンス（実行中のコンテナ）」。初版のノードは一つだが、状態の形は複数ノードに拡張できるようにする。複数ノードのスケジューラ・クラスタ・オートスケールは初版の対象外。
- 状態の保存は P4 のデータベースを使い、整合性が要る更新は単一のトランザクションで行う。管理の状態のバックアップと復元は P4-1 の仕組みを使う。

## 決定 3: 隔離と資源の制限（既定は拒否）

次を**既定**とし、緩める場合は仕様に明示する。緩めるほど検証が厳しくなる項目は、仕様の検査で理由を要求する。

| 項目 | 既定 |
|---|---|
| 利用者 | 非 root（user namespace）。ADR 0035 のイメージは 65532 |
| 特権 | `privileged` を持たない。host の PID・IPC・UTS・ネットワーク namespace を共有しない |
| capability | すべて削除。加えるものは仕様に列挙し、危険なもの（例: `SYS_ADMIN`）は拒否する |
| システムコール | seccomp は許可リスト |
| ファイルシステム | rootfs は読み取り専用。書き込める場所は、宣言した一時領域・ボリュームだけ |
| マウント | 宣言したものだけ。host のパスは許可リストに載ったものに限り、`/proc`・`/sys`・デバイスは既定で出さない |
| 資源 | メモリ・CPU・プロセス数（pids）・ディスク・ログの量の**上限が必須**。未指定は仕様エラー。超過はコンテナ内の失敗（OOM 等）として観測し、ホストへ影響させない |
| ネットワーク | 既定は接続なし（決定 4） |
| 秘密 | 環境変数でなくファイル（メモリ上）で渡す。仕様・状態・ログ・エラーに値を出さない |

コンテナは**カーネルを共有する**。信頼できないコードの実行に対する完全な境界とは扱わず、その用途はマイクロ VM のバックエンド（後続）を前提にする。これを利用者向けの文書とエラーに明記する。

## 決定 4: ネットワークの接続

- 既定は**接続なし**。接続は仕様に明示する。
- 単一ノードの初版は、コンテナごとの network namespace と、ノード内のブリッジ、宣言したポートの公開、名前による参照（ノード内）を扱う。host network は禁止する。
- 外向きの通信の許可（宛先・ポート）は宣言し、許可しないものは遮断する。ノード間の接続、サービスの負荷分散、TLS 終端は初版の対象外（対応表に残す）。
- 公開するポートと待ち受けの既定は、「いまは外部公開しない」に合わせて、ループバックまたは宣言した内部のアドレスに限る。

## 決定 5: 効果カテゴリ

- 初版（P5-1〜P5-5）は**新しいカテゴリを追加しない**。ランタイムの起動は `process`、bundle やログは `fs.*`、通信は `net.*`、状態は `db`、時刻は `clock` で宣言し、推論と一致させる。
- 標準ライブラリにコンテナ操作の公開 API を作る段に入るときに、追加するカテゴリとその語彙を ADR に記録してから行う（ADR 0004、ADR 0005 決定 3）。本 ADR はその追加を承認しない。
- 実在の操作面（生成・破棄、隔離と資源の制限、ネットワークの接続）は、その ADR で語彙を決める材料にする。

## 決定 6: 段の分割と完了条件

各段は、それだけで使える成果物を出す。実装は別リポジトリが作られてから始める。

| 段 | 成果物 | 完了を確かめる方法 |
|---|---|---|
| P5-1 コンテナ仕様と状態の核 | 仕様の型と検証、既定拒否の規則、決定的な OCI runtime-spec の bundle 生成、OCI Image Layout の読み取りと層のパスの検査、状態の保存形式（P4 のデータベース上） | 純粋関数のテスト、同じ入力から同じ bundle、危険な仕様（特権・資源上限なし・host マウント）の拒否、tar のパス・シンボリックリンク・展開爆弾のファジング、評価器とネイティブの一致 |
| P5-2 ランタイム接続 | rootfs の展開、OCI ランタイムの起動、作成・起動・停止・削除・状態・ログ、非 root での実行 | 実ランタイムで ADR 0035 のイメージが動く、否定試験（特権昇格・書き込み禁止・メモリ／pids の超過・ネットワークなし）、ランタイムの強制終了時の後始末、runc／crun の出力との照合 |
| P5-3 調整ループ | 望ましい状態への収束、再起動の方針、ヘルスチェック、変更の通知の購読、周期的な再調整 | 調整中の強制終了から再開して収束、通知の取りこぼし、冪等性、障害注入（状態の保存の失敗、ランタイムの失敗） |
| P5-4 ネットワークと公開 | 決定 4 の接続、ポートの公開、ノード内の名前解決 | 既定で外へ出られない、許可した宛先だけ通る、host network の拒否、コンテナ間の分離 |
| P5-5 管理 API と検証 | 管理の HTTP API（ADR 0037 の認証と権限）、宣言の版管理との連携、バックアップと復元 | 認証・認可の否定試験、宣言の差分、復元後の収束、公開関門 G2 の確認と G3 の報告の準備 |

後続（本 ADR の段階表に載せ、入るときに ADR で範囲を決める）: nspawn バックエンド、マイクロ VM バックエンド、複数ノード（スケジューラ・ノード間ネットワーク）、レジストリとの送受信、イメージのビルド、効果カテゴリの追加。

**各段に共通する要件**

- 特権や cgroup v2・user namespace が要る試験は、環境が無いときに黙って成功にしない。CI で省略せず、必要な環境を CI に用意するか、記録して別区分にする（理由を残す）。
- ネイティブと SIR 評価器で同じ操作列・エラー・上限を確認する。性能は記録するが初版の合否にはしない。
- 上限（仕様の大きさ、層の数・サイズ、ファイル数、パスの長さ、ログの量）は、読み込む前に効く値として段の個別実装で決め、超過は自動分割や黙った切り捨てをせず明示的に失敗する。

| 項目 | 初版 |
|---|---|
| OCI ランタイム（runc／crun） | 対象 |
| nspawn、マイクロ VM | 未対応（後続） |
| 複数ノード、スケジューラ、クラスタ | 未対応 |
| サービスの負荷分散、ノード間ネットワーク、TLS 終端 | 未対応 |
| レジストリの送受信、イメージのビルド | 未対応 |
| ボリュームの外部ストレージ、スナップショット | 未対応 |
| 自前ランタイム（namespace・cgroup の直接操作） | 対象外 |
| Windows コンテナ、macOS | 対象外 |
| 秘密の保管庫（鍵管理） | 未対応（ファイルでの受け渡しまで） |
| 効果カテゴリの追加 | 未対応（決定 5） |

## 脅威と対策（公開関門 G1）

| 脅威 | 対策・残る限界 |
|---|---|
| **入力**: 悪意あるイメージ・仕様（tar のパストラバーサル、シンボリックリンク、特殊ファイル、展開爆弾、巨大な宣言） | 層の展開は相対パス・上位参照・リンク・特殊ファイルを検査し、サイズ・個数・深さに上限を持つ。圧縮は ADR 0052 の契約に従う。digest 固定の参照だけを受け付け、読み込み前に上限を適用する。ファジングを完了条件に含める |
| **隔離の突破**: カーネルの脆弱性や設定の誤りによる脱出 | 既定は拒否（決定 3）。コンテナはカーネルを共有するため、信頼できないコードの完全な境界とは扱わない（マイクロ VM を後続で扱う）。残る限界として、ランタイムとカーネルの脆弱性は本 ADR の保証外 |
| **認証・認可**: 管理 API の不正利用 | ADR 0037 の HMAC ベアラー認証を再利用し、操作ごとに権限を検査する。権限の変更は次の要求から有効にし、読めない対象の存在は明かさない |
| **秘密**: 環境変数・ログ・状態からの流出 | 秘密はファイル（メモリ上）で渡し、仕様・状態・ログ・エラーに値を出さない。バックアップを元データと同じ秘密として扱う。試験は使い捨てのデータだけを使う |
| **資源**: 一つのコンテナによるホストの枯渇 | 資源の上限を必須にし、超過はコンテナ内の失敗にする。管理側にも状態・ログ・同時操作の上限を持つ |
| **供給網**: イメージの差し替え | digest 固定。SHA-256 の一致は発行者を認証しない（ADR 0035）。署名・検証は未対応として対応表に残す |
| **調整の暴走**: 失敗の再試行による資源の消費 | 再起動に間隔と回数の上限を持たせる。状態の保存に失敗したときは操作を進めない |

「いまは外部公開しない」を維持する。検証は CI と隔離した環境で行い、外部ネットワークや実利用者の秘密を使わない。G2 は各段の完了検証と、秘密・上限・信頼基盤の監査を含む。G3 は別セッションの公開前レビューの報告を `docs/security/` に残し、所有者が公開可否を判断する。本 ADR の PR の作成・マージは公開の許可ではない。

## 完了条件

1. ADR 0053 が起草され、PR が作成される（本 Issue の完了）。
2. 別系統のレビューで承認され、CI が緑でマージされる。
3. 実行環境の抽象の選び方（決定 1）と、隔離・資源の制限・ネットワークの接続の扱い（決定 3・4）、後続の段の分割と各段の完了条件（決定 6）が本 ADR に書かれている。

実装（別リポジトリの作成後）は決定 6 の段ごとに行い、各段の完了を確かめる方法を満たす。

## 決めないこと

- 別リポジトリの名前・作成の時期・権限の設定（所有者の操作）。
- 各段の詳細（仕様の項目の最終形、状態のスキーマ、管理 API の形、ブリッジの構成）。各段の実装前に必要なら ADR で決める。
- nspawn・マイクロ VM・複数ノードの詳細。入るときに ADR で決める。
- 保存データの暗号化の要否、外部の専門家のレビューを加えるか（所有者が公開の前に決める。ADR 0020）。
- 追加する効果カテゴリの語彙（決定 5）。
