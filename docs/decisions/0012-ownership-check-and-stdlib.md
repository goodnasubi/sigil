# 0012: 所有権の検査の範囲と標準ライブラリの細目（M2 の前）

- **状態**: 承認（2026-10-25。所有者の委任を受けて Claude が決定。）

## 背景

M1（名前解決・型検査・効果の推論と一致検査）は完了した（PR #22〜#25）。次の M2 は所有権・借用の検査で、[ADR 0006](0006-p0-scope-and-bootstrap.md) の完了条件は次のとおりである。

- `03-ownership` が検査を通り、そのエラー例 3 件（移動した後の使用・構造体の中の参照・借用の引数が 2 つある関数からの参照の返却）が期待どおりのエラーになる。
- 排他借用の間の共有借用と、借用をとらえたクロージャの変数への保存がエラーになる（[ADR 0003](0003-ownership-and-borrowing.md) の規則 5）。
- ADR 0006 の決定 3 の条件 1・3・8 のテストが通る。

[ADR 0003](0003-ownership-and-borrowing.md) は規則（所有・借用・二級の参照・共有所有・クロージャ）を言葉で定めたが、ループと分岐での移動、1 つの呼び出しの中の借用の重なり、返された参照の区間、契約の式の中の値の扱い、篩型の値の借用など、検査器が判定に使う細目までは決めていない。[ADR 0011](0011-type-system-scope.md) は参照の名前を参照先の値として扱う規則（決定 4）を決め、移動と借用の検査を M2 に回した。

M1 の実装でも、標準ライブラリの最小部分（`src/stdlib.rs`）に仮の決めごとが残った。

- 読むだけの自由関数（`len`・`sum`・`min`・`max`・`empty`・`trim`・`parse_int`）が引数を値の型（`List<T>`・`String`・`Path`）で受け取る。M2 の移動の検査をこのまま入れると、`01-average` の `return sum(xs) / to_float(len(xs));` は `sum(xs)` で `xs` を移動した後に `len(xs)` で使うことになり、エラーになる。`02-read-port` の `trim(text)` の後の `ConfigError.NotANumber(text)` も同じである。
- `List.get` が `Option<&T>` を返す。
- `console.log` が型引数に制約を付けず、値を値の型で受け取る（文字列を表示すると移動する）。
- 利用者が標準の自由関数と同じ名前の関数を宣言すると、利用者のものが優先される。メソッドと名前空間の関数（`fs.read` など）は上書きできない。

さらに、ADR 0006 の決定 4 で「M1 の前」とした「異常停止・無限ループを効果に数えるか」は、決めないまま M1 が完了した。

本 ADR はこれらを決める。コードと examples は変えず、変更は M2 の着手時に行う（「影響」に一覧を載せる）。

前提:

- 書き手は AI。人間は仕様（モジュールの宣言・型の宣言・シグネチャと 4 節）だけをレビューする（[ADR 0001](0001-vision-and-scope.md)）
- 参照は二級で、借用は引数としてだけ渡す。参照を返せるのは借用の引数がちょうど 1 つの関数だけ（ADR 0003 の規則 3）
- 呼び出しの位置では `&x`・`&mut x` を書き、自動で借用するのはメソッドの受け手だけ（ADR 0011 の決定 4・6）
- 関数の型は引数の型としてだけ書ける（ADR 0011 の決定 10）。大域の可変な値はない（ADR 0006 の条件 12）

## 評価の観点

各決定に共通で、重要な順に並べる。

1. **安全性**: ADR 0003 の保証（解放後の使用・二重解放・データ競合がない）を、コンパイル時の検査だけで満たすこと（必須条件）。
2. **仕様として信頼できるか**: シグネチャの「受け取る・読む・書き換える」（ADR 0003 の規則 7）と、契約の式の意味が、本体や他の宣言によって黙って変わらないこと。
3. **AI が誤りなく書けるか**: 規則が少なく、エラーの直し方が一つに決まること。
4. **M2 の実装量と、後から広げられるか**: 検査器を小さく保ち、P1 以降の拡張（中断点・取り消し。[ADR 0007](0007-concurrency-model.md)）で規則を変えずに済むこと。

各決定では、選択肢を挙げ、推奨する 1 つを採用し、理由と M2 への影響を記す。

## 決定 1: M2 の所有権の検査の範囲

### 選択肢

- **A: 関数ごとの制御の流れの上で、場所（変数とそのフィールドの道筋）ごとに移動と借用を追う。借用の区間は最後に使う地点までとする**（Rust の非字句的な生存期間を、二級の参照に限って行う）
- **B: A と同じで、借用の区間を字句のスコープの終わりまでとする**（Rust の 2018 年以前の規則）
- **C: 移動だけを検査し、借用の重なりは 1 つの呼び出しの引数の中だけで調べる**

### 決定

**A** を採用する。規則:

#### 1. 場所と移動

- **場所**は、変数（`let` の変数と引数）か、その後に `.フィールド` を続けたもの（`a.owner`）とする。参照の型の名前を通した場所（`account.balance`。`account: &Account`）も場所である。
- `Copyable` でない型（ADR 0011 の決定 6）の値は、次の位置で **移動** する: `let` の初期化、代入の右辺、値で受け取る引数、`return`、構造体の値・列挙型の値・組の中身、`move` のクロージャのとらえ、値を束縛する `match` の対象（下記）。`Copyable` な型の値はこれらの位置で複製される。
- **部分的な移動**: 値で持つ変数（参照の型でない変数）のフィールドだけを移動できる（`return account.owner;`）。その後は、そのフィールドと、変数全体（変数全体を使う位置。引数に渡す、`&account` など）を使えない。他のフィールドは使える。参照を通した場所からは、フィールドを含め移動できない（ADR 0011 の決定 4。`.clone()` を使う）。
- **`match` の対象**: 対象が場所で、腕のパターンが `Copyable` でない中身を値として束縛するとき、対象の場所は移動する（どの腕に入るかによらず、`match` の時点で移動したものとする）。束縛が `Copyable` な中身と `_` だけなら移動しない。対象が参照の型か `&場所`（下の 3 の `match &x`）なら、束縛は参照になり（ADR 0011 の決定 4）、移動しない。
- **使えなくなった場所**: 移動した場所を、再び代入するまで使うとエラーにする。`let mut` の変数と、値で持つ変数のフィールドへの代入は、移動した場所を使える状態に戻す（再初期化）。

#### 2. 分岐とループ

- 検査は関数ごとに、`if`・`match`・`while`・`return`・`?` の制御の流れの上で行う。各地点で「移動したかもしれない場所」の集合を求める。
- 分岐の合流点では、いずれかの経路で移動した場所を「移動したかもしれない」とし、使うとエラーにする（エラーの説明に、移動した経路の位置を示す）。
- `while` の本体で、ループの外の場所を移動するには、次の繰り返しに戻る前に（本体の終わりまでに）その場所へ再び代入しなければならない。そうでなければ、2 回目の繰り返しでの使用としてエラーにする。ループの解析は、移動の集合が変わらなくなるまで繰り返して求める。
- 早期の戻り（`return`・`?`）の後の経路は合流に加えない。

#### 3. 借用

- `&場所`・`&mut 場所` と `&式`（一時的な値の借用）は、関数とメソッドの呼び出しの引数と、`match` の対象（下記）としてだけ書ける（`let r = &x;` はエラー。ADR 0003 の規則 3）。メソッドの受け手の自動の借用（ADR 0011 の決定 6）も引数と同じ扱いとする。
- **一時的な値**: 場所でない式（呼び出しの結果、構造体の値、リテラルなど）の値は、それを含む文の終わりで破棄される。`if`・`while`・文の `match` では、条件・対象の式の終わり（ブロックに入る前）を文の終わりとみなす。値の `match` は、それを含む `let`・`return` などの文全体が 1 つの文である。
- **一時的な値から借りた参照**: 一時的な値を `&式` で借りた参照、または一時的な値を受け手として自動で借りた参照から、参照を返す呼び出しで得た値（`first(&make_list())`・`make().get(0)` の結果と、そこから `match` で取り出した束縛）は、同じ文の中でだけ使える。`let` への束縛（`let r = make().get(0);`）、後の文での使用、`return`、ブロックを持つ文の対象から腕の中への持ち込み（`match make().get(0) { Some(a) => { ... a ... } ... }`）はエラーにする。エラーの説明に「一時的な値を先に `let` で変数に入れる」と示す。同じ文の中で使い終わる場合（`let n = match make().get(0) { Some(a) => a.n, None => 0, };`）は通る。値の `match` の腕にブロックは書けない（ADR 0008 の決定 2、ADR 0009 の決定 9）ので、`let n = match make().get(0) { Some(a) => { a.n } None => { 0 } };` は所有権の検査の前に構文エラーになる。腕で文を実行したいときは、一時的な値を先に `let` で変数に入れ、文の `match` で書く。
- **`match &x`**（司令塔の決定）: `match` の対象に `&場所` を書ける。書ける場所は **所有している場所**（値で持つ変数とそのフィールド。`let` の変数、値で受け取った引数）に限る。参照の名前（`x: &T`・`x: &mut T`、参照を返す呼び出しを受けた変数）とそれを通した場所は、すでに参照なので `match x { ... }`・`match x.f { ... }` と書き（束縛は ADR 0011 の決定 4 のとおり参照になる）、`match &x` はエラーにする（書き方を一つにするため。エラーの説明に「`&` を外す」と示す）。`&場所` の借用は `match` の終わり（文の `match` は最後の腕のブロックの終わり、値の `match` はその式の終わり）まで続き、腕の束縛は参照になる（ADR 0011 の決定 4 の、対象が参照の型のときの規則と同じ）。これにより、移動せずに場所の中身で分岐できる。`&mut 場所` を対象にすることは P0 では持たない（腕で書き換えが要る場面は、`&mut` の引数を取るメソッドで書く）。`let r = &x;` の禁止は変えない。
- **`match &一時的な値`**: `match &make() { ... }` のように一時的な値を借りて対象にした場合も、上の一時的な値の規則に従う。値の `match` なら、その文の中で腕の束縛を使える。文の `match` では、対象の式の終わりで一時的な値が破棄されるので、腕の束縛を腕のブロックの中で使うとエラーにする（ブロックへの持ち込みのエラー）。
- `&mut` の借用は、`let mut` の変数（とそのフィールド）、または `&mut` の参照の名前（とそのフィールド）からだけとれる。
- **1 つの呼び出しの中の重なり**: 引数（受け手を含む）の中で、ある場所の `&mut` の借用と、同じ場所に重なる場所（一方が他方の前に `.フィールド` を足したもの）の借用・読み出し・移動が並ぶとエラーにする。異なるフィールド（`&mut a.x` と `&a.y`）は重ならない。`&` の借用どうしは重なってよい。
- 受け手の自動の `&mut` の借用と、引数の中の同じ場所の読み出しも重なりとしてエラーにする。`xs.push(xs.len())` は **意図したエラー** である（Rust の 2 段階の借用に当たる例外を設けない。引数をすべて評価してから借用をとる、という評価の順序の特例を規則に持ち込まないため）。エラーの説明に直し方「`let n = xs.len(); xs.push(n);` のように一時変数に入れる」を示す。
- **呼び出しの間**: 呼び出し先に渡した借用は、その呼び出しから戻ると終わる（返された参照を除く）。
- **返された参照**: 参照（`&T`・`&mut T`・`Option<&T>` など、参照を含む値）を返す呼び出しの結果は、借用の引数（ちょうど 1 つ）の場所を借り続ける。区間の中では、元の借用が `&` なら、その場所を読む・`&` で借りることはできるが、書き換え・`&mut` の借用・移動・代入はできない。元の借用が `&mut` なら、その場所を一切使えない。
- **参照を含む値の流れと区間**: 参照を含む値（型に参照を含む値）は、それぞれ「貸し」（借りている場所と、`&`・`&mut` の種類）の集合を持つ。区間は、その貸しを持つ値（変数・束縛・一時的な値）のどれかが後で使われうる地点の全体とする（制御の流れの上の生存の解析で求め、ループは集合が変わらなくなるまで繰り返す）。貸しは次のように流れる。
  - `let x = 式;`: `x` は `式` の貸しを持つ。
  - `match`: 腕の束縛は、対象の貸しを持つ。`match &x` の束縛は、`x` を `&` で借りた貸し（と、`x` が参照を含む値ならその貸し）を持つ。
  - 値の `match` の結果: 腕ごとの値の貸しの和集合を持つ（どの腕を通ったかによらず、すべての貸しが続く）。`if` は文で値を持たない（ADR 0008 の決定 2）ので、分岐の合流で値が合わさるのは値の `match` だけである。
  - 呼び出し: 参照を返す関数に、参照を含む値（または、それが指す場所の借り直し `&r`・`r.field`）を借用の引数として渡すと、結果はその値の貸しを引き継ぐ。区間は推移的に延びる（`let a = xs.get(0); let b = pick_first(&a);` では、`b` を最後に使うまで `xs` の貸しが続く）。
  - 代入: 参照を含む型の変数は `let mut` で宣言できない（`&T` は ADR 0011 の決定 4 のとおり。`Option<&T>` など参照を含む型も同じとする）。再代入がないので、変数の貸しは `let` の時点で決まり、代入による合流は起きない。束縛し直したいときは新しい `let` を書く。
- **参照を返す関数の本体**: 戻り値の型が参照を含むとき、`return 場所;`（と `Some(場所)` など、戻り値の型の形に合わせた値）は、その場所への参照を返す。場所は借用の引数から始まるもの（`return accounts.first;` の `accounts`）か、借用の引数を渡した呼び出しが返した参照でなければならない。借用の引数の種類（`&`・`&mut`）をそのまま引き継ぐ。
- **区間の計算を一か所に**: 借用が有効な区間の計算は、単独で呼べる 1 つの部品にまとめる（ADR 0006 の条件 8）。P1 で中断点を加えるときもこの部品を変える（ADR 0007 の決定 4）。

#### 4. 参照を置ける位置

- **書ける位置**: 宣言に書く型の中で、参照の型を書けるのは次の位置だけとする。
  1. 引数の型の一番外（メソッドの受け手 `self: &T`・`self: &mut T` を含む）
  2. 引数の型に書いた関数の型の、引数の型の一番外（`key: fn(&T) -> K` の `&T`）
  3. 戻り値の型の一番外と、戻り値の型の一番外の `Option<…>` の中身（`-> &T`・`-> Option<&T>`）

  構造体のフィールド・列挙型の値の中身・それ以外の型引数・関数の型の戻り値・`let` の型注釈に書くとエラーにする（ADR 0003 の規則 3。`03-ownership` のエラー例 `struct View`）。宣言の中で参照を入れ子にすること（`&Option<&T>` と書くこと）もできない。
- **借用の引数**: 型のどこかに参照を含む引数（受け手を含む。関数の型の引数の中の参照は数えない）を借用の引数と呼ぶ。参照を返す関数は、借用の引数がちょうど 1 つでなければならない（`03-ownership` のエラー例 `pick`）。
- **総称の型引数に参照を入れること**: 総称の関数・メソッドの型引数（受け手の型の型引数を含む）に参照の型を入れて呼べるのは、置き換えた後のシグネチャが次を満たすときだけとする。
  - 置き換えで引数の型の中に生じた参照は、一番外でなくても（`Option<&Account>` の中、`&Option<&Account>` の入れ子）、上の 1・2 の引数の位置にあるときだけ許す。引数の位置の入れ子は「参照を含む値を借りる」ことで、内側の参照の貸しは外側の借用の間も続く。式の中では、ADR 0011 の決定 4 により入れ子の参照も最も内側の値として使う（`&&T` の値を書く手段はない）。
  - 戻り値の型の中の参照は上の 3 の位置にだけ現れ、そのとき借用の引数がちょうど 1 つである。
  
  `src/stdlib.rs` の `Option` のメソッドに `T = &Account` を入れると、次のようになる。

  | 宣言（`src/stdlib.rs`） | 置き換えた後 | 扱い |
  |---|---|---|
  | `is_some(self: &Option<T>) -> Bool`（`is_none` も同じ） | `self: &Option<&Account>` | 呼べる。受け手（位置 1）の入れ子で、戻り値に参照がない |
  | `map<U>(self: Option<T>, f: fn(T) -> U) -> Option<U>` | `self: Option<&Account>`、`f: fn(&Account) -> U` | 呼べる。`self` は値で受け取る受け手（位置 1）の中の参照、`f` の引数は位置 2。`U` はクロージャの戻り値なので参照にならず、戻り値に参照はない。`self` は借用の引数だが、参照を返さないので数は問わない |
  | `unwrap_or(self: Option<T>, default: T) -> T` | `self: Option<&Account>`、`default: &Account`、戻り値 `&Account` | 呼べない。参照を返すのに借用の引数が 2 つ |
  | `ok_or<E>(self: Option<T>, error: E) -> Result<T, E>` | 戻り値 `Result<&Account, E>` | 呼べない。戻り値の参照が位置 3 にない |

  `Option<&T>` から中身を取り出すときは `match` を使う。`List<&T>` の値は作れない（`List.new()` の戻り値の型の中に参照が現れるため）。クロージャは参照を返せない（関数の型の戻り値に参照を書けないため）。

#### 5. クロージャ

- **非脱出のクロージャ**（呼び出しの引数に直接書いたクロージャ）は、とらえた変数を、読むだけなら `&`、書き換えるなら `&mut` で借りたものとして扱う。その借用は呼び出しの間だけ続き、同じ呼び出しの他の引数との重なりを上の規則で検査する。本体の中でとらえた値を移動することはできない（何度呼ばれるか分からないため。`.clone()` を使う）。
- **脱出するクロージャ**（呼び出しの引数以外に書いたクロージャ。`let add_n = move |y| y + n;`）は `move` を必須とし、`move` のないものはエラーにする（ADR 0003 の規則 5、ADR 0008 の決定 2）。`move` のクロージャはとらえた値を移動（`Copyable` なら複製）する。参照の型の名前をとらえるとエラーにする（借用をとらえたクロージャの保存。ADR 0006 の M2 の完了条件）。本体の中でとらえた値を移動することはできない。
- クロージャの型は、とらえた値とその持ち方（移動・複製・`&`・`&mut`）の一覧を保持する（ADR 0006 の条件 3）。
- `move` の要否は、とらえる値の有無によらず、書いた位置だけで決める（`let` に束縛するクロージャは、何もとらえなくても `move` を付ける）。要否を構文の位置だけで判定でき、エラーの直し方も一つになるためである。

#### 6. 篩型の値

- 篩型は基の型の `Copyable` を引き継ぐ（ADR 0011 の決定 6）。`Copyable` でない基の型の篩型（`type NonEmptyPath = Path where ...;`）の値は、基の型と同じく移動する。
- 篩型の値を基の型として値で渡すと、移動（または複製）する（ADR 0011 の決定 8）。`T.check(v)` は `v` を値で受け取る。
- `&p`（`p` は篩型）は、`&B`（基の型の参照）が求められる位置に渡せる。読むだけなので条件は崩れない。`&mut p` は `&mut B` の位置に渡せない（書き換えで条件が崩れうるため）。篩型の値を書き換えるには、新しい値を `check` を通して作り、代入する。

#### 7. 契約の式

- `requires`・`ensures` の中では、`Copyable` でない値を移動できない（契約の式は読むだけで、評価しても本体の値を変えない。ADR 0006 の決定 5）。値で受け取る引数を持つ関数を、`Copyable` でない場所を渡して呼ぶとエラーになる（決定 2 で、読むだけの標準の関数は参照で受け取るようにする）。
- `ensures` は各 `return` の直前で評価される。`ensures` が参照する値で受け取った引数は、どの `return` に至る経路でも移動していてはならない（`close(account)` の `ensures result == account.balance` は、本体が `account` を移動しないので通る）。`old(式)` の中は入口の値で、この規則の対象にならない。

#### 8. 破棄

- 移動していない場所は、スコープの終わり・代入による上書き・早期の戻りで破棄される（ADR 0003 の規則 1）。M2 は、各地点で破棄する場所と「移動したかもしれない場所」（実行時の印で破棄を判定する場所）を求め、M3 のインタプリタと M5 の出力がそれを使う。破棄の順序（宣言の逆順）と、早期の戻り・契約違反での順序は、ADR 0006 の条件 9 のとおり M3 のテストで固定する。

### 理由

ADR 0003 の規則 2 は「借用は使われる最後の地点で終わる」と定めており、B はこれに反する（`deposit(&mut a, 50); let b = balance_of(&a);` のような、借用を使い終わった後の別の借用を、同じスコープの中で書けなくなる）。C は返された参照（`richest` の戻り値、`List.get` の結果）の区間を検査できず、安全性（観点 1）を満たさない。A は Rust の非字句的な生存期間と同じ考え方だが、参照が二級でライフタイム注釈がないので、貸しの流れは「引数 → 戻り値」と「`let`・`match` の束縛」だけに限られ、関数をまたいだ解析は要らない（観点 4）。一時的な値から借りた参照を文の中に閉じ込めるのは、一時的な値の破棄の地点（文の終わり）を変えずに解放後の使用を防ぐためである。

### M2 への影響

- 関数ごとの制御の流れの表現（文と式の評価の順序、分岐・ループ・早期の戻り）を作り、その上で移動の集合と借用の区間を求める。これを M5 の中間表現に使うかは、M5 の前の ADR で決める。
- 上の 1〜7 の規則のエラーと、8 の破棄の情報を実装する。ADR 0006 の M2 の完了条件に、本 ADR の「M2 の完了条件に加えるもの」を加える。

## 決定 2: 読むだけの標準の関数の引数

### 選択肢

- **A: 読むだけの操作は、受け手を `&T` で受けるメソッドにする。自由関数で読むだけのものは引数を `&T` にし、呼び出しでは `&` を書く**
- **B: 自由関数の引数を `&T` にし、`&T` の引数には `&` なしで場所を渡せる自動の借用の規則を加える**（Swift の `inout` 以外の引数に近い）
- **C: 値の型で受け取るままにする**（`len(xs)` は `xs` を移動する）

### 決定

**A** を採用する。規則:

- 標準ライブラリの、引数を読むだけの操作は `&T` の受け手を持つメソッドとして置く（`xs.len()`・`xs.sum()`・`xs.min()`・`xs.max()`・`path.is_empty()`・`text.trim()`・`text.parse_int()`）。受け手は自動で借用される（ADR 0011 の決定 6）ので、呼び出しの位置に `&` は現れない。
- 同じ操作の自由関数（`len`・`sum`・`min`・`max`・`empty`・`trim`・`parse_int`）は標準ライブラリから除く。自由関数として残すのは、`Copyable` な値だけを受け取る関数（`to_float(n: Int)` など）に限る。
- 名前空間の関数で読むだけの引数を持つものは `&T` で受け、呼び出しでは `&` を書く（`fs.read(&path)`）。
- 空の一覧で値を決められない操作（`min`・`max`）は、メソッドの `requires` で空でないことを要求する（`requires self.len() > 0`）。違反は契約違反の停止である（ADR 0006 の決定 5）。
- **`sum`・`min`・`max` の定め方**: 型引数に制約を付けた `impl` に置く。

  ```
  impl<T: Numeric> List<T> {
    fn sum(self: &List<T>) -> T          // 空の一覧では 0（Int）・0.0（Float）
  }
  impl<T: Comparable + Copyable> List<T> {
    fn min(self: &List<T>) -> T          // requires self.len() > 0
    fn max(self: &List<T>) -> T          // requires self.len() > 0
  }
  ```

  `Numeric` の型（`Int`・`Float`）はすべて `Copyable` なので、`sum` は値を複製して返せる（決定 6 の規則 3）。`min`・`max` は値を返すので `Copyable` を要求し、`String` の一覧の最小は、参照を返す別のメソッドとして標準ライブラリの最小部分で決める。総称の `sum` の本体は 0 を作る必要があるが、利用者の総称の関数は 0 を作れない（ADR 0011 の決定 6）ので、`sum` の本体は信頼基盤の標準ライブラリ（M3 のインタプリタの組み込み）が `Int`・`Float` ごとに持つ。型の具体化した `impl List<Int>`・`impl List<Float>` に分ける案は、同じ名前のメソッドを型引数によって選び分ける解決の規則が要り、総称の関数の中で `xs.sum()` を呼べなくなるので採らない。

### 理由

C は `01-average` を M2 の移動の検査で通せず（背景）、契約の式の中で値を移動する（決定 1 の 7 に反する）。B は `len(xs)` と `len(&xs)` の 2 つの書き方を生み（ADR 0002 の規則 1）、どちらかを禁じるには `&` の意味を引数の型によって変えることになる。また、本体を読んで「この呼び出しは移動するか」を引数の型を見ずに判断できなくなる。A は ADR 0011 の決定（呼び出しの位置で `&` を書く、受け手だけ自動で借用する）を変えずに、`xs.len()` という Rust・TypeScript で一般的な書き方になる（観点 3）。自由関数が減るので、決定 5 の名前の衝突も少なくなる。

### 現行の例への影響

M2 の着手時に、次のとおり直す（意味は変わらず、仕様の表記が変わる）。

| 例 | 現在 | 直した後 |
|---|---|---|
| `01-average` | `requires len(xs) > 0` | `requires xs.len() > 0` |
| | `ensures min(xs) <= result && result <= max(xs)` | `ensures xs.min() <= result && result <= xs.max()` |
| | `return sum(xs) / to_float(len(xs));` | `return xs.sum() / to_float(xs.len());` |
| `02-read-port` | `requires !empty(path)` | `requires !path.is_empty()` |
| | `fs.read(path)` | `fs.read(&path)` |
| | `parse_int(trim(text))` | `text.trim().parse_int()` |
| `03-ownership` | `console.log(b);`・`console.log(refund);` | `console.log(&b);`・`console.log(&refund);`（決定 4） |
| `04-effects` | `requires !empty(path)`・`fs.read(path)?`（エラー例のコメントの中の `fs.read(path)` も） | `requires !path.is_empty()`・`fs.read(&path)?` |
| | `console.log("loading prices");` | `console.log(&"loading prices");`（決定 4） |
| | `parse_int(line).unwrap_or(0)` | `line.parse_int().unwrap_or(0)` |
| | `ensures len(result) == len(xs)`・`len(prices)` | `ensures result.len() == xs.len()`・`prices.len()` |

候補 A・B の比較用のファイル（`a-sexpr.sigil`・`b-indent.sigil`）は比較の記録なので直さない。`.spec` の期待出力は、直した仕様に合わせる。

### M2 への影響

- `src/stdlib.rs` の表を上のとおり改める（M1 の検査器の変更を含むので、M2 の最初の作業とする）。

## 決定 3: `List.get` の戻り値 `Option<&T>`

### 選択肢

- **A: `get(self: &List<T>, i: Int) -> Option<&T>` のままとし、決定 1 の返された参照の規則で扱う**
- **B: `get(self: &List<T>, i: Int) -> Option<T>` とし、`T: Copyable` に限る**（複製を返す）
- **C: 範囲外を停止とする `get(...) -> &T` にする**

### 決定

**A** を採用する。`get` は借用の引数が受け手の 1 つだけなので、ADR 0003 の規則 3 を満たす。結果の `Option<&T>` は、最後に使う地点まで一覧を `&` で借り続ける（決定 1 の 3）。その間、一覧への `push`（`&mut` の借用）はエラーになる。これは、要素の参照を持ったまま一覧を伸ばして要素が移る、Rust で知られた解放後の使用を防ぐ規則そのものである。`Option<&T>` は `let` に束縛し、`match` で取り出す（`Some(a)` の `a` は `&T`）。決定 1 の 4 により、`unwrap_or` のように参照を 2 つの借用から返すメソッドは使えない。範囲外は `None` で、停止しない。

B は `Copyable` でない要素（`List<Account>`）を読めない。C は範囲外が暗黙の停止になる（ADR 0009 の決定 8 で添字 `a[i]` を持たなかった理由と同じ）。書き換え用の `get_mut(self: &mut List<T>, i: Int) -> Option<&mut T>` は同じ規則で扱えるが、サンプルが使わないので、標準ライブラリの最小部分を決めるときに加える。

### M2 への影響

- 決定 1 の返された参照の規則と、総称の型引数に参照を入れる規則のテストに `get` を使う（「M2 の完了条件に加えるもの」）。

## 決定 4: `console.log` の型の制約

### 選択肢

- **A: 性質 `Displayable`（表示できる）を加え、`console.log<T: Displayable>(x: &T)` とする**
- **B: `console.log(x: String)` とし、他の型は `to_string()` で文字列にしてから渡す**（Java・Kotlin）
- **C: 制約なしの `console.log<T>(x: T)` のままにする**

### 決定

**A** を採用する。規則:

- 性質 `Displayable`（仕様での訳は「表示できる」）を ADR 0011 の決定 6 の表に加える。基本の型は `Int`・`Float`・`Bool`・`String`・`Unit` で、篩型は基の型から引き継ぐ。構造体・列挙型・組・`List` には導出しない（表示の形式を決めていないため。決めるときは表示の形式とあわせて ADR で定める）。
- `console.log` は値を `&T` で読む。呼び出しは `console.log(&b)`・`console.log(&"loading prices")` と書く（文字列のリテラルは一時的な値の借用。決定 1 の 3）。
- 表示の形式: `Int` は 10 進、`Bool` は `true`・`false`、`String` は中身のまま（引用符なし）、`Unit` は `Unit`、`Float` は ADR 0009 の決定 5 の小数のリテラルの正規形と同じ綴り（無限大・NaN の綴りは標準ライブラリの最小部分で決める）。末尾に改行 1 つを出力する。

### 理由

C は表示の形式が決まっていない型（`Shared<Cell<Int>>`・関数を含む構造体など）も受け取り、出力が仕様として読めない（観点 2）。また値で受け取るので、文字列を表示すると移動する。B は表示のたびに `to_string()` を書き、変換の形式の規則が型ごとに分かれる。A は「読む」として仕様に現れ、決定 2 の「読むだけなら `&T`」と同じ規則になる。`&"..."` は他の言語にない書き方で、AI が `&` を書き忘れる誤りが出うる（エラーの説明に `&` を付けると示す。末尾の計測の対象）。

### M2 への影響

- 性質の導出の仕組みに `Displayable` を登録し（ADR 0006 の条件 1 の仕組みをそのまま使う）、`src/stdlib.rs` の `console.log` を改める。予約名に `Displayable` を加える（ADR 0009 の決定 4）。

## 決定 5: 利用者の自由関数が標準の自由関数を上書きできること

### 選択肢

- **A: 禁止する。標準の自由関数の名前は予約名とし、利用者は同じ名前の関数を宣言できない**
- **B: 許す（M1 の現状）。利用者の宣言が優先される**
- **C: 許すが、上書きした関数を契約の式の中では使えない**

### 決定

**A** を採用する。M1 の上書きの扱い（`src/check.rs`）をやめ、標準の自由関数の名前を予約名にする。メソッドと名前空間の関数を上書きできないことと揃う。

- **エラーの種類**: 予約名の定義と同じ **構文エラー**（`ReservedNameDefined`）とする。予約名は構文解析の段階で検査し（ADR 0009 の決定 4）、標準の自由関数の名前もその一覧に入れる。型検査の段階に別のエラーを設けない。
- **予約名の一覧**（本 ADR の後。ADR 0009 の決定 4 の一覧に、ADR 0011 と本 ADR で加えたものを含める）:

  | 種類 | 名前 | 加えた ADR |
  |---|---|---|
  | 効果のカテゴリの最上位の語・標準のモジュール名 | `console` `fs` `net` `db` `state` `clock` `process` `foreign` `task` `browser` | ADR 0009 |
  | 篩型の関数名 | `check`（篩型の関数名としてだけ） | ADR 0008・0009 |
  | 標準の前置きの型と値 | `Int` `Float` `Bool` `String` `Unit` `List` `Option` `Result` `Some` `None` `Ok` `Err` `Path` `IoError` `ParseError` `Shared` `Cell` `Set` `Map` | ADR 0009（`Unit` は ADR 0011、`Path` 以降は本 ADR。M1 の `src/stdlib.rs` が置く中身を見せない型） |
  | 性質 | `Copyable` `Equatable` `Comparable` `Numeric` `Sendable` `Shareable` `Displayable` | ADR 0011（`Displayable` は本 ADR の決定 4） |
  | 標準の自由関数 | `to_float` | 本 ADR（決定 2 の後に残る自由関数） |

  標準の自由関数を加えるときは、この一覧に同時に加える（ADR 0009 の「影響」の手続きと同じ）。予約名は関数・変数・引数・型の名前として定義できず、フィールド名は対象外である（ADR 0009 の決定 4）。

### 理由

人間は本体を読まずに契約の式を読む（ADR 0001）。`requires len(xs) > 0` の `len` が、同じファイルの別の場所の宣言で別の意味（効果のない別の計算）に変わっても、仕様の読み手は気づけない（観点 2）。B はこれを許し、C は契約の中と本体の中で同じ名前が別の関数を指すことになる。A の欠点（標準の名前を使えない）は、決定 2 で標準の自由関数が `Copyable` な値の関数（`to_float` など）だけになるので小さい。他のモジュールの関数との名前の衝突は、モジュールの単位の ADR（M1 の前の論点として残っている）で `use` とあわせて決める。

### M2 への影響

- M2 の最初の作業として、M1 の検査器の上書きの扱いを、予約名の定義のエラーに改める（決定 2 の標準ライブラリの変更と同時に行う）。

## 決定 6: 標準ライブラリの M1 範囲（`src/stdlib.rs`）を ADR に載せるか

### 選択肢

- **A: 一覧を ADR に載せず、標準ライブラリの最小部分を決める ADR（M3 の前）まで暫定とする。本 ADR は一覧が従う規則だけを定める**
- **B: 現在の一覧を本 ADR に正式なものとして載せる**
- **C: 標準ライブラリの分割の ADR（M4 の前）まで、規則も含めて何も決めない**

### 決定

**A** を採用する。`src/stdlib.rs` の表は M1〜M2 の検査に必要な最小の範囲を置く暫定のものとし、次の規則に従わせる。

1. 読むだけの操作は `&T` の受け手のメソッドにし、自由関数は `Copyable` な値だけを受け取るものに限る（決定 2）。
2. 参照を返す関数は ADR 0003 の規則 3 と決定 1 の 4 を満たす（決定 3）。
3. 値を複製して返す操作は `T: Copyable` を要求する（例: `Shared<Cell<T>>` の `get(self: &Shared<Cell<T>>) -> T` は `T: Copyable` を付ける。付けないと `Copyable` でない中身を複製できてしまう）。
4. 標準の関数・メソッドにも 4 節を書き、値を決められない入力は `requires` で除く（決定 2 の `min`・`max`）。
5. 表に項目を足すときは、ADR 0011 と本 ADR の規則に照らす。新しい性質・効果のカテゴリを足すときは ADR に記録する（ADR 0004・0005）。
6. 中身を見せない標準の型（`Path`・`IoError` など）の読む操作も、規則 1 のとおり `&T` の受け手のメソッドにする。`Path` には `is_empty(self: &Path) -> Bool` を置く（決定 2 の `path.is_empty()`）。
7. `impl` の見出しで型引数を具体化すること（`impl<T> Shared<Cell<T>>`、`impl List<Int>`）は標準ライブラリにだけ許し、利用者の `impl` の見出しは型の宣言の型引数をそのまま並べる形（`impl<T> Stack<T>`）に限る。同じ型の、型引数に制約を付けた `impl`（決定 2 の `impl<T: Numeric> List<T>`）は利用者にも許す（ADR 0011 の決定 6）。標準ライブラリでも、同じ名前のメソッドを具体化の違いで複数置くことはしない（決定 2 の `sum` の理由）。

正式な一覧（M3 のインタプリタが本体を持つ範囲。`List`・`Option`・`Result`・`String` とその関数）は、ADR 0006 の M3 の完了条件の前に、標準ライブラリの最小部分の ADR で決める。その ADR で扱う項目として、次を書き残す: `List` の検索と比較の操作（`find`・`min_by`・`position` など。現在の表にはなく、`String` の一覧の最小のように参照を返す形を含めて決める）、`get_mut`（決定 3）、`unwrap` に当たる停止する取り出しの要否（ADR 0011 の決定 9）、`Int` の最小値の定数（ADR 0011 の決定 1）、`Float` の無限大・NaN の表示（決定 4）、間接化の型（ADR 0011 の繰り延べ）。分割（核と OS 依存部分）は M4 の前の ADR で決める（ADR 0006 の決定 4）。

### 理由

B は、本体を持たない検査用の表を正式な一覧として固定し、M3 で本体を書くときに必要になる変更（名前・引数の型・契約）のたびに ADR を改める必要が生じる（観点 4）。C は、M2 の検査が依存する引数の形（決定 2）まで決めず、M2 の結果が標準ライブラリの書き方次第で変わる。A は M2 に必要な規則だけを固定する。

### M2 への影響

- `src/stdlib.rs` の冒頭の「仮の決めごと」の注記を、本 ADR を参照する形に改める。規則 3 により `Shared<Cell<T>>` の `get` に `T: Copyable` を付け、規則 6 により `Path` の `is_empty` を加える。規則 7 の利用者の `impl` の見出しの制限が M1 の検査器にないなら加える。

## 決定 7: 「異常停止・無限ループを効果に数えるか」を決める時期

### 選択肢

- **A: M2 の前（本 ADR）で決める**
- **B: M3 の前に、別の ADR で決める。それまでは M1 の現状（数えない）のままとする**
- **C: P0 の完了後（契約の静的検査を入れるとき）まで決めない**

### 決定

**B** を採用する。ADR 0006 の決定 4 の表の決める時期を「M1 の前」から「M3 の前」に改める。

### 理由

- M2 の所有権の検査は、効果の推論の規則に依存しない。停止を効果に数えても数えなくても、移動と借用の判定は変わらない（観点 4）。
- 停止が実際に起こるのは M3 のインタプリタからである（契約違反・桁あふれ・0 での除算。ADR 0006 の決定 5、ADR 0011 の決定 1）。M3 で停止を実装する前に決めれば、停止の扱い（効果の表、テスト用の実行環境での扱い）を一度で作れる。
- C は、停止を数える場合に M1 の効果の推論と全サンプルの `effects` 節を後で変えることになり、P0 の計測（ADR 0004 の効果の検査のエラー率）の前提が変わる。M3 の前なら、計測の結果を記録する前に決められる。
- 決める際の材料として、ADR 0011 の決定 1 により `Int` の `+`・`*` が桁あふれで停止しうるので、停止を効果に数えると整数を扱うほぼすべての関数（`add_tax` など）が `effects none` でなくなる点を記録しておく。

### M2 への影響

- なし。M2 は効果の推論を変えない。

## M2 の完了条件に加えるもの

ADR 0006 の M2 の完了条件に、次のテストを加える（エラー例はテスト用のファイルに切り出す）。

- エラーになる:
  - 移動: `if` の片方の腕で移動した変数の合流後の使用、`while` の本体でループの外の変数を移動して再び代入しないもの、`Copyable` でない値を束縛する `match` の後の対象の使用、参照を通したフィールドの移動、部分的に移動した変数全体を渡す呼び出し。

  - 一時的な値: `let r = first(&make_list());`・`let r = make().get(0);` の後の `r` の使用、文の `match &make()` の腕のブロックの中での束縛の使用、一時的な値から借りた参照の `return`、`match make().get(0)` の腕のブロックの中での束縛の使用。

- 通る: `f(&mut a.x, &a.y)`、`let n = match make().get(0) { Some(a) => a.n, None => 0, };`、`match &x { ... }`（`x` は `let` の変数）の腕での束縛の使用とその後の `x` の使用、`Option<&Account>` の `map(|a| a.balance)`、`Option<&Account>` の `is_some`、`max_by(|a| a.balance)`、`if` の両方の腕で移動した後に再び代入した変数の使用、`return account.owner;`（部分的な移動）、`get` の結果を使い終わった後の `push`、`&p`（篩型）を `&B` の引数に渡す呼び出し、`console.log(&"text")`。

## 根拠の限界と再検証

- 各決定の観点 3「AI が誤りなく書けるか」は、一般に知られている傾向（Rust の借用検査のエラー、`&` の書き忘れ）に基づく定性的な判断で、この言語で計測した結果ではない。
- 候補の案出しと採点を同じ者（Claude）が行っており、偏りがありうる。
- 部分的な移動（決定 1 の 1）と、ループでの再初期化（決定 1 の 2）は、検査を簡単にするために禁じる案（部分的な移動を持たない）もありえた。M2 の実装で検査器の主な複雑さの元になった場合は見直す。
- `T.check(v)` が `v` を値で受け取るので、`Copyable` でない基の型の篩型では、検査に失敗すると元の値が失われる。`Path` などを基の型とする篩型を使う段階で、失敗時に値を返す形（`Result<T, B>`）を検討する。
- M2 の完了後、ADR 0003 の計測（所有権の検査のエラー率と修正の成功率）と合わせて次を計測する。結果が本決定と大きく食い違う場合は、この ADR を見直す。
  - `console.log(&...)`・`fs.read(&...)` の `&` の書き忘れの数（多ければ、読むだけの引数の自動の借用（決定 2 の B）を再検討する）
  - 標準の自由関数と同じ名前を宣言しようとした誤りの数
  - 返された参照の区間のエラー（決定 1 の 3）と、総称の型引数の参照のエラー（決定 1 の 4）の数と修正の成功率

## 補遺: M2 PR2（移動の検査）の実装で仮に決めたこと

ADR が定めていない細部を、実装で次のとおり仮に決めた。誤りと分かった場合は直す。

- 場所は変数か「変数 + `.field` の連なり」。移動の記録は経路の文字列（`a`、`a.owner`）で持ち、同じ経路か、一方がもう一方の接頭辞なら衝突とする。部分的な移動は、所有している根（`Ref` でない）に限る。参照の根からの移動は `MoveFromRef`。
- 分岐は状態を複製して各腕を検査し、和集合で合流する（`return` などで到達しない腕は除く）。
- ループは本体を再実行しない（`RedundantAnnotation` が使う注釈の記録が崩れるため）。ループの頭で未移動だった場所が本体の末尾で移動済みなら `MovedInLoop`。ループを出る時点の状態は、条件の後と本体の末尾の合流。
- `let _ = x` は移動しない。`x?` は被演算子の場所を消費する。参照の根に届く `match` の対象は、腕の束縛を参照にする。値の `match` の腕の本体は消費する。型変数が未解決のものは移動とみなさない。
- 誤りの位置は使用の側の文とし、文言に移動した行を示す。
- 契約と篩型の式は移動を追わない（`track = false`）。
- 引数に参照の名前を渡す形は、その型が `Copyable` なら複製、そうでなければ `MoveFromRef`（PR #27 のレビュー 1）。

### PR3 への申し送り（借用の範囲）

- 総称の型引数に `&x` を渡せない件（決定 1 の 4 の置き換えの規則）は未実装のまま。現在のエラー文は規則が未実装であることを示さず、ユーザーの誤りのように読める。PR3 で規則を実装し、文言も直す。

### PR4 への申し送り（クロージャ）

- クロージャが外側の変数をとらえる移動は記録していない（外側の移動済みの場所の使用はエラー）。`Fn` 型の値は消費しない。PR4 のとらえ方の規則で扱う。
