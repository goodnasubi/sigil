# 0003: 所有権と借用の規則

- **状態**: 承認（2026-10-22。所有者の委任を受けて Claude が決定。計測による再検証の条件は末尾を参照）

## 背景

[ADR 0001](0001-vision-and-scope.md) で、Rust と同等のメモリ安全性（解放後の使用・二重解放・ヌル参照・データ競合がない）を、ガベージコレクションに頼らずコンパイル時に保証すると決めた。
そのための所有権と借用の規則を決める。前提は次のとおり。

- 書き手は AI。人間はコードを読まず、仕様（シグネチャと契約節）だけをレビューする（ADR 0001）
- 構文は波括弧 + 契約節。参照は Rust に倣い `&` / `&mut` で書く（[ADR 0002](0002-syntax-family.md)）
- 出力先はネイティブ・WebAssembly・JavaScript。Python から呼び出せる（ADR 0001）

## 評価の観点

重要な順に並べる。

1. **安全性**: Rust と同等の保証を、コンパイル時の検査だけで得られるか（必須条件）。
2. **AI が誤りなく書けるか**: 検査を通るコードを AI が少ない試行で書けるか。
3. **仕様の読みやすさ**: シグネチャは人間がレビューする仕様の一部なので、そこに現れる記述が少なく、意味が明快か。
4. **出力先・Python 連携との相性**: ネイティブ・WebAssembly・JavaScript で同じ意味になり、Python との境界で破綻しないか。
5. **表現力**: 実用プログラム（UI・サーバー）を無理なく書けるか。

## 選択肢

- **A: Rust と同じ規則**: 参照を構造体に保持でき、関数から自由に返せる。その代わり、生存期間（ライフタイム）注釈 `'a` が必要になる場面がある。
- **B: 参照を二級に限る規則**: 借用（`&` / `&mut`）は引数としてだけ渡せる。構造体に参照を保持すること、参照を変数に入れて関数の外へ持ち出すことはできない。参照を返せるのは「借用の引数がちょうど 1 つ」の場合に限り、返した参照はその引数から借りたものとみなす。ライフタイム注釈は存在しない。共有が必要なら、参照ではなく共有所有の型（参照カウント）を使う。Hylo（旧 Val）の「可変な値の意味論」と同系統の考え方である。
- **C: 参照カウントを基本にする**: Swift のように、値の共有を実行時の参照カウントで管理する。

## 比較

| 観点 | A: Rust と同じ | B: 参照を二級に限る | C: 参照カウント中心 |
|---|---|---|---|
| 1. 安全性（必須） | ◎ 実績あり | ◎ A の規則の部分集合なので、A で安全なことは B でも安全 | × 循環参照によるリークがあり、データ競合の排除には別の仕組みが要る。実行時の費用もある |
| 2. AI が書けるか | △ ライフタイム注釈と、それに関する検査エラーが Rust で最も扱いにくい部分として広く知られている | ○ ライフタイム注釈がなく、規則が少ない | ◎ 検査がほぼない |
| 3. 仕様の読みやすさ | △ シグネチャに `'a` が現れうる | ◎ シグネチャには「受け取る / 読む / 書き換える」の 3 種類しか現れない | ○ |
| 4. 出力先・Python | ○ | ◎ 参照が関数呼び出しの外に残らないので、Python との境界で参照の扱いを考えずに済む | ○ |
| 5. 表現力 | ◎ | △ 参照を保持する構造（借用した反復子を持つ構造体など）は書けず、所有か共有所有で書き直す必要がある | ◎ |

## 決定

**B: 参照を二級に限る規則** を採用する。

必須条件の安全性は A と同等であり、AI の書きやすさと仕様の読みやすさで A に勝る。表現力の不足は、所有・共有所有の型・非脱出クロージャで補う。

### 規則

#### 1. 所有

- すべての値には、ただ 1 つの所有者（変数・構造体のフィールドなど）がある。
- 代入・引数渡し・戻り値で、値は **移動** する。移動した後の元の変数は使えない（コンパイルエラー）。
- `Int`・`Float`・`Bool` などの小さな値型は、移動の代わりに暗黙に **複製** される。それ以外の型を複製するには `.clone()` を明示する。
- 所有者がスコープを抜けると、値はその地点で **破棄** される。破棄の地点はコンパイル時に決まる。

#### 2. 借用

- `&T`（共有借用）: 読むだけ。同時にいくつあってもよい。
- `&mut T`（排他借用）: 書き換えられる。存在する間、同じ値への他の借用は一切許さない。
- 借用は、使われる最後の地点で終わる（スコープの終わりではない）。

#### 3. 参照は二級（ライフタイム注釈なし）

- 借用は **関数の引数としてだけ** 受け渡せる。
  - **追記（[ADR 0012](0012-ownership-check-and-stdlib.md)）**: 引数のほかに、`match` の対象に `&場所` を書ける（`match &x { ... }`）。書けるのは所有している場所（値で持つ変数とそのフィールド）だけで、借用は `match` の終わりまで続き、腕の束縛は参照になる。`let r = &x;` のように借用を変数に入れることはできないままとする。
  - **追記の補足（ADR 0012 の実装時に確認）**: (1) `match &x` の借用は、腕の束縛を最後に使う地点まで続く（上の「使われる最後の地点で終わる」規則どおり）。束縛を使わない腕では、借りた場所を書き換えられる。(2) `Option<&T>` を `let` で束縛した変数（`let r = xs.get(0);`）は、参照の名前として扱う。取り出すときは `match r { ... }` と書き、`match &r` は書けない（`&` を外すよう案内するエラーになる）。腕の束縛が参照になることは、`&x` で借りたときと同じ。
- 構造体・列挙型・コレクションの要素に参照を入れることはできない。
- 参照を返せるのは、借用の引数がちょうど 1 つの関数だけ。返した参照はその引数から借りたものとみなす。それ以外で値を返すときは、所有した値を返す。
- ライフタイム注釈の構文は存在しない。

#### 4. 共有所有

- 複数の所有者が必要な場合は、標準ライブラリの共有所有の型（単一スレッド用・スレッド間用の参照カウント型）を使う。
- 共有所有の型を通した書き換えは、実行時に排他性を検査する型（Rust の `RefCell` / `Mutex` に相当）を介してだけ行える。
- **追記（[ADR 0007](0007-concurrency-model.md)）**: 型の名前は、単一スレッド用を `Shared`・`Cell`、スレッド間用を `SyncShared`・`Lock` とする。両者の間に暗黙の変換はない。
- 参照カウントの循環はメモリリークになる（メモリ安全性は損なわない）。循環を作る用途には弱参照を使う。

#### 5. クロージャ

- 借用をとらえるクロージャは **非脱出**（呼び出しの間だけ使われる引数）としてだけ渡せる。
- 変数に保存したり、後で呼ばれる（イベントハンドラなど）クロージャは、とらえる値を移動するか、共有所有の型で持つ。

#### 6. ヌルと unsafe

- ヌルは存在しない。値がないことは `Option<T>` で表す。
- 安全性の検査を外す仕組み（Rust の `unsafe` に相当）は、通常のコードでは使えない。標準ライブラリ・ランタイム・処理系が生成するコード（Python 連携の束縛など）だけに許す。人間はコードを読まないため、検査の外にあるコードを人間のレビューで補うことができないからである。
- **改訂（[ADR 0005](0005-long-term-goals.md)）**: OS を書けるようにするため、許す範囲を「信頼基盤」（上記に加え、OS のプラットフォーム層の最小部分）に広げた。信頼基盤であることはモジュールの宣言で明示し、検査を外した各箇所には安全の前提を契約として書くことを必須とする。

#### 7. 仕様での表示

- 引数の受け渡し方は仕様（シグネチャ）の一部であり、人間向けの表示では次のように訳す。
  - `x: T` → 「x を受け取る（呼び出し後、呼び出し側では使えない）」
  - `x: &T` → 「x を読む」
  - `x: &mut T` → 「x を書き換える」

## 影響

- **データ競合**: 「共有なら読むだけ、書き換えるなら排他」の規則により、単一の値に対する読み書きの競合はコンパイル時に排除できる。スレッドをまたいで渡せる型の区別（Rust の `Send` / `Sync` に相当）は、並行処理の ADR で決める。**追記（[ADR 0007](0007-concurrency-model.md)）**: 型の構成要素から導く 2 つの性質 `Sendable`（別の処理に渡せる）・`Shareable`（複数の処理から同時に読める）とした。
- **JavaScript 出力**: 破棄の地点はコンパイル時に決まるので、ファイル・接続などの資源を持つ型は、JavaScript でもその地点で明示的に解放するコードを出力する。メモリそのものの回収は JavaScript のガベージコレクションに任せる。これで ADR 0001 の「資源の解放時期を出力先によらず同じにする」を満たす。
- **Python 連携**: 参照は呼び出しの外に残らないので、Python に公開する関数の引数は、所有か共有借用（境界で複製して渡す）に限り、戻り値は所有した値に限る。Python に渡した値は Python 側の取っ手が所有し、解放時期は Python の都合で決まる。資源を持つ型は Python のコンテキストマネージャ（`with` 文）で明示的に閉じられるようにする。詳細は Python 連携の ADR で決める。
- **UI**: イベントハンドラは脱出するクロージャなので、状態は共有所有の型で持つことになる。UI の記述モデルの ADR では、この前提で設計する。
- **examples**: 規則を示すサンプルを [examples/03-ownership](../../examples/03-ownership/) に追加する。

## 根拠の限界と再検証

- B が A と同等に安全なのは、B の規則が A の規則を狭めたもの（A で許されるプログラムの一部だけを許す）だからである。ただし、本言語の検査器の正しさは実装後に検証する必要がある。
- 「ライフタイムが AI にとって書きにくい」は一般に知られている傾向に基づく定性的な判断で、計測していない。
- 「参照を保持する構造が書けないこと」が実用プログラムでどれほど障害になるかは未検証である。Hylo は同系統の考え方を採っているが、大規模な実用例はまだ少ない。
- 候補の案出しと採点を同じ者（Claude）が行っており、偏りがありうる。
- 処理系ができた段階で、次を計測する。結果が本決定と大きく食い違う場合は、この ADR を見直す（A への拡張、つまり限定的なライフタイム注釈の導入を含む）。
  - AI が書いたコードの、所有権・借用の検査エラー率と修正の成功率
  - UI・サーバーの代表的な課題で、共有所有の型に書き換えが必要になった箇所の数と、性能への影響
