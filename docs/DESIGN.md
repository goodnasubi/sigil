# 設計の全体像（草案）

このドキュメントは Sigil の設計方針を整理する草案です。決定事項は [decisions/](decisions/) に記録し、ここでは全体像のみを扱います。

## 1. 目的

AI が生成・改変するプログラムについて、以下を保証しやすくすること。

- **意図の保存**: なぜその処理があるのか（目的・前提・事後条件）が、コードと一体で残る。
- **検証の自動化**: 型・契約・効果の検査で、誤りを実行前に検出できる。
- **差分の可読化**: 意図レベルでの変更を追跡でき、AI が生成した大きな差分を人間が判断しやすい。

## 2. 非目標（当面）

- 既存言語との完全な互換性
- 人間の手書きに最適化された短い記法
- 性能の最適化（まずは意味論と検証を優先）

## 3. 未決の論点

| 論点 | 状態 |
|---|---|
| 構文の基本形（S 式 / 中置 / その他） | 未決 |
| 型システムの範囲 | 未決 |
| 契約（事前・事後条件）の表現と検査方法 | 未決 |
| 効果（副作用）の扱い | 未決 |
| 実行モデル（インタプリタ / コンパイラ） | 未決 |

未決の論点は、検討の結果を `decisions/` に ADR として記録してから確定させます。

## 4. 進め方

1. `examples/` に小さなサンプルを書き、構文の候補を比べる。
2. 候補ごとの利点・欠点を ADR に記録する。
3. 決定した項目を本ドキュメントに反映する。
